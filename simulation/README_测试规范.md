# 仿真测试规范

> 2026-10-20 制定
> 起因：端到端长测试每次 20 分钟，占掉 90% 的仿真时间，却只抓到过 1 个 bug；
> 而真正抓 bug 的全是秒级单元测试。

---

## 一、为什么这么分

### 靠仿真抓到的严重问题（2026-10-19 ~ 20 盘点）

| 问题 | 严重程度 | 靠哪个测试抓到 |
|---|---|---|
| `wave_fetch` 要 16 拍但 `STRIDE=8` | 致命（全是噪音） | 数 `rom_rdy` 的短测试 |
| `chan_buf` 早 23 拍采样 | 致命（存上一个时隙） | 短测试 |
| `pf_gate`/`pf_ch` 早一个时隙 | 致命（完全静音） | 短测试 |
| `slot` 在脉冲间回落 0 | 致命（全写到 slot-0） | 短测试 |
| `chan_table` 调制字段复位成 0 | 严重（自激 + 爆音） | 读代码 + 短测试验证 |
| CC71/72/73 方向反了 | 中等 | 短测试 |
| `full_top` 选通条件漏 `VOICE_SRC=0` | 中等 | **唯一的 20 分钟级测试** |

**7 个里 6 个来自秒级测试。而"炸"这个核心问题，20 分钟的端到端跑了十几次，一次都没抓到。**

### 第二个价值：推翻假设

```
SVF 积分器漂移假设  → 43 秒的独立测试推翻
                     省掉一次"改代码 + 综合 + 上板"（约 1.5 小时）
```

## 二、分级与执行时机

### A 级：每次改完必跑（秒级，总耗时 < 1 分钟）

```
tb_svf_voice          滤波器位精确比对
tb_wave_real          真实波表 + 地址拼接
tb_wave_fetch         / tb_wave_fetch_tb   扫描时序
tb_dsp_voice          DDS
tb_chan_table         通道表 + dump
tb_chan_layer         通道层音量/发送
tb_chan_buf           通道缓冲 + 四路累加
tb_voice_mono         单声部层
tb_adsr_vca           包络/VCA
tb_sched_subsystem    调度层
tb_pt8211_tx          I2S 发送
tb_soft_limiter       限幅器
tb_dc_block           直流阻断
tb_fx_*               效果器（各自）
```

**只要改了 `rtl/` 下任何文件，这一组必须全过。**

### B 级：改了顶层连线 / 时序语义才跑（约 20 分钟）

```
tb_full_system        端到端：MIDI → 出声音
tb_timbre_e2e         同上 + Program Change
```

**触发条件（满足任一）：**

```
· 改了 full_system.v / full_top.v 的端口或连线
· 改了 slot / slot_vld / sample_stb / pit 这类"节拍语义"
· 改了通道层的选通条件
· 准备综合上板之前（跑一次即可，不要反复跑）
```

### C 级：改了对应模块才跑（5~15 分钟）

```
tb_bend_glissando     改 voice_fetch / 弯音时
tb_poly_latency       改分配器 / 32 复音时
tb_timbre_amp         改音色表 / 包络幅度时
tb_vel_amp            改力度映射时
```

## 三、跑之前先估时间

**本机的仿真速度：约 **7500 秒实际时间 / 1 秒仿真时间**（一个仿真秒要跑两个多小时）。**

**提交任何测试台前先算：**

```
预计耗时 = 仿真时间 × 7500
仿真时间 = MIDI 传输时间（32 µs/位 × 10 位 × 字节数）+ 所有 wait 之和
```

**判据：**

```
< 1 分钟   → 直接跑
1~10 分钟  → 可以跑，但要说明预期
> 10 分钟  → **先想办法缩短**
              · 能关掉 ADSR 攻击吗（CC73=0 瞬间起音）
              · 能只测局部模块吗（例化单个 module 而不是整系统）
              · 能缩短测量窗口吗（只取包络稳定后的 5 ms）
```

**教训（2026-10-20）：**

```
· tb_ss 每个音等 600 ms 让包络爬完 → 4 个音 2.8 秒仿真 → 估算 5.8 小时，跑 46 分钟才发现，白跑
· tb_ss2 改用 CC73=0 瞬间起音，只等 20 ms → 225 ms 仿真 → 28 分钟，可行
```

## 四、MIDI 位时间（BIT_TICK）的坑

**不要随便把它调小！**

```
tb_full_system / tb_timbre_e2e  用 1573 ns（注释写"与 midi_parse 一致"）
其余测试台                       用 32000 ns（真实 31250 baud）
```

**2026-10-20 踩过的坑：** 自己写测试台时用了 1573，结果 MIDI 完全没进去，
三个音符的探针全是 0，误判成"低音没输出"这个不存在的 bug。

**结论：**

```
· 自己新写测试台，**先用 32000**（已验证可用的值）
· 想加速再试 1573，但**必须先用一个已知能出声的音符验证 MIDI 通了**
```

## 五、长测试的替代手段

**需要"稳态"数据时，别靠等：**

```
① ADSR 攻击是 300 ms  → 发 CC73=0 把攻击拉到最短，20 ms 就稳态
② 需要特定音色         → 发 Program Change，别改代码
③ 需要特定音量/表情     → 发 CC7 / CC11
④ 只需要看某个模块     → **单独例化那个 module**，别例化整个 full_system
   （例：SVF 漂移测试只例化 svf_voice，43 秒跑完 3 个频率各 10 万采样）
```

## 六、已知的测试台缺陷（不要被它们误导）

**这些测试台报 FAIL，但不是代码 bug：**

| 测试台 | 现象 | 原因 |
|---|---|---|
| `tb_full_top` | "左/右声道不是双极性" | 测试台没接 `ext_aud_in`，却把 `TEST_MODE_DEFAULT` 设成 0 |
| | | （临时改成 1 就 6 项全过） |
| `tb_master_chain` | 编译失败 | 依赖不存在的模块 `test_tone` |
| `tb_test_voice_gen` | 幅度断言失败 | 期望 1/32 FS，实际设计是 1/512 FS（断言过时） |
| `tb_wave_real` | "槽0 与槽1 首点相同" | 两个周期波形的首点都是 0，判据选得不好 |
| `tb_wave_real` | "未分配槽仍有输出" | 假设"槽 2~7 填 0"，但波表已重做成 8 槽全填真实波形 |
| `tb_full_chain` | "打不开 out/demo.txt" | 缺数据文件 |
| `tb_timbre_e2e` | "没有声部被分配" | 它加了 `repeat(2000)`，`pf_gate` 单点采样正好落在空时隙上 |

**共 7 个，全部是测试台自身的问题，不要花时间去"修代码"。**
