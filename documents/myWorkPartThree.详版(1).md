# 模块三 混合部分设计（修正版）

## 设计前提

    本模块落在 Sipeed Tang Mega 138K Pro Dock（FPGA：GW5AST-LV138FPG676AC1/I0，Arora V，22nm）。
    下面这些前提直接决定位宽、时序与资源，写 RTL 之前先确认。

### 一、板卡可用资源（官方数据手册 DS1104-1.0E）

    LUT4 / FF ........ 138240 / 138240
    BSRAM ............ 6120 Kbit，共 340 块；单块 18 Kbit，可配 16 Kbit 或 18 Kbit 两种模式；最高时钟 380 MHz
    DSP .............. 298 个，每个含 1 个 27x18 乘法器 M0、1 个 12x12 乘法器 M1、前加器、48-bit 四输入 ALU
    PLL .............. 12 个，原语名是 PLL（注意：PLLA 只支持 GW5A-25，本器件没有 PLLA）
    ADC .............. 2 个模块，每模块 8 通道，10-bit 精度，采样时钟 < 2 MHz

    一条贯穿全文的结论：
        M0 是 27x18 有符号乘法器，所以“24-bit 音频 x 16-bit 系数”一次乘法只用 1 个 DSP；
        而且 M0 的输出可以直接喂给同一个 DSP 的 48-bit ALU 做累加（Accumulator 模式）。
        本模块的所有多路求和都走这条路，不在 LUT 里搭加法树。

### 二、音频链路与引脚

    FPGA ──I2S(BCK/WS/DIN)── U6 PT8211-S ──二阶低通(LMV321)── U32 XPT4809 耳放 ──┬── 3.5mm 耳机口
                                                                                  └── BL1551 模拟开关 ── 2-pin 扬声器座

    引脚（官方例程 audio.cst，全部 LVCMOS33）：
        HP_BCK = E22      位时钟， = 32 x f_s
        HP_WS  = F24      声道选择， = f_s
        HP_DIN = G24      串行数据
        PA_EN  = H17      耳放使能，高电平有效
        clk    = P16      板载 50 MHz 主时钟
        rst    = U4

    注意：Pro 官方例程的 .cst 里漏掉了 PA_EN 的约束，自己建工程必须补 IO_LOC "PA_EN" H17;
    PA_EN 在 Dock 板是低电平有效、在 Pro 板是高电平有效，两块板的例程写法相反，别抄错。

    PT8211 关键约束：
        16-bit，LSBJ（Japanese，低位对齐）格式，二进制补码，MSB 先出，BCK 上升沿被采样
        每个声道 16 个 BCK，所以 BCLK = 32 x f_s
        BCK 最高 18.4 MHz，WS 最高 384 kHz
        输入超过 16 bit 时只取 MSB 起前 16 位，其余丢弃
        不需要 MCLK

    待实测：PT8211 手册写“WS 低电平把数据移入 right input register”，
    而 Sipeed 官方例程注释写“低电平对应左声道”，两者相反，上板必须用“只送左声道”的码流确认。

### 三、时钟树（本项目已定）

    第一级：MS5351M（板载可编程时钟，25 MHz 晶振）输出 12.288 MHz ── USR_CLK_IN（FPGA 引脚 N22）
    第二级：FPGA PLL（原语用 PLL）

        Fclkin = 12.288 MHz，IDIV = 1，FBDIV = 2，MDIV = 64
        Fpfd   = 12.288 / 1        = 12.288 MHz           合法（10 ~ 400 MHz）
        Fclkfb = 12.288 x 2        = 24.576 MHz
        Fvco   = 24.576 x 64       = 1572.864 MHz         合法（800 MHz ~ 2 GHz）
        CLKOUT0：ODIV0 = 32  →  1572.864 / 32  = 49.152 MHz   →  f_clk，全逻辑主时钟
        CLKOUT1：本项目不需要 MCLK，直接关闭（CLKOUT1_EN = "FALSE"）
                 如果确实要一路 12.288 MHz 给别处用，ODIV1 必须取 128，即 1572.864 / 128 = 12.288 MHz；
                 取 ODIV1 = 4 会得到 393.216 MHz，那是错的。

    f_clk = 49.152 MHz，单一主时钟域，分频链：
        sample_enable   ÷1024  →  48.000 kHz    周期节拍
        bclk_enable     ÷32    →  1.536 MHz     I2S 移位，每 16 个 BCK 翻转一次 WS
        lrck_enable     ÷1024  →  48.000 kHz    I2S 声道切换
        midi_tick       ÷1573  →  31247.3 Hz    目标 31250 Hz，误差 0.0086%，够 MIDI 用
        i2c_tick        ÷128   →  384 kHz       I2C 主控时钟

    核对：BCLK = 1.536 MHz = 32 x 48 kHz，满足 PT8211；T_s = 1/f_s = 20.8333 us；每采样 1024 拍。

    为什么要用 MS5351M（重要）：
        板载 50 MHz（P16）无法精确合成 49.152 MHz。在 Arora V 的 PLL 约束下，
        由 50 MHz 做精确 48 kHz 一族，最高只能到 24.576 MHz / 512 拍每采样（证明见附四）。
        所以 49.152 MHz 必须外供。MS5351M 官方手册（V1.4）指标：3 通道输出，
        2.5 kHz ~ 200 MHz 任意频率，输出频率误差 0 ppm，可配 25 MHz 或 27 MHz 晶振。
        12.288 MHz 在它的能力范围内，且可由 25 MHz 精确合成，无频率误差。

    上电流程：
        1. FPGA 先用 P16 的 50 MHz 跑起来（配置逻辑、I2C 主控、复位状态机）。
        2. FPGA 经 I2C 配置 MS5351M：PLL1 的 TWI 为 SCL = IO28、SDA = IO27，
           需先经 TWI 复用器选通（SEL[0..2] = 1,0,0，SEL 引脚在 N19/P19/P26）。
        3. 等输出稳定（保守 1 ms）。
        4. 让 PLL 以 N22 为 CLKIN 重锁，等 LOCK 有效后再放开音频域。
        5. 时钟稳定之前 PA_EN 保持关断、DAC 数据保持 0，避免上电爆音。

    两个必须验证的点：
        1. N22 在官方 pinout（UG986）里的功能是 IOR80B / MGCLKC_3 / RPLL2_C_FB1 / RPLL3_C_FB1，
           即“多用途全局时钟 + PLL 反馈输入”，并不是专用的 PLL CLKIN 脚。
           能不能把它当 PLL 的 CLKIN 用，必须在 Gowin IDE 里实际布一次看报告；
           如果不行，就把它直接当 f_clk 用（走 GCLK 全局时钟网络，不经 PLL）。
        2. 代码里不要写 BUFG，那是 Xilinx 的原语；Gowin 用 GCLK 全局时钟网络，由工具自动推断。
           ODDR 虽然 Gowin 确实有（原语指南 SUG283 第 1.2.2 节），
           但 1.536 MHz / 48 kHz 这个速度完全不需要，普通寄存器输出就够（可选加 IOB 约束让寄存器进 IOB）。

### 四、定点格式约定

    音频样本 .... Q1.23，24-bit 有符号，范围 [-1, 1 - 2^-23]
    系数 ........ Q1.15，16-bit 有符号，范围 [-1, 1 - 2^-15]
    单个乘积 .... Q2.38，有效 39-bit（用 40-bit 容器装）
    多路累加 .... Q6.38，有效 44-bit（用 DSP 的 48-bit ALU 累加器装）
    记法 ........ Qm.n 的总位数 = m + n，m 含符号位；所以 Q1.23 = 24-bit、Q1.15 = 16-bit

    命门（原稿在这里错了）：
        Q1.23 乘 Q1.15 得到 Q2.38，必须算术右移 15 位才能回到 Q1.23。
        原稿“不截断、保留全精度”之后直接取低 24 位，等于把结果乘了 2^15，增益错约 90 dB。

### 五、通用“归一化 + 饱和”单元（全模块复用）

    第一步： 目标：把 48-bit 的累加结果安全压回 24-bit。
                输入：acc（48-bit 有符号累加结果，Q6.38 量级）
                输出：y（24-bit Q1.23，已饱和）
            操作:1. 四舍五入（可选）：acc_rnd = acc + 2^14。这一步必须在 48-bit 容器里加，不要先截断。
                2. 归一化：sh = acc_rnd >>> 15，得到 29-bit 有效（Q6.23）。
                3. 取低 29 位：v = sh[28:0]。
                4. 溢出判断：ovf = (v[28:24] != {5{v[23]}})。
                5. 输出：ovf 为 0 时 y = v[23:0]；ovf 为 1 时按 v[28] 判正负，
                   正溢出给 24'h7FFFFF，负溢出给 24'h800000。
            说明：24-bit 有符号要装得下，要求第 23 位以上全是符号位，
                  所以判据是 v[28:24] 是否等于 v[23] 的 5 位复制。
                  原稿写“检查 44-bit 的高 20 位 [43:24]”，那是在不右移的前提下写的，位选错了。

## 该块总体分为四个部分

    1.效果发送总线（Summing Bus）
    2.效果器运算（差分方程）
    3.主混音求和（Main Mix）
    4.主输出处理（Master Output）

## 下面是四个部分的分步总览

### 1.效果发送总线

    该部分共分为五步，分别是：发送量归一化（准备系数），时分复用乘法（维度扩展），
    串行累加（卷积和），归一化与饱和（降维输出），TDM 时序控制（FPGA 架构核心）。

    第一步： 目标：把来自通道状态表的 7-bit 整数发送量，转换为可以参与 DSP 乘法的 Q1.15 定点小数。
                输入：SendRev_i, SendCho_i, SendDel_i（7-bit，0 ~ 127）
                输出：SendRev_Q15, SendCho_Q15, SendDel_Q15（16-bit Q1.15）
            操作:1. 把 7-bit 无符号数扩展为 16-bit（高位补 0）。
                2. 左移 8 位（相当于乘 256），使范围落在 0x0000 ~ 0x7F00，即 0.0 ~ 0.9922。
                3. 打一拍寄存，与音频数据对齐时序。
            说明：这一步原稿是对的，保留。

    第二步： 目标：把 24-bit 音频乘以归一化后的发送系数。
                输入：ChL_i, ChR_i（24-bit Q1.23），SendXX_Q15（16-bit Q1.15）
                输出：乘积流（40-bit，Q2.38）
            操作:1. 用 DSP 的 M0（27x18 有符号乘法器）。操作数 A 取声道数据符号扩展至 27 位，
                   操作数 B 取发送系数符号扩展至 18 位。
                2. 每个采样周期内，用同一个乘法器按 TDM 依次乘完 6 条总线 x N 个声部，
                   顺序为 SendRev_L_0 … SendRev_L_N-1、SendRev_R_0 …，再切 SendCho_、SendDel_。
                3. 用 2 个 DSP 分左右声道并行（一个累加 L、一个累加 R），把周期数减半。
            为什么必须 TDM（原稿这里自相矛盾，必须定死）：
                N = 32 声部时，6 条总线 x 32 声部 x 2 声道 = 384 次乘法/采样。
                若全部并行，光发送总线就要 384 个乘法器，已超过全片 298 个 DSP，
                还要留给振荡器。所以 32 复音下并行方案不可行，只能用 TDM。
            DSP 命名修正：
                原稿写的“Xilinx/高云 DSP48、25x18”是错的。Gowin 没有 DSP48 这个命名，
                本器件是 M0（27x18）+ M1（12x12），单通道 24x16 用 M0 一个就够。

    第三步： 目标：把每条总线上 N 个声部的乘积加起来。
                输入：乘积流（40-bit，Q2.38）
                输出：bus_acc（48-bit 累加结果）
            操作:1. 用 DSP 自带的 48-bit ALU 做累加（ALU 输出反馈到 ALU 输入，即 Accumulator 模式）。
                   不要另搭加法树：TDM 累加本身就是串行累加，靠的是时钟拍数而不是组合逻辑深度。
                   原稿的“16→8→4→2→1 加法树”只适用于全并行方案，与 TDM 不兼容，二者只能选一个。
                2. 位宽：单乘积最大 2^38，32 路相加 |Σ| ≤ 32 x 2^38 = 2^43，
                   44-bit 有符号足够，48-bit ALU 绰绰有余。
                3. 累加结束后走第五节统一单元：>>>15，判 v[28:24] 与 v[23]，饱和到 24-bit。
            周期预算（f_clk = 49.152 MHz，1024 拍/采样，2 个 DSP）：
                发送总线 6 x 32 = 192 拍/声道 ...... 18.8%
                主混音干路 32 拍/声道 .............. 3.1%
                主音量 1 拍 ........................ 0.1%
                合计 225 拍 ........................ 约 22%
                N = 16（基础要求）时减半到约 11%；若把左右声道串到同一个 DSP，拍数翻倍到约 44%，
                仍可行但余量只剩一半，所以建议保留 2 个 DSP。

    第四步： 目标：把累加结果安全压回 24-bit，送给效果器运算。
                输入：bus_acc（48-bit）
                输出：BusRev_L/R, BusCho_L/R, BusDel_L/R（24-bit Q1.23）
            操作:1. 四舍五入（可选）：bus_acc + 2^14。
                2. 归一化：sh = bus_acc >>> 15。
                3. 溢出判断：v = sh[28:0]，ovf = (v[28:24] != {5{v[23]}})。
                4. 饱和：无溢出取 v[23:0]；正溢出给 0x7FFFFF；负溢出给 0x800000。
                5. 在“累加结束”与“饱和”之间插一拍寄存器；若用了 DSP 的输出寄存器，这一步天然已分开。
            （原稿写“检查高 20 位 [43:24]，没有溢出就直接取低 24 位”，位选是错的。）

    第五步： 目标：在 f_clk = 49.152 MHz、每采样 1024 拍的限制下，用有限资源算完 6 条总线。
                输入：所有声部数据、发送量
                输出：控制信号、地址、写使能、sample_stb
            操作:1. 状态机：IDLE → SEND_REV → SEND_CHO → SEND_DEL → MIX_DRY → MIX_MASTER，
                   每条总线 32 拍（N = 32），L/R 两个 DSP 同步推进。
                2. 采样周期 T_s = 1/f_s = 20.8333 us（f_s = 48.000 kHz），全模块必须在 T_s 内
                   写完并送入 BSRAM 或寄存器。
                3. 全部算完后产生一拍的 sample_stb 同步脉冲，供整个音频域对齐。
                4. 声部数参数化：N_VOICE = 16（基础要求）/ 32（拓展要求），
                   地址计数器用 clog2(N_VOICE) 位。

### 2.效果器运算

    该部分共分为六步，分别是：接口与数据流约定，混响（Schroeder / Freeverb），
    合唱（Chorus），延迟（Delay），效果返回混合（FX Return），参数平滑。

    总原则（原稿缺）：
        1. 三条效果器全部挂在并行湿路上，输出只参与第 3 部分的干湿相加；
           干信号不经过任何效果器，干路额外延迟为零。否则混响和延迟会把总延迟拉爆。
        2. 每条效果器自己乘一次返回电平 xxx_return（Q1.15），第五步汇总时不再重复乘。
        3. 所有延时线用 BSRAM 的 Semi Dual Port 模式（一写一读、独立时钟），
           读模式用 Pipeline（带输出寄存器）。BSRAM 最高 380 MHz，本设计工作在 49.152 MHz，余量充足。

    第一步： 目标：定义效果器模块的输入输出边界和定点数格式。
                输入：BusRev_L/R, BusCho_L/R, BusDel_L/R（24-bit Q1.23，来自第 1 部分）
                输出：RevOut_L/R, ChoOut_L/R, DelOut_L/R（24-bit Q1.23，送往第五步）
                控制参数：reverb_size、reverb_decay、reverb_damping、reverb_pre_delay、
                          chorus_rate、chorus_depth、chorus_mix、
                          delay_time、delay_feedback、delay_mix
            操作:1. 所有参数在控制率更新，先经第六步的一阶平滑，再写入 Q1.15 寄存器。
                2. 统一声明：n 为当前采样点，z^-1 在硬件里由 BSRAM 地址偏移或寄存器实现。
                3. 本部分所有乘法结果都要 >>>15 归一化（原稿多处漏写）。

    第二步： 目标：实现混响，拆成预延迟、并联梳状加阻尼、串联全通、混响输出四小步。
            2.1 预延迟：
                目标：在直达声之后留一段空白，模拟房间尺寸。
                输入：x[n]（24-bit）
                输出：x_pre[n]（24-bit）
                公式：x_pre[n] = x[n - D_pre]
                操作：D_pre 取 10 ~ 100 ms，由 reverb_pre_delay 控制，对应 BSRAM 的读地址偏移。
                      该阶段是纯延迟，无乘法运算。100 ms @48 kHz 等于 4800 个采样点。
            2.2 并联梳状滤波器加环路阻尼：
                目标：产生密集回声，是混响的核心，也是 BSRAM 和乘法器消耗最多的地方。
                输入：x_pre[n]
                输出：y_comb_sum（各条梳状输出之和，24-bit）
                公式：单条梳状 y_comb[n] = x_pre[n] + g_decay * y_damp[n - D_comb]
                                  y_damp[n] = (1 - d) * y_comb[n] + d * y_damp[n - 1]
                操作：1. 并联 8 条。原稿写 4 条，那是 Schroeder 的最小配置，回声密度不够，
                          拓展要求“丰富演奏听觉层次”，建议用 8 条；BSRAM 紧张时再退回 4 条并说明取舍。
                      2. D_comb 按 f_s = 48 kHz 从 Freeverb 的 44.1 kHz tuning 换算，
                          换算公式 L(f_s) = round(L_44.1 x f_s / 44100)，换算系数 1.08844。
                          8 条梳状延迟为 1215、1293、1390、1476、1548、1623、1695、1760 个采样点。
                          （原稿写 29.7 ms / 37.1 ms，与 Freeverb 原始 tuning 对不上，已重算。）
                      3. g_decay 由 reverb_decay 映射，d 由 reverb_damping 映射，
                          两者都限制在 0 ~ 0.98 以保证稳定。
                      4. 阻尼是一阶低通，放在反馈环路内，用于模拟高频衰减。
                          这一级含乘法，必须 >>>15 归一化。
                      5. 8 条梳状的输出相加，位宽扩到 27-bit（24 + ceil(log2 8) = 27），再饱和回 24-bit。
            2.3 串联全通滤波器：
                目标：进一步扩散声音，让混响尾音平滑。
                输入：2.2 的求和结果
                输出：y_ap
                公式：y_ap[n] = -g_ap * x_in[n] + x_in[n - D_ap] + g_ap * y_ap[n - D_ap]
                操作：1. 串联 2 个。Freeverb 用 4 个，2 个可用，密度略低。
                      2. g_ap 取 0.5，Q1.15 表示为 16384。
                      3. D_ap 用同一换算系数，取 605、480、371、245 个采样点。
                      4. 本级的 -g_ap 项和 +g_ap 项都含乘法，必须 >>>15。
            2.4 混响输出：
                目标：乘返回电平并饱和。
                输入：y_apL, y_apR
                输出：RevOut_L/R（24-bit Q1.23）
                公式：RevOut_L = sat24( (y_apL * reverb_return) >>> 15 )
                操作：左右声道各一套。右声道的各条延迟长度在原值上再加 25 个点（立体声展宽）。

    第三步： 目标：实现合唱，拆成 LFO 生成、调制延迟加线性插值、干湿混合三小步。
            3.1 LFO 生成：
                目标：产生低频正弦调制信号。
                输出：LFO[n]（Q1.15 正弦波）
                公式：LFO[n] = sin( 2 * pi * (chorus_rate / f_s) * n )
                操作：用与振荡器共用的一张 1024 点正弦表加相位累加器实现；
                      chorus_rate 典型取 0.1 ~ 5 Hz，频率字 FTW = round(chorus_rate / f_s * 2^32)。
            3.2 调制延迟加线性插值：
                目标：产生被调制的延迟，实现音高微飘。
                输入：x[n]（24-bit），LFO[n]
                输出：x_delayed[n]（24-bit）
                公式：D_mod[n] = D_base + chorus_depth * LFO[n]        （单位是采样点，含小数部分 frac）
                      x_delayed[n] = (1 - frac) * x[n - k] + frac * x[n - k - 1]，其中 k = floor(D_mod)
                                    = x[n-k] + frac * ( x[n-k-1] - x[n-k] )
                操作：1. D_base 取 15 ~ 25 ms（20 ms @48 kHz 等于 960 个点），
                          chorus_depth 不超过 5 ms（240 个点）。
                      2. 按 a + frac*(b-a) 的写法，只要 1 个乘法器和 2 个加法器。
                         这是合唱的算法核心，BSRAM 用双口读两个相邻地址。
                      3. 立体声两个声道建议用反相 LFO，空间感更好。
            3.3 干湿混合与输出：
                公式：y_mix[n] = sat24( ( (1 - chorus_mix) * x[n] + chorus_mix * x_delayed[n] ) >>> 15 )
                      ChoOut   = sat24( (y_mix * chorus_return) >>> 15 )
                （原稿这两处都漏了 >>>15。）

    第四步： 目标：实现延迟（回声），拆成延迟读取、反馈运算、干湿混合三小步。
            4.1 延迟读取：
                目标：取出 D_delay 个采样点之前的数据。
                输入：x[n]
                输出：x_del[n]
                公式：x_del[n] = x[n - D_delay]，D_delay = round(delay_time * f_s)
                操作：1. 存储量核算（BSRAM 是硬约束）：24-bit x 立体声 x 1 s @48 kHz
                          等于 48000 x 24 x 2 = 2304000 bit。按 16 Kbit 模式折算
                          （2K x 8 三片拼成 24-bit x 2048 深，每块提供 16384 bit）是 141 块 BSRAM，
                          占全片 340 块的 41%。
                      2. 建议最大延时限制到 500 ms（1152000 bit，71 块，21%），
                          把余量留给混响和波表。若坚持 1 s，请在文档里写明占用 41% 的 BSRAM 块。
                      3. 地址 = 环形写指针 + 偏移；用 Semi Dual Port 模式，写口和读口独立。
            4.2 反馈运算：
                目标：把输出按比例送回输入端，形成重复回声。
                公式：y_fb[n] = x[n] + sat24( (delay_feedback * x_del[n]) >>> 15 )
                操作：反馈系数必须小于 1，Q1.15 建议不超过 32000（约 0.977），否则会自激。
            4.3 干湿混合与输出：
                公式：y_mix[n] = ( (1 - delay_mix) * x[n] + delay_mix * y_fb[n] ) >>> 15
                      DelOut   = sat24( (y_mix * delay_return) >>> 15 )

    第五步： 目标：把三条立体声湿信号汇总成一条立体声湿总线，送往主混音求和。
                输入：RevOut_L/R, ChoOut_L/R, DelOut_L/R（24-bit Q1.23）
                输出：FxRet_L, FxRet_R（24-bit Q1.23）
            操作:1. 并行相加：FxRet_L = RevOut_L + ChoOut_L + DelOut_L（右声道同理）。
                2. 位宽：3 个 24-bit 相加，中间取 26-bit（24 + ceil(log2 3) = 26），先符号扩展再相加，
                   避免溢出。
                3. 饱和：按统一单元，判 v[25:24] 是否等于 v[23] 的复制，压回 24-bit。
                4. （GM2 可选）合唱按比例汇入混响：
                       BusRev_L = BusRev_L + sat24( (ChoOut_L * ChoToRev) >>> 15 )
                   可使混响更饱满。
                5. 加法后打一拍，与干信号对齐。
                6. 各效果器的返回电平已经在第二至第四步内乘好，本步只做求和，不重复乘。

    第六步： 目标：消除参数突变造成的拉链噪声（zipper noise）。
                输入：vol_i、pan_i、SendXX_i、reverb_*、chorus_*、delay_* 的目标值
                输出：平滑后的 Q1.15 系数
            操作:1. 所有控制量经一阶低通后再生效：
                       p[n] = p[n-1] + alpha * (p_target - p[n-1])
                   alpha 取 2^-8 ~ 2^-12，对应截止频率约 10 ~ 100 Hz。
                2. 每个采样周期只更新 1/N 个声部的参数（轮转），保证单周期工作量恒定。
                3. note on / note off 相关的开关走各自的 ADSR 状态机，不走这条慢速平滑。

### 3.主混音求和（Main Mix）

    该部分共分为五步，分别是：声像与音量（并行乘法），干信号串行累加，
    干湿比例混合，主音量控制，饱和输出。

    第一步： 目标：对每个声部的干信号应用音量与声像系数，生成左右分量。
                输入：ChL_i, ChR_i（24-bit Q1.23），vol_i, pan_i（16-bit Q1.15）
                输出：DryL_i, DryR_i（40-bit，Q2.38）
            操作:1. 采用等功率声像法则：
                       theta_i = (pan_i + 1) / 2 * pi/2      （pan 从 -1 到 +1 映射到 theta 从 0 到 pi/2）
                       gL_i = vol_i * cos(theta_i)
                       gR_i = vol_i * sin(theta_i)
                   中心点（pan = 0）时 gL = gR = 0.7071，即 -3 dB。
                2. DryL_i = ChL_i * gL_i，DryR_i = ChR_i * gR_i；
                   24-bit 乘 16-bit 得 40-bit，保留全精度进入下一步。
                3. cos / sin 用 1024 点正弦表加象限映射（与振荡器共用表），按 pan 高 10 位查表；
                   gL / gR 在控制率（通道状态表更新时）预算好存寄存器，不占采样周期。
            原稿的错（必须改）：
                原稿写 gL_i = vol_i * (1 - pan_i)、gR_i = vol_i * pan_i。
                pan 是 Q1.15（范围 -1 ~ +1），代入 pan = 0（正中间）会得到 gL = vol、gR = 0，
                声像直接退化成全左。这是明确的公式错误。

    第二步： 目标：把 N 个声部的干信号分量分别求和。
                输入：DryL_i, DryR_i（40-bit）
                输出：DryL_24, DryR_24（24-bit Q1.23）
            操作:1. 与第 1 部分第三步一致：用 2 个 DSP（L / R）在 48-bit ALU 里 TDM 累加 N = 32 个乘积，
                   不写加法树。
                2. 累加后走统一单元：>>>15 加饱和到 24-bit。

    第三步： 目标：把干信号与湿总线按干湿比例混合。
                输入：DryL_24, DryR_24, FxRet_L, FxRet_R（24-bit）
                输出：MixL, MixR（26-bit）
            操作:1. MixL = sat26( (DryL_24 * master_dry) >>> 15 ) + sat26( (FxRet_L * master_wet) >>> 15 )
                   右声道同理。两个乘法都要 >>>15（原稿漏了）。
                2. 湿信号（24-bit）符号扩展到 26-bit 再相加，避免溢出。
                3. 结果保留 25 ~ 26 bit，送第四步。

    第四步： 目标：应用主音量，并做静音控制。
                输入：MixL, MixR（26-bit），G_master（16-bit Q1.15），mute（1-bit）
                输出：VolL, VolR（24-bit）
            操作:1. 先把 MixL / MixR 饱和到 24-bit，再做 24 x 16 乘法。
                   理由：原稿写“44-bit x 16-bit = 60-bit”，在 27x18 的 DSP 上放不下，需要拆成 2 ~ 3 段；
                   而 44-bit 里只有 29 位是有效精度，先饱和到 24-bit 只损失不超过 1 LSB，
                   却把乘法降到 1 个 M0，明显更划算。
                2. 主音量换算：SysEx 主音量是 14-bit（0 ~ 16383），G = V / 16383，
                   量化为 Q1.15 近似等于 V 左移 1 位，即 G_Q15 = V << 1，最大 32766（0.99994），
                   误差小于 0.006%。原稿说“避免真除法，改用倒数表乘”，其实直接左移 1 位就够。
                3. VolL = sat24( (MixL_sat * G_master) >>> 15 )，右声道同理；mute 有效时置 0。
                4. 打一拍寄存。

    第五步： 目标：把结果安全转换回 24-bit，送往主输出处理。
                输入：VolL, VolR
                输出：MainL, MainR（24-bit Q1.23）
            操作:1. 此时是 25-bit 压到 24-bit，判据为 v[24] 是否等于 v[23]。
                2. 饱和：正溢出给 0x7FFFFF，负溢出给 0x800000。

### 4.主输出处理（Master Output）

    该部分共分为五步，分别是：软限幅，直流去除（可选），抖动与位深转换，
    PT8211 串行化，输出级流水线寄存。

    第一步： 目标：对主混音输出做限幅，防止硬截断产生刺耳爆音。
                输入：MainL, MainR（24-bit）
                输出：LimL, LimR（24-bit）
            操作:1. 包络检测：Env[n] = max(|MainL|, |MainR|)。
                2. 目标增益：Env 不超过 Threshold 时 G_target = 1.0；否则 G_target = Threshold / Env。
                   Threshold 是 24-bit 幅度阈值，例如 0x600000 约等于 -2.5 dBFS。
                   避免真除法：Threshold / Env 用 256 项倒数 LUT 加线性插值，Env 取前 8 位做表索引。
                3. 增益平滑：
                       G_target 小于 G_limit[n-1] 时立即响应（Attack 约等于 0）；
                       否则 G_limit[n] = G_limit[n-1] + Release * (G_target - G_limit[n-1])。
                4. 施加限幅：LimL = sat24( (MainL * G_limit) >>> 15 )，右声道同理。
                5. 限幅后打一拍寄存。
            说明：32 声部叠加时这一级是必需品，否则硬截断会产生刺耳爆音。

    第二步（可选）： 目标：去除直流偏置，避免后级功放偏置。
                输入：LimL, LimR（24-bit）
                输出：DcL, DcR（24-bit）
                公式：y[n] = x[n] - x[n-1] + a * y[n-1]，a = 0.995
            操作:1. Q1.15 表示为 round(0.995 * 32768) = 32604 = 0x7F5C。
                2. 截止频率 f_c 约等于 (1 - a) * f_s / (2 * pi) = 0.005 * 48000 / 6.283 = 38.2 Hz，合理。
                3. 每声道 1 个乘法器、2 个加法器、1 个延迟寄存器；乘法后 >>>15。

    第三步： 目标：在把内部 24-bit 截断成 16-bit 之前加抖动，改善量化失真。
                输入：DcL, DcR（24-bit）
                输出：y16L, y16R（16-bit）
            操作:1. 为什么必须做：板载 DAC 是 PT8211（16-bit），内部 24-bit 到 16-bit 是有损截断。
                   原稿说“若内部精度已高于 24-bit 且最终即 24-bit 输出可省略”，在本板上不成立。
                2. 用两个独立的 32-bit 最大长度 LFSR（抽头 32、22、2、1），取低 16 位相减：
                       diff = signed({1'b0, lfsr1[15:0]}) - signed({1'b0, lfsr2[15:0]})
                       tpdf = diff >>> 8
                   diff 的范围是 -65535 ~ 65535，右移 8 位后落在 -256 ~ 255。
                   由于 16-bit 的 1 LSB 相当于 24-bit 域的 2^8 = 256，
                   所以这就是幅度为 ±1 LSB（16-bit）的三角形分布（TPDF），符合抖动理论要求。
                3. y24 = sat24( DcL + tpdf )，然后 y16 = y24[23:8]（截断到 16-bit）。
                4. 不需要再额外加舍入偏置，抖动本身已经随机化了低位。

    第四步： 目标：把 16-bit 样本装配成 PT8211 需要的 LSBJ 帧，输出到 DAC。
                输入：16-bit 样本
                输出：HP_BCK, HP_WS, HP_DIN
            操作:1. 位深 16-bit，格式 LSBJ（Japanese，低位对齐），二进制补码，MSB 先出。
                   注意这不是标准 I2S（Philips）格式。原稿按“24-bit 样本、低位补 0 到 32-bit 槽、
                   BCLK = f_s x 64”来写是错的。
                2. 时序关系：
                       HP_BCK = BCLK = 32 * f_s = 1.536 MHz     （由 f_clk 经 ÷32 得到）
                       HP_WS  = LRCK = f_s     = 48.000 kHz     （由 f_clk 经 ÷1024 得到）
                       HP_DIN 在 BCK 上升沿被 DAC 采样，每个声道 16 个 BCK。
                3. 实现：用 5-bit 位计数器（0 ~ 31）分帧，0 ~ 15 为一个声道、16 ~ 31 为另一个声道；
                   数据请求 req 在每帧起始（以及第 16 拍）产生，向前级取下一个 16-bit 字。
                   可直接对照官方例程 audio_driver.v（b_cnt 是 5-bit，req 在第 0 / 16 拍，
                   HP_DIN = idata_r[15]）。
                4. PA_EN 恒为 1'b1（Pro 板耳放高电平有效，即常开）。
                5. 输出时钟不必用 ODDR。Gowin 确实有 ODDR 原语，但 1.536 MHz 这个速度普通寄存器输出就够，
                   可选加 IOB 约束让寄存器进 IOB。注意不要写 BUFG（那是 Xilinx 的命名）。
                6. 待实测：WS 极性与左右声道的对应关系在芯片手册和官方例程注释里说法相反，
                   上板先送“只有左声道有信号”的测试码流确认。

    第五步： 目标：输出级流水线寄存，保证时序收敛。
                输入：待输出样本、时钟使能
                输出：HP_BCK / HP_WS / HP_DIN / PA_EN
            操作:1. 在移位寄存器与 IOB 之间插一级寄存器，满足建立 / 保持时间。
                2. 目标时钟 49.152 MHz。Arora V 的 DSP / BSRAM 在 -C1 速度等级下的 Fmax，
                   数据手册没有给具体数值（DS1104 的 Table 3-14 / 3-15 全是短横线），
                   必须以 Gowin IDE 的静态时序报告为准。

## 附一、资源预算

    DSP（全片 298 个）：
        发送总线累加（L / R）....................... 2
        主混音干路累加（L / R）..................... 2
        主音量 ..................................... 1
        混响 8 梳状 x 环路阻尼 x 2 声道 ............. 16
        混响全通 x 2 声道 .......................... 0    （乘常数 0.5，用移位加加法实现）
        合唱（线性插值加干湿）x 2 声道 ............. 4
        延迟（反馈加干湿）x 2 声道 ................. 4
        效果返回电平 3 x 2 声道 .................... 6
        软限幅增益 x 2 声道 ........................ 2
        隔直 x 2 声道 .............................. 2
        小计 ....................................... 约 39（分时复用后可压到约 20）
        留给振荡器（模块一 / 二）................... 不少于 259

        提醒：32 复音 x 32 路加法合成分量 = 1024 个分量，用“1 分量 1 个 DSP”是放不下的（只有 298 个）。
              振荡器侧同样必须走 TDM 或“多分量共享一个 DSP”。本模块压到约 39 个 DSP，
              就是为了把这条退路留出来。

    BSRAM（全片 340 块 / 6120 Kbit）：
        延迟线 500 ms 立体声 ....................... 1152000 bit，71 块
        （若用满 1 s）.............................. 2304000 bit，141 块
        混响（8 梳状加 4 全通，立体声）............. 657648 bit，41 块
        混响预延迟 100 ms 立体声 ................... 230400 bit，15 块
        合唱延迟线 25 ms 立体声 .................... 57600 bit，4 块
        波表（8 张 x 2048 点 x 16-bit）............. 262144 bit，16 块
        正弦表（1024 点 x 16-bit，DDS 与声像共用）.. 16384 bit，1 块
        合计（延迟限 500 ms）....................... 148 / 340 块，44%
        合计（延迟用满 1 s）........................ 218 / 340 块，64%

        块数按 16 Kbit 模式折算：每块（2K x 8）提供 16384 bit，24-bit 数据用三片拼成
        24-bit x 2048 深，利用率 100%。若改用 18 Kbit 模式（1K x 18），
        24-bit 数据每个字浪费 12 bit，块数会多约 33%，不推荐。
        取舍建议：延迟限 500 ms，波表 8 张给 32 声部分时复用，可把 BSRAM 占用稳定控制在 45% 以内。

## 附二、延迟预算（赛题硬指标：基础 ≤10 ms，拓展 ≤5 ms 且确定性无抖动）

    f_s = 48.000 kHz，T_s = 20.8333 us。

        演奏传感器扫描加解码 ......... 不超过 1.0 ms（扫描周期设 1 ms；或与 sample_stb 同步，则不超过 1 T_s）
        事件到音符寄存器更新 ......... 不超过 1 T_s = 0.0208 ms（全部在采样边界同步更新，避免亚稳态）
        振荡器加包络流水线 ........... 小于 1 us（16 级 @49.152 MHz 等于 0.33 us，同一采样周期内完成）
        发送 / 混音 / 主输出流水线 .... 不超过 2 T_s = 0.0417 ms（各模块流水线总深度约 10 ~ 20 拍）
        I2S 串行输出 ................. 不超过 1 帧 = 32 BCK = T_s = 20.833 us
        PT8211 内部（8 倍过采样 R-2R）.. 未确认，保守估不超过 0.2 ms（手册未给群延迟，需实测）
        XPT4809 耳放（AB 类）.......... 约 0（模拟器件，只贡献相移，不贡献采样级延迟）
        合计（干路）................... 约 1.3 ms，远优于 5 ms 指标

    三条必须写进 RTL 注释的约束：
        1. 三条效果器不得串入干路；干路延迟与效果参数无关。
        2. 全链路同步设计，唯一的异步边界是传感器输入，用固定周期扫描加两级同步器加边沿检测，
           保证抖动小于 1 个 T_s。
        3. 禁止“事件驱动时才计算”的写法，那会让延迟随运气变化，破坏确定性要求。

## 附三、与竞赛评分规则的对应

    一、振荡器统计规则
        独立发声单元 = 含独立相位累加器、频率调控、包络控制的完整振荡器。
        发送总线、混音、混响 / 合唱 / 延迟一律不计入振荡器数。
        所以本模块的唯一设计目标就是：用最少的 DSP 和 BSRAM 把混音与效果做干净，把资源让给振荡器。
        这也是本文把 384 次并行乘法改成 TDM、把 44-bit 乘法降到 24-bit 乘法的根本动机。

    二、吞吐量指标
        吞吐量 = 同时活跃可闻独立振荡器总数 x 实际音频输出采样率，过采样不叠加加分。
        本项目 32 复音时：32 x 48.000 kHz = 1.536 M 振荡器样本每秒。
        不要用“内部 2 倍 / 4 倍过采样”去宣称吞吐量，规则明确不叠加。
        输出采样率以送到 DAC 的实际 f_s 为准（由 BCLK / 32 决定），不是内部计算率。

    三、测试模式（现场验证必需）
        需要一个 TEST_MODE 寄存器，一键进入可验证状态：
            关闭所有效果（SendXX 全为 0、master_wet 为 0）
            关闭软限幅的动态增益（Threshold 设为 1.0，即固定增益）
            32 个振荡器分配互不重合的频率（例如 200 Hz 起、对数均匀分布到 8 kHz）
            每声部幅度缩放 1/N 或 1/sqrt(N)，避免 32 路叠加削顶
            声像左右交替（L / R / L / R …），顺带验证声像与声道极性
            可选：把 MainL / MainR 接到 LED 或 WS2812 做简易电平指示
        现场用频谱仪或示波器 FFT 数谱峰，即可佐证复音数；同时打开 RTL 展示纯硬件通路。

    四、合规红线
        所有音频必须由 FPGA 逐音、逐样本实时生成；波表只能是单周期波形，
        严禁任何形式的预录 PCM 或整段录音回放。
        板上 AE350 RISC-V 硬核只能用于控制、UI、曲库和参数管理，不得参与逐样本音频运算。

## 附四、时钟可行性证明（为什么必须用 MS5351M）

    要求 BCLK = 32 x f_s，且 f_clk 是 BCLK 的整数倍，则
        BCLK  = 32 x 48000 = 1.536 MHz
        f_clk = K x BCLK = 1.536 x K (MHz)，K 为正整数
        N_clk = f_clk / f_s = 32 x K                 每采样可用拍数

    Arora V 的 PLL 关系与约束：
        Fpfd = Fclkin / IDIV
        Fclkfb = Fpfd x FBDIV
        Fvco = Fclkfb x MDIV                    内部反馈
        Fclkoutx = Fvco / ODIVx
        IDIV 取 1 ~ 64，FBDIV 取 1 ~ 64，MDIV 取 2 ~ 128（支持 1/8 小数步进），
        ODIV0 取 1 ~ 128（支持 1/8 小数步进），ODIV1 ~ ODIV6 只有整数；
        CLKIN 与 PFD 取 10 ~ 400 MHz，VCO 取 800 MHz ~ 2 GHz，CLKOUT 取 6.25 MHz ~ 1 GHz。

    把 f_clk 相对 50 MHz 的比值写出来，并计入 1/8 小数步进
    （令 MDIV = (8m+a)/8、ODIV0 = (8o+b)/8，a、b 取 0 ~ 7）：

        FBDIV x (8m+a)      1.536 x K      96 x K
        ---------------  =  ---------  =  --------            3125 = 5^5，与 96 互素
        IDIV x (8o+b)          50          3125

    因为 96 与 3125 互素，约分后分母里 5 的幂次只能由 IDIV x (8o+b) 提供。
    又由 VCO 约束 ODIV0 = Fvco / (1.536K)，得 8o+b 落在 [6400/(1.536K), 16000/(1.536K)]。分两种情况：

        情况 a：8o+b 小于 625（5^4 塞不进 ODIV0）
            此时 8o+b 里最多含 5^3，而 IDIV 不超过 64、小于 125，最多含 5^2。
            要凑满 5^5，必须 IDIV 含 5^2 且 8o+b 含 5^3，
            于是 IDIV 只能取 25 或 50，Fpfd = 50 / IDIV 不超过 2 MHz，违反 PFD 下限 10 MHz，无解。
            而“8o+b 必然小于 625”的条件是其上界小于 625，即 f_clk 大于 25.6 MHz，也就是 K 不小于 17。

        情况 b：8o+b 不小于 625
            ODIV0 还受不超过 128 的限制，可行窗口内唯一能提供 5^4 的取值是 8o+b = 625，
            即 ODIV0 = 78.125（整数部分 78，落在“2 ~ 127 时小数分频有效”的合法区间）。
            此时需要 IDIV 含 5^1，即 IDIV = 5，Fpfd = 10 MHz，恰好等于下限，可用。剩余条件：
                FBDIV x MDIV = 12 x K
                Fvco = 120 x K MHz 不超过 2000  =>  K 不超过 16
                Fvco = 120 x K MHz 不小于 800   =>  K 不小于 7

    结论：
        可行的精确 48 kHz 时钟只有 f_clk = 1.536 x K MHz，K 从 7 到 16，
        即 10.752 MHz ~ 24.576 MHz，每采样 224 ~ 512 拍。
        其中 K = 16 时是 24.576 MHz（512 拍），取 IDIV = 5、FBDIV = 16、MDIV = 12、ODIV0 = 78.125，
        Fpfd = 10 MHz、Fvco = 1920 MHz，成立。
        而 f_clk 大于 25.6 MHz 的全部不可行，包括 49.152 MHz（K = 32，1024 拍）
        和 98.304 MHz（K = 64，2048 拍）。

    一句话：用板载 50 MHz 加单级 PLL，精确 48 kHz 最高只能做到 24.576 MHz / 512 拍每采样；
    要 49.152 MHz / 1024 拍，必须换时钟源，本项目走 MS5351M。

## 附六、相对原稿的修正清单

    C1   删掉“Xilinx / 高云 DSP48、25x18”。Gowin 没有 DSP48 这个命名，
         本器件是 M0（27x18）加 M1（12x12），共 298 个。
    C2   并行 16 个乘法器与 TDM 1 个乘法器的自相矛盾，定死为 TDM
         （32 复音下并行方案在 298 个 DSP 里放不下）。
    C3   补上 Q1.15 乘法之后的 >>>15 归一化。原稿漏了，会带来 2^15 的增益错误。
    C4   溢出判据从“检查 [43:24]”改为“先 >>>15，再判 v[28:24] 是否等于 v[23] 的 5 位复制”。
    C5   声像公式从 gL = vol x (1 - pan)、gR = vol x pan 改为等功率 cos / sin。
         原式在 pan = 0（正中间）时会变成全左。
    C6   主音量乘法从 44 x 16 改为先饱和到 24-bit 再做 24 x 16。
         原式的位宽在 27x18 的 DSP 上放不下。
    C7   输出格式从 24-bit I2S 加 BCLK = 64 f_s 改为 16-bit LSBJ 加 BCLK = 32 f_s，
         并新增 24-bit 到 16-bit 的抖动环节。
    C8   时钟从 98.304 MHz 改为 49.152 MHz（MS5351M 出 12.288 MHz，再经 PLL x2），
         并写明 50 MHz 无法合成 48 kHz 一族。
    C9   T_s 从写死的 20.833 us 改为按 f_s 计算。本设计 f_s = 48 kHz，每采样 1024 拍。
    C10  通道数从写死 16 改为参数 N_VOICE（16 / 32），满足拓展要求的 32 复音。
    C11  新增延迟预算、资源预算、评分规则对应、参数平滑、时钟证明、待确认清单。
    C12  混响梳状延迟从“4 条加 29.7 ms / 37.1 ms”改为“8 条加按 f_s 换算出的采样点数”。
    C13  补充 BSRAM 使用说明（Semi Dual Port、Pipeline 读、16 Kbit 模式折算块数）。
    C14  抖动 LFSR 给出位宽、抽头与幅度换算。
    C15  明确三条效果器全部挂并行湿路，干路零额外延迟。
    C16  明确 PA_EN 高电平有效、扬声器由 BL1551 模拟开关切换、板上没有大功率 Class-D。
