## 一、时钟与复位

### 1. 时钟树

```
MS5351（25 MHz）×1
    │
    ↓ 24.576 MHz ──→ USR_CLK_IN(N22) ──→ FPGA
    │
PLL：IDIV=1 / FBDIV=1 / MDIV=32（CLKFB_SEL = INTERNAL，内部反馈）
    └── CLKOUT0 → ODIV0=16  → 49.152 MHz ──→ f_clk（全逻辑）
    │
f_clk = 49.152 MHz（单一主时钟域）
    │
    ├── sample_enable   ÷1024  → 48 kHz，周期类节拍
    ├── bclk_enable     ÷32    → 1.536 MHz，I2S 移位（每 16 拍翻转）
    ├── lrck_enable     ÷1024  → 48 kHz，I2S 声道切换
    ├── midi_tick       ÷1573  → 31250 Hz（误差 0.0086%）
    └── i2c_tick        ÷128   → 384 kHz
    │
    └── 输出时钟生成（普通寄存器输出）
         ├── BCLK   1.536 MHz  → DAC（PT8211）
         └── LRCK   48 kHz     → DAC
```

> `N_cyc = 49.152e6 / 48e3 = 1024`（2 的幂 → 各类分频均为整数、占空比 50%）。

### 2. 时钟源

| 源 | 频率 | 引脚 | 说明 |
|---|---|---|---|
| 板载有源晶振 | **50 MHz** | **P16** | 直接可用 |
| MS5351 #1 / \#2（Dock） | 可编程 | **`USR_CLK_IN` = N22** | 精确合成音频时钟 |
| 片内 OSC | 210/Param MHz | — | 精度差，不可用于音频 |

**f_clk = 49.152 MHz**：由 MS5351 提供 **24.576 MHz**，FPGA 内部 PLL **×2**。

```
MS5351（25 MHz 晶振）
    │  VCO = 786.432 MHz，输出整数分频 ÷32
    ↓
24.576 MHz（= 512 × f_s）
    │  经 USR_CLK_IN = N22 进 FPGA
    ↓
FPGA PLL：IDIV=1, FBDIV=1, MDIV=32, ODIV0=16（CLKFB_SEL = INTERNAL）
    │  Fpfd = 24.576 MHz（19~81.25）
    │  VCO  = 24.576 × 1 × 32 = 786.432 MHz（650~1300）
    ↓
f_clk = 786.432 / 16 = 49.152 MHz
```

**PLL 取值范围**（以工具报错为准）

| 量 | 范围 |
|---|---|
| PFD | **19 ~ 81.25 MHz** |
| VCO | **650 ~ 1300 MHz** |
| CLKOUT | 6.25 MHz ~ 1 GHz |

> 因 `PFD = FCLKIN / IDIV` 且 `IDIV ≥ 1`，故 **FCLKIN 必须 ≥ 19 MHz**；**12.288 MHz 不能直接喂该 PLL**。
> PLL 原语要点：`CLKOUT0_EN="TRUE"` 之外，**动态使能脚 `ENCLK0` 必须接 `1'b1`**。

**外部时钟源 MS5351**

板上 2 颗 `MS5351M` 是 Si5351 的国产替代，分数分频分母为 20 位整数（最大 1048575），能精确合成音频时钟。
- **I2C 从地址 = `0xC0`**（8'b1100 000X，同 Si5351A）
- **使用 CLK2 输出**（`USR_CLK_IN` 源自 CLK2，不是 CLK0）

**合成 24.576 MHz 的参数（误差 0 ppm）**

```
VCO  = 24.576 × 32 = 786.432 MHz
N    = 786.432 / 25 = 31.45728 = 31 + 1429/3125
输出分频 = 32（整数、偶数 → 占空比 50%）
结果 = 25 × (31 + 1429/3125) / 32 = 24.576 MHz
```

**配置要点**
- 配 MS2 分频（寄存器 0x3A~0x41）；`Reg18(0x12) = 0x4F`（CLK2 / MS2 / PLLA / 8 mA）
- **`Reg187(0xBB) = 0xD0`（fanout 使能，不加则无输出）**
- `Reg3` 只使能 CLK2（`0xFB`）
- **扩频（Spread Spectrum）必须关闭**
- MS5351 输出为 3.3 V CMOS 方波

### 3. 时钟处理

**内部逻辑：全部使用 clock enable，仅有一个时钟域。**

- 所有寄存器都挂在 `f_clk` 上，用 `sample_enable` / `bclk_enable` 等使能控制节拍
- 好处：**内部无跨时钟域问题**，不需要同步器 / 异步 FIFO
- 代价：使能信号需要扇出到全芯片，需注意扇出平衡

**对外输出：普通寄存器输出即可。**

- BCLK = 1.536 MHz（÷32）、LRCK = 48 kHz（÷1024）均为整周期分频，普通寄存器输出即得 50% 占空比
- 可选加 IOB 约束，让输出寄存器进 IOB
- PLL 的 CLKOUT 由工具自动接入全局时钟网络（GCLK）

**三处时钟域边界：**

| 边界 | 处理 |
|---|---|
| MIDI 输入（外部异步串行） | 两级触发器同步，必要时加去毛刺 |
| I2S 输出时钟 | 与主逻辑同源，无需 FIFO |
| 复位（异步输入） | 同步释放（见 §4） |

**节拍链（全系统只有一个 48 kHz 帧节拍源）：**

```
f_clk ──÷1024──▶ sample_enable ──▶ pt8211_tx ──▶ sample_stb ≡ frame_stb
                                                  （全系统的帧边界 / 提交时刻）
f_clk ──÷1024──▶ voice_slot_seq ──▶ slot_vld ──┬─▶ 通道处理层
                                                └─▶ 单声部层（端口名 `sample_en`）
```

- `sample_enable`（÷1024 = 48 kHz）是**帧节拍的唯一产生点**；`pt8211_tx` 以它为输入并回送 `sample_stb`，两者同拍同频，全文统一记作 **`frame_stb`**（`§三` 的提交相位、`§五.8.5.1` 的时隙计数复位都用它）。
- **时隙节拍**由 `voice_slot_seq` 产生（每帧 `G` 个脉冲），同一根线同时送通道处理层与单声部层——单声部层的端口名沿用 `sample_en`，与 `slot_vld` **是同一根信号**（见 §五.5.1、§8.5.1）。
- **禁止**任何模块自行分频产生第二个 48 kHz 节拍。

### 4. 复位方案

采用 **异步复位、同步释放**：

```
rst_n (异步)  ──→ [触发器1] ──→ [触发器2] ──→ rst_sync_n
                   ↑          ↑
                 f_clk      f_clk
```

- **异步断言**：复位到来立即生效，不依赖时钟
- **同步释放**：释放沿与 `f_clk` 对齐，避免亚稳态
- 复位信号应走**专用复位网络**（Gowin 的全局复位资源），不要用普通布线

### 5. 复位情况表

| 模块 / 资源 | 复位后的状态 |
|---|---|
| **声部状态表** | 全部置 IDLE；`gate` = 0；运行状态字段归零 |
| **通道状态表** | 运行参数归零或默认；配置项（`max_voices`、`default_timbre`）载入默认值 |
| **音色参数表 / 波表 / 音色映射表** | **不受复位影响**（BRAM 初值已固化） |
| **效果参数表** | 载入默认值 |
| **主输出参数表** | 载入默认值 |
| **效果器延迟线** | 清零 |
| **MIDI 消息解析** | 状态机回 IDLE；运行状态缓存清零 |
| **声部时序器** | 计数器归零 |
| **声部取数器** | 预取寄存器置无效 |
| **声部分配 / 释放器** | 无待处理事件 |
| **I2S 发送** | 停止移位输出 |
| **全局 `ready`** | 复位释放后置低，**各表载入完成后置高** |

- **BRAM 初值不受复位影响** —— 只读表（音色 / 波表 / 映射表）无需复位逻辑
- **延迟线必须清零** —— 否则上电会有残留噪声

## 二、输入输出接口

### 1. 输入接口

| 位置 | 名称 | 说明 |
|---|---|---|
| 板外 → FPGA | **乐器端口 ×3** | 每个端口 I2C / MIDI 二选一；进 FPGA 前统一转为 MIDI |
| 板外 → FPGA | **混音器端口** | **独立接口**（第 4 路）；全部消息进混音 / 控制路径 |

- 乐器端口的**混音类 CC（7 / 10 / 91 / 93 / 94）直接丢弃**
- 混音器端口提供：`volume`、`pan`、`send_reverb`、`send_chorus`、`send_delay`、效果参数、主音量
- 引脚见 [[#附录 A：硬件信息表]]（MS5351 I2C、PMOD、按键等）

**结论（混音器端口与 4 路解析架构）**：

| 项 | 结论 | 理由 |
|---|---|---|
| 物理形态 | **标准 MIDI UART，31250 baud**（与乐器端口一致） | 板外混音设备只需一根 MIDI 线；FPGA 侧复用同一套位定时（÷1573） |
| 4 路解析架构 | **各配一个独立解析器**（4 份并行） | ① 4 个解析器各自只占极少逻辑（位定时计数器 + 移位 + 状态字节）；② **共用需仲裁**会引入消息丢失风险与额外延迟，与"确定性延迟"目标相悖；③ 混音器端口的消息**不得被乐器端口抢占**，物理分离最干净 |
| 乐器端口过滤 | 解析器出口按**端口号 + CC 号**过滤，丢弃 CC7/10/91/93/94 | 混音调节只认混音器端口 |
| 汇总 | 4 路解析后的消息汇入同一条事件总线（按到达次序），由通道状态表编辑器 / 分配器统一处理 | 消息本身携带端口号，下游无需区分来源 |

### 2. 输出音频链路

**（1）板载音频链路**

Dock 板已有**完整的音频通路**（原理图页 `FPGA_AUDIO`），不需要自行设计：

| 器件 | 型号 | 作用 |
|---|---|---|
| U6 | **PT8211-S** | **DAC**（16-bit 立体声，R-2R） |
| U32 | **XPT4809** | **功率放大**（`INA/INB/OUTA/OUTB/EN`） |
| U8 / U23 | LMV321 | 耳机缓冲 |
| U20A/B | BL1551 | 模拟开关（耳机 / 喇叭切换） |
| J29 | PJ-342 | **3.5mm 耳机口**（CTIA） |
| J30 | Conn_01x02 | **喇叭座** |
| — | — | 低通滤波、`HP_DET` 耳机检测、`PA_EN` 功放使能、**MIC 输入** |

**（2）引脚连接**

| 信号 | FPGA 引脚 | 引脚功能 | Bank |
|---|---|---|---|
| **I2S_BCLK** | **E22** | `IOB37A` | 5 |
| **I2S_LRCK** | **F24** | `IOB140B` | 4 |
| **I2S_DIN** | **G24** | `IOB140A` | 4 |
| **PA_EN** | **H17** | `IOB91A` | 5 |

> **PA_EN 高电平有效**（Pro 板）。官方例程 `.cst` 漏了 PA_EN 约束，自建工程需补 `IO_LOC "PA_EN" H17;`。
> BCLK 在 bank5，LRCK/DIN 在 bank4；实测两 bank 的 VCCIO 与 LVCMOS33 兼容（已正常出声）。

**（3）数据格式【关键：PT8211 不是标准 I2S】**

**PT8211 使用 LSBJ（Least Significant Bit Justified）格式，又称「日本格式」。**

| 特性 | PT8211（LSBJ） | 标准 I2S |
|---|---|---|
| 位序 | **MSB 先出**，二进制补码 | MSB 先出 |
| MSB 位置 | **紧贴 WS 跳变** | 跳变后**延后 1 个 BCK** |
| WS 极性 | **WS 高 = 左声道**，低 = 右声道 | WS **低** = 左声道 |
| 位宽 | **16 bit**（多出的位被截断） | 视器件 |

**⇒ 若直接套用标准 I2S，会出现：左右声道颠倒**（WS 极性相反），且位对齐差 1 拍。

**帧结构**

```
WS:    ┌── 左声道 ──┐┌── 右声道 ──┐
       │  16 × BCK  ││  16 × BCK  │
DIN:   MSB ... LSB   MSB ... LSB
       ↑                ↑
       紧贴 WS 跳变      紧贴 WS 跳变
```

**项目当前配置**

| 项 | 值 |
|---|---|
| 数据位宽 | **16 bit**（受 PT8211 限制） |
| 每声道 BCK 数 | **16** |
| 帧长 | 32 BCK |
| 采样率 | 48 kHz |
| BCLK | 1.536 MHz（`USE_PLL=0` 的 bring-up 配置下为 1.5625 MHz） |
| 对齐方式 | **LSBJ（日本格式）**，非标准 I2S |
| MCLK | 不需要 |

**（4）实现要点**

**移位与对齐**
- MSB 先出，**紧贴 WS 跳变**（不是 I2S 的延后 1 拍）
- 每声道恰好移 16 位
- **WS 高 = 左声道**

**时钟沿**
- BCLK / LRCK 用普通寄存器输出（整周期分频，50% 占空比），可选加 IOB 约束
- 数据在 BCLK **下降沿**更新，DAC 在上升沿采样

**位深匹配**
- 内部可保持 24 bit 精度，**送 DAC 前截断/舍入到 16 bit**（建议带抖动 dither，否则小信号失真）
- 若误按 24 bit 对齐发送，数据会整体错位 → 音量异常或噪声

**PT8211 电气约束**

| 项 | 限制 | 我们 |
|---|---|---|
| BCK 频率 | ≤ 18.4（可到 20）MHz | 1.536 MHz ✓ |
| WS 频率 | ≤ 384 kHz | 48 kHz ✓ |
| 输入高电平 VIH | ≥ 1.8 V（VDD=5V 时） | FPGA 3.3 V ✓ |
| 供电 | 板载 +5V | ✓ |
| 内部结构 | 8 倍过采样 R-2R | — |
| 群延迟 | 手册未给 | 保守估 ≤ 0.2 ms |

> PT8211 手册见 `material/PT8211 V1.7_E.pdf`。

> **PT8211 群延迟：暂缓实测**（`测试清单.md` T-6 / H10 亦标为暂缓）。
> 理由：该值只影响 ≤5 ms 指标的**余量**，而当前干路预算约 **1.3 ms**，
> 即使 PT8211 群延迟取保守估计 0.2 ms 仍有约 3.5 ms 余量，**不构成风险**。
> 若将来要精确回填，方法是"送一个阶跃码流、示波器测 DAC 输出的建立时刻"。

### 一、总体结构

#### 1. 模块划分

| 模块 | 类别 | 文件 | 职责 |
|---|---|---|---|
| `midi_parse` | 事件 | `rtl/scheduler/midi_parse.v` | 单路 UART 接收 + 字节流解析 + 运行状态 + SysEx 保护。**例化 4 份** |
| `midi_arb` | 事件 | `rtl/scheduler/midi_arb.v` | 4 路消息汇流（带端口号），单条串行交付 |
| `midi_filter` | 事件 | `rtl/scheduler/midi_filter.v` | 按「端口号 × 消息类型/CC 号」过滤与分流 |
| `chan_table` | 事件 | `rtl/scheduler/chan_table.v` | 通道状态表：双缓冲本体 + 待写缓冲 + `P` 个并行读口 + 派生字段计算 |
| `timbre_map` | 事件 | `rtl/scheduler/timbre_map.v` | `(bank_msb, program)` → `timbre_slot[2:0]` |
| `voice_alloc` | 事件 | `rtl/scheduler/voice_alloc.v` | 声部分配 / 抢断 / 释放；写声部表分配类字段；产出分配事件 |
| `voice_slot_seq` | 周期 | `rtl/scheduler/voice_slot_seq.v` | 时隙时序器（**可直接复用模块三已有实现**） |
| `voice_fetch` | 周期 | `rtl/scheduler/voice_fetch.v` | 声部取数器：预取参数、写回运行状态 |

#### 2. 两条路径

```
事件路径（消息到达，延迟不敏感）
  4× UART ─→ midi_parse ×4 ─→ midi_arb ─→ midi_filter ─┬─→ chan_table（待写缓冲）
                                                        ├─→ timbre_map
                                                        ├─→ fx 参数表（接口留给全局层）
                                                        └─→ 主输出参数表（同上）
                                       voice_alloc ←────┘（Note On/Off）

周期路径（每采样，必须在 1024 拍内跑完）
  frame_stb ─→ voice_slot_seq ─→ voice_fetch ─→ 单声部层 ─→ 通道处理层
                    ▲                 │
                    └── 声部状态表 ←──┘（写回）
```

**唯一的跨路径耦合点**：
- `voice_alloc` 不直接改写计算路径正在使用的字段，只通过**「已分配 / 已释放」事件 FIFO** 通知 `voice_slot_seq`；
- 所有事件类写入都在 **`frame_stb` 帧边界**提交（§三.一.4）。

#### 3. 时钟与复位

- 单一 `f_clk = 49.152 MHz` 时钟域，全部用 clock enable 节拍：`frame_stb`(÷1024)、`bclk_en`(÷32)、`midi_tick`(÷1573)。
  > ⚠ 单声部层的端口 `sample_en` **不是**这个 ÷1024 的帧节拍，而是 `voice_slot_seq` 输出的**时隙节拍**（每帧 `G` 个脉冲）——
  > 两者是两根不同的线，见 §一.3「节拍链」与 §五.5.1。
- 复位：**异步复位、同步释放**（两级触发器），走专用复位网络。
- `ready`：由本层产生，送顶层。`ready = pll_locked & ~rst_sync_n` 的释放沿延迟 **16 拍**后置高；只读表（音色参数表 / 波表 / 映射表）由 BRAM 初值固化，**不受复位影响、不参与载入**。
- MIDI 输入：`rx` 外部异步 → **两级触发器同步** → 送入 `midi_parse`。

#### 4. 提交相位（全系统唯一）

`frame_stb`（来自 `pt8211_tx.sample_stb`）是**全系统唯一提交时刻**：

| 表 | 提交方式 |
|---|---|
| 通道状态表 | 双缓冲，`frame_stb` 边界翻转 bank 选择位 |
| 效果参数表 / 主输出参数表 | 双缓冲，同一时刻提交（由全局层实现，本层只提供 `frame_stb`） |
| 声部表运行状态 | 采样边界统一写回（由 `voice_fetch` 执行） |

### 二、MIDI 消息解析（事件类）

#### 1. 4 路独立解析器

| 端口号 | 来源 | 说明 |
|---|---|---|
| 0 / 1 / 2 | 乐器端口 ×3 | I2C / MIDI 二选一（板上转换），混音类 CC **丢弃** |
| 3 | 混音器端口 | 全部消息进混音 / 控制路径 |

**4 路各配一个独立解析器**，不共用：避免仲裁丢消息与延迟不确定性。每份带 `parameter [1:0] PORT_ID`。

#### 2. 位定时与字节接收

- 位时间：`1 / 31250 = 32 µs = 1572.864` 个 `f_clk` → 取 **1573**（误差 0.0086%，远小于 UART 容差 ±2%），**不需要累加器**。
- 接收流程：

```
空闲线 = 1
  ① 检测 1→0 跳变（起始位）
  ② 等 1.5 bit（= 2359 拍）→ 采第 0 位（bit 中心）
  ③ 每 1573 拍采一位，共 8 位
  ④ 再等 1573 拍采停止位，必须为 1；为 0 → framing_error（丢弃该字节）
```

- 采样计数器：`bit_cnt` 计 `0..1572` 循环；起始延迟 `START_DLY = 2359`；位间隔 `BIT_TICK = 1573`。
- **极性**：`parameter INV_INPUT = 0`，为 1 时对 `rx` 取反（6N138 光耦输出通常反相，上板一位切换，不必等硬件结论）。

#### 3. 解析状态机

状态编码（3 位）：

| 状态 | 编码 | 含义 |
|---|---|---|
| `ST_IDLE` | `3'd0` | 等状态字节 |
| `ST_D1` | `3'd1` | 等第 1 个数据字节 |
| `ST_D2` | `3'd2` | 等第 2 个数据字节 |
| `ST_SYSEX` | `3'd3` | 收集 SysEx 数据 |
| `ST_SYSEX_SKIP` | `3'd4` | 丢弃剩余 SysEx，直到 `F7` |

**字节分类**（每个收满的字节先过这一层，再进数据字节状态）：

| 字节 | 处理 | 运行状态 |
|---|---|---|
| `0x80`–`0xEF` | 记为本条消息的状态字节；`0xCn` / `0xDn` 只需 1 个数据字节，其余需 2 个 | **替换** |
| `0xF0` | 进 `ST_SYSEX`，长度计数清零，固化端口号 | **清除** |
| `0xF1` / `0xF2` / `0xF3` | 按 System Common 收 1~2 个数据字节后发射 | **清除** |
| `0xF4` / `0xF5` / `0xF6` | 直接丢弃 | **清除** |
| `0xF7` | 在 `ST_SYSEX` 内是终止符；在 `ST_IDLE` 内忽略 | **清除** |
| `0xF8`–`0xFE` | **就地旁路**：不参与解析、不计入数据字节数、不改变运行状态、不打断当前消息 | **不影响** |

**边界情况**：

- 数据字节**多于**期望：多出来的按「下一条运行状态消息的第一个数据字节」处理（即不丢弃，回 `ST_D1` 重新开始）。
- 数据字节**不足**：等下一个状态字节；未完成的消息被**重置**（发射一个 `msg_drop` 脉冲供调试计数）。
- 实时字节可插在**数据字节之间**（如 `90 F8 3C F8 64`），因此判断必须放在**每个字节入口**，不是消息边界。

#### 4. 消息输出格式（非 SysEx）

| 信号 | 位宽 | 说明 |
|---|---|---|
| `msg_vld` | 1 | 单拍脉冲；**保持到 `msg_ack`**（供 `midi_arb` 仲裁） |
| `msg_status` | 8 | 状态字节（含通道号 `n`） |
| `msg_d0` / `msg_d1` | 8 / 8 | 数据字节；未用填 0 |
| `msg_port` | 2 | 端口号（`parameter`） |
| `msg_drop` | 1 | 调试用：未完成消息被重置时拉高一拍 |

#### 5. SysEx 与保护

**格式**：`F0 <厂商ID/通用ID> <数据…> F7`，第二字节 `7E` = Universal Non-Real-Time、`7F` = Universal Real-Time。

本层只做**通用交付**，不做参数解读：

| 信号 | 位宽 | 说明 |
|---|---|---|
| `sysex_start` | 1 | 单拍脉冲，校验通过后发出；同拍 `sysex_len` 有效 |
| `sysex_len` | 7 | 后续字节数（不含 `F0` / `F7`） |
| `sysex_vld` | 1 | 每拍一个字节 |
| `sysex_byte` | 8 | SysEx 数据字节（**已剔除** `F0` / `F7`） |
| `sysex_err` | 1 | 超长 / 超时 / framing 错误时，整条丢弃并拉高 |

**保护参数**（两个都做，互为兜底）：

| 保护 | 值 | 依据 |
|---|---|---|
| 长度上限 | **64 字节** | 本项目最长 SysEx = 效果参数 7 字节、主音量 8 字节，留 8 倍余量 |
| 字节间超时 | **10 ms = 312 个 `midi_tick`**（9 位计数器） | 正常字节间隔 ≤ 1 字节时间（320 µs），10 ms 足够宽松又不会真卡死 |

**实现方式**：解析器内部缓存整条 SysEx（64 字节小 RAM），**校验全部通过后**才通过上述接口交付——避免下游看到"解析到一半才发现超长"的半条消息。超限 / 超时后清缓冲、回 `ST_IDLE`、清运行状态。

> 下游分工（不属于本层）：`F0 7D <slot> <param> <val_hi> <val_lo> F7` → 效果参数表（厂商 ID `0x7D`）；
> `F0 7F <dev> 04 01 ll mm F7` → 主输出参数表（主音量，14 位）。

#### 1. 端口 × 消息过滤

| 消息 | 乐器端口（0~2） | 混音器端口（3） |

| Note On / Note Off | 处理 | 处理 |

#### 2. 消息 → 目标（分发映射）

| 消息 | 目标 |
|---|---|
| Note On / Note Off | `voice_alloc` |
| CC 演奏类 / 混音类 | `chan_table` 待写缓冲 |
| Program Change（含待用 Bank） | `chan_table`（写 `program`）+ `timbre_map`（更新该通道的 `timbre_slot` 待用值） |
| Pitch Bend | `chan_table`（写 `bend_value`，触发 `bend_ratio` 重算）。⚠ **调度层已实现；声部层未接**（`note2inc` 未乘 `bend_ratio`），故弯音暂不生效 —— 见文末勘误 |

| 效果参数 SysEx | 效果参数表（交给全局层接口） |

#### 3. 通道表字段编号（`field_id`）

待写缓冲条目 = `{ch[3:0], field_id[4:0], value[15:0]}`。

| `field_id` | 字段 | `field_id` | 字段 |
|---|---|---|---|
| 0 | `volume` | 9 | `send_reverb` |
| 1 | `pan` | 10 | `send_chorus` |
| 2 | `expression` | 11 | `send_delay` |
| 3 | `sustain_pedal` | 12 | `bank_msb` |
| 4 | `sostenuto_pedal` | 13 | `bank_lsb` |
| 5 | `attack_mod` | 14 | `program` |
| 6 | `release_mod` | 15 | `bend_value` |
| 7 | `resonance_mod` | 16 | `bend_range` |
| 8 | `filter_cutoff_mod` | 17 | 保留（`note_count` 由分配器内部维护，不经 FIFO） |

**Bank Select 的"待用值"语义**（照 `MIDI协议.md`）：

- 单独发 `CC0` / `CC32` **不生效**，只更新 `bank_msb` / `bank_lsb`；

- Bank Select **不改变正在发声的音符**。

### 四、通道状态表

#### 1. 存储组织

| 项 | 约定 |
|---|---|
| 本体 | **双缓冲**：两份参数寄存器区，各 16 项 |
| 每项位宽 | **182 bit**（`技术文档.md` §四.1「通道状态表」全部字段逐项相加：7+7+7+7+16+14+8+7+7+6+6+7+16+16+7+7+7+7+7+7+1+1+7） |
| 总规模 | 16 × 182 × 2 = **5824 bit ≈ 5.7 Kbit**（寄存器实现） |
| 读侧 | **`P` 个并行读口**（`voice_fetch` 每时隙一次读走该时隙所需全部通道参数） |
| 写侧 | 待写缓冲 FIFO（§2），帧边界提交 |
| 为什么不用 BSRAM | 一个时隙内要并发读 `P` 个声部的通道参数；单口 BSRAM 每拍只读 1 次会**停拍** |
| 复位 | 运行参数归零；配置项 `max_voices` / `default_timbre` 载入默认值 |

#### 2. 待写缓冲与提交

| 项 | 约定 |
|---|---|
| 条目 | `{ch[3:0], field_id[4:0], value[15:0]}` = 25 bit |
| 深度 | **4**（事件极稀疏：MIDI 一帧最快 960 µs ≈ 46 个采样周期） |
| 满 / 溢出 | 溢出时**丢弃最旧**并计数（`wr_ovf`），不阻塞事件路径 |
| 提交 | `frame_stb` 边界：把 FIFO 内全部条目写入后台 bank（同一拍可写多条，寄存器写口足够） |
| bank 翻转 | 提交完成后翻转 1 bit bank 选择位 |
| 一致性 | 读方整帧只读当前 bank ⇒ 不会"半新半旧"；**双缓冲足够，不需要三缓冲** |

#### 3. 派生字段（在 `chan_table` 内、控制率计算）

| 字段 | 触发 | 算法 |
|---|---|---|
| `pan_gL` / `pan_gR` | `pan` 变化 | 等功率律：`gL = cos(θ)`、`gR = sin(θ)`，`θ = (pan/127)·π/2`；中心 0.7071（−3 dB）；**64 项表**（`pan[6:1]` 查表 + `pan[0]` 插值），输出 Q1.15 |
| `bend_ratio` | `bend_value` 或 `bend_range` 变化 | `2^(Δsemi/12)`，`Δsemi = (bend_value − 8192)/8192 × bend_range`；查 `bend_exp.hex`（**512 项**，覆盖 ±24 半音）+ 线性插值，索引由 `dsemi` 换算（**不是**"bend_value 高 7 位"）；输出 **Q2.14 无符号**，中心值 **16384**（= 1.0）<br>⚠ **2026-10-16 更正**：原写"128 项 / Q1.15 / 中心 32768"三处均有误 |
| `note_count` | 分配 / 释放 | 由 `voice_alloc` 维护（读改写同一份寄存器） |

> 表数据（等功率表、指数表）由波表 / 系数表生成脚本一并产出，与 `wave_table/` 的输出一起固化。

### 六、声部分配 / 释放器

#### 1. 分配优先级（Note On）

```
① 同通道、同 note、且 gate=1 的声部存在  → 重新触发该声部（复用，按新力度重采包络）
② 否则存在空闲声部（env_state == IDLE 且 gate == 0）→ 取编号最小者
③ 否则抢断：本通道内 age 最大（最老）的声部
```

- 步骤 ① 的"重新触发"：不重新分配，只更新 `velocity` / `velocity_gain` / `age`，并把 `env_state` 强制回 `ATTACK`。
- 步骤 ② 的一拍实现：`N = 32` 个"空闲"标记 → 优先级编码器。
- 步骤 ③ 的 `age` 比较：32 输入比较树（可流水，事件路径不限拍）。
- `max_voices` 限制：步骤 ②③ 需先检查该通道 `note_count < max_voices`；若已达上限，则只在本通道内抢断。

#### 2. 抢断与淡出

- 抢断**必须走约 1 ms 的快速释放斜坡**（直接切断有 click）。
- 实现：**复用现有 `RELEASE` 状态**，把该声部的 `release_step` 临时改为约 1 ms 对应的步进值，**不新增状态**；斜坡结束后声部回到 `IDLE`（由 ADSR 自己完成）。
- 分配器只需把该声部标记为"已释放"并立即重新分配（新 Note On）。

#### 3. 字段归属（谁会写声部表）

| 字段组 | 写者 | 时机 |
|---|---|---|
| 分配类：`note` / `velocity` / `channel` / `timbre_slot` / `gate` / `velocity_gain` / `age` | `voice_alloc` | 事件到达，**经写口 + 采样边界提交** |
| 运行状态：`phase_acc` / `phase_inc` / `env_value` / `env_state` / `filter_ic1/2` | `voice_fetch` | **`frame_stb` 帧边界**统一写回（§三.八.2） |
| 演奏控制：`gate` | `voice_alloc`（Note Off 只写 `gate = 0`） | 事件到达 |

> **声部表没有 `pending_release`、也没有 `sustain_pedal`**：延音踏板保持由 ADSR 自己读通道表的 `sustain_pedal` 判定（`技术文档.md` §五.1.6「ADSR / VCA」结论）。

> **`velocity_gain` 从哪来**：由 `voice_alloc` 在分配时用 `velocity` 与**音色参数表**的 `vel_sensitivity` 派生
> （公式见 `技术文档.md` §四.2（4））—— 因此 `voice_alloc` 需要一路**音色参数表读口**（按 `timbre_slot` 索引），
> 该读口与 `voice_fetch` 的读口互不影响（只读表，无写冲突）。

#### 4. 分配事件（→ 时序器）

FIFO 条目 = `{voice_id[4:0], op[1:0]}`（`op`：0=分配、1=释放、2=抢断），深度 **4**。
`voice_slot_seq` 在帧边界消费，保证"分配器不改写计算路径正在使用的字段"。

#### 5. Note Off / 控制类消息

| 消息 | 动作 |
|---|---|
| Note Off（力度可为 0） | 找到该通道该 `note` 且 `gate=1` 的声部 → **只写 `gate = 0`** |
| Note On 力度 = 0 | 按 Note Off 处理（MIDI 规范） |
| CC120 All Sound Off | 该通道全部声部 → `env_state = IDLE`、`gate = 0`、`env_value = 0`（**不走 RELEASE**） |
| CC121 Reset All Controllers | 复位控制器，**不复位**：Program Change、Bank Select、`volume`、`pan`、Portamento Time、`send_reverb`、`send_chorus` |
| CC123 All Notes Off | 该通道全部声部 → `gate = 0`（**走正常 RELEASE**） |
| CC122 / 124–127 | 忽略 |

### 七、周期类：声部时序器 `voice_slot_seq`

**接口**（照本文 §8.5.1）：

| 信号 | 位宽 | 方向 | 定义 |
|---|---|---|---|
| `clk` / `rst_n_sync` | 1 / 1 | 输入 | — |
| `frame_stb` | 1 | 输入 | 采样帧起始，复位内部拍计数 |
| `slot` | 2 | 输出 | 当前时隙号 `0 ~ G-1` |
| `slot_vld` | 1 | 输出 | **单拍脉冲**，时隙开始时拉高 1 拍 |

**四条硬性契约**（违反则下游行为未定义）：

1. 每采样周期**恰好发 `G` 个** `slot_vld`，且**位置固定**；
2. 每个脉冲**恰好 1 拍宽**；
3. `slot` 在 `slot_vld` 那一拍有效，取 `0,1,…,G-1` **顺序递增**；
4. 第一个脉冲距 `frame_stb` **至少 1 拍**（不能同拍）。

**默认参数**：`STRIDE = 32` 拍间距 → 时隙落在 `cyc = 1 / 33 / 65 / 97`，
4 个时隙跨度 96 拍，加上通道层的 48 拍（32 拍累加 + 16 拍输出）约 169 拍，
占 1024 拍的 **16.5%**。
`cyc` 计数器由 `frame_stb` 复位（时隙边界与采样同步，这是确定性延迟的前提）。

> ⚠ **2026-10-19 修正**：`STRIDE` 由 **8 改为 32**。
> 原因：`wave_fetch` 全片只有一份波表 ROM，**每个时隙要串行扫 `2P = 16` 个地址**，
> 而 `STRIDE = 8` 让时隙每 8 拍就来一次 —— 扫描指针每 8 拍被新的 `sample_en` 清零，
> **永远扫不满 16 拍**。实测：每帧 `slot_vld` 4 次但 `rom_rdy` 只有 **1 次**，
> 4 个时隙里 3 个拿不到波表数据 → 输出变成阶梯状低频噪音（实板听感"炸/乱码"）。
> **通用约束：串行资源（单口 ROM、单乘法器、单累加器）的占用周期必须小于调度间隔。**

### 八、周期类：声部取数器 `voice_fetch`

#### 1. 预取

`voice_fetch` 的取数口**单口**，靠预取隐藏读延迟：

```
时隙 g：  [取数器读第 g+1 时隙参数 →  P 组预取寄存器]
     ‖    [单声部层用第 g 时隙参数计算]
```

- 预取字段（每个泳道一份，合计 **169 bit**）：`phase_inc`(32)、`wave_sel`(2)、`timbre_slot`(3)、`f_coeff`(16)、`q_coeff`(16)、`filter_type`(2)、`attack_step`(16)、`decay_step`(16)、`sustain_level`(16)、`release_step`(16)、`gate`(1)、`sustain_pedal`(1)、`velocity_gain`(16)、`vca_gain`(16)。
- 寄存器量：169 × P = 169 × 8 = **1352 bit ≈ 1.3 Kbit**。

#### 2. 写回缓冲

| 字段 | 位宽 |
|---|---|
| `phase_acc` | 32 |
| `env_value` | 16（Q1.15，满量程 **32767**） |
| `env_state` | 3 |
| `filter_ic1` | 32 |
| `filter_ic2` | 32 |
| `lfo_phase`（**预留**，LFO 暂缓但位宽保留） | 24 |
| **合计** | **139 bit / 声部** |

- 写回时刻：**采样边界（= `frame_stb` 帧边界）统一写回**（不是算完立即写）。
- 缓冲规模：139 × N = 139 × 32 = **4448 bit ≈ 4.3 Kbit**（寄存器实现）。
- `phase_acc` 运行时**不主动清零**（仅复位时归零）：频率切换时保持相位连续。

#### 3. 与单声部层 / 通道层的接口（**冻结**，照本文 §8.5.1 的接口表）

**输出到单声部层**（全部 × P 并行）：`vld`(1)、`phase_inc`(32)、`wave_sel`(2)、`timbre_slot`(**3**)、`f_coeff`/`q_coeff`(16)、`filter_type`(2)、`attack_step`/`decay_step`/`sustain_level`/`release_step`(16)、`gate`/`sustain_pedal`(1)、`velocity_gain`/`vca_gain`(16)。

**时序**：必须在**时隙开始前**稳定并被单声部层寄存；单声部层在时隙边界采样，**不需要握手**。

**从单声部层回来的**：`aud_in`(24×P)、`ch_in`(4×P，**0~15** = `midi_channel − 1`)、`vld`(1×P) 直接送通道处理层；运行状态进写回缓冲。

> 通道号换算**只有这一处**：`ch_addr = midi_channel − 1`。

### 九、声部状态表存储组织

| 项 | 约定 |
|---|---|
| 分 bank | **按泳道分 bank**，每泳道一个**单口 bank** |
| 端口数 | **恒为 `P`，与 `G` 无关**；扩声部（加 `G`）只让 bank 变深 |
| 每 bank 深度 | `G`（默认 4），地址 = 组号 `g[1:0]`；`voice_id = {g, lane}` |

> **术语等价**：**组号 `g` = 时隙号 `slot`**（同一维度的两个名字，全文混用但指同一件事）；
> `lane` = `P` 路并行中的第几路；`voice_id = {slot, lane}`。
| 每声部位宽 | **225 bit**（逐项相加：32+32+16+3+32+32+24+7+7+1+3+16+4+16） |
| 总规模 | 225 × 32 = **7200 bit ≈ 7.0 Kbit** |
| 物理分区 | 按 5 组**分开存储**（DSP 运行状态 / 演奏控制 / 音色引用 / 派生缓存 / 管理调度），因为写者与写频率不同。**注意**：分区只是**物理布局建议**，逻辑上仍由同一个 `frame_stb` 提交；写回缓冲（§三.八.2）只暂存**运行状态组** |
| 与复位 | 全部置 IDLE、`gate = 0`、运行状态字段归零 |

**读写冲突**（照本文 §三.四.1 的存储组织）：

| 冲突 | 处理 |
|---|---|
| `voice_alloc` 写分配类字段 ↔ `voice_fetch` 读同一声部 | 分配器写入后**等一个采样边界**才对该声部生效；由分配事件 FIFO + 帧边界提交保证 |
| `voice_fetch` 写回运行状态 ↔ 下一时隙预取读 | **时刻不重叠**：写回在采样边界、预取在时隙内 |
| 同一声部在写回缓冲未提交前又被分配 | 不允许：分配只发生在帧边界之后，且写回缓冲在提交后清空 |
| 分配类字段 vs 运行状态字段同刻提交 | **字段不重叠、写口独立**：`voice_alloc` 写分配类（`note` / `velocity` / `channel` / `timbre_slot` / `gate` / `velocity_gain` / `age`），`voice_fetch` 的写回缓冲只覆盖运行状态（§三.八.2）；两者都在 `frame_stb` 提交，地址不重叠 |

## 四、数据表示（定点 / 溢出）

### 1. 数据格式（定点数）

| 量 | 格式 | 位宽 | 说明 |
|---|---|---|---|
| 音频样本 | Q1.23 | 24 bit 有符号 | 范围 −1 ~ (1 − 2⁻²³) |
| 系数（增益、发送量、滤波器系数等） | Q1.15 | 16 bit 有符号 | 范围 −1 ~ (1 − 2⁻¹⁵) |
| 单个乘积 | Q2.38 | 40 bit 容器 | Q1.23 × Q1.15 |
| 多路累加 | Q6.38 | 48 bit 容器 | 用 DSP 的 48-bit 累加器 |

> `Qm.n` 的总位数 = `m + n`（`m` 含符号位），故 Q1.23 = 24 bit、Q1.15 = 16 bit。

**归一化规则**：Q1.15 乘法后必须**算术右移 15 位**回到 Q1.23。

```
Q1.23 × Q1.15 = Q2.38  ──(>>>15)──▶  Q1.23
```

若不右移，等于把结果乘了 2¹⁵（增益错约 90 dB）。

### 2. 溢出与饱和

**（1）全模块复用：通用「归一化 + 饱和」单元**

把 48-bit 累加结果压回 24-bit。输入 `acc`（48-bit 有符号，Q6.38 量级）→ 输出 `y`（24-bit Q1.23）：

1. **四舍五入（可选）**：`acc_rnd = acc + 2^14`（在 48-bit 容器里加，不要先截断）
2. **归一化**：`sh = acc_rnd >>> 15`，得 29-bit 有效（Q6.23）
3. **取低 29 位**：`v = sh[28:0]`
4. **溢出判断**：`ovf = (v[28:24] != {5{v[23]}})`
5. **输出**：`ovf = 0` 时 `y = v[23:0]`；`ovf = 1` 时按 `v[28]` 判正负，正溢出给 `0x7FFFFF`、负溢出给 `0x800000`

> 判据含义：24-bit 有符号要装得下，要求第 23 位以上全是符号位，故比较 `v[28:24]` 是否等于 `v[23]` 的 5 位复制。

**（2）各位置的处理**

- **相位累加器**：靠自然回绕（2³² 模）实现周期，**用取模截断，禁止饱和**
- **包络值**：Q1.15 无符号语义，饱和到 `[0, 32767]`（**不是** 0~65535 的 Q1.16 口径，见 `技术文档.md` §五.1.6（4））
- **VCA 乘法后**：饱和到 24 bit
- **通道总线累加**：32 位累加器**不中途饱和**，读出时用一次 `sat24` 压回 24 位
- **主混音求和**：48 位累加器**同样不中途饱和**，最后统一 `sat24` 一次
- **滤波器内部状态**：先对系数 `f` **限幅**（保证稳定），再对状态幅值钳位兜底

## 五、单声部处理

### 1. 音色槽与波表

音色槽数：**8**（`timbre_slot` 3 位，0 ~ 7）

> ⚠ **本口径为最终口径（2026-10-06 定稿），不再预留"只用低 1 位"的过渡写法。**
> 原稿"2 槽 × 4096 点"与扩展指南"4 音色 → 16384 点"的口径不一致，现统一如下。

| `timbre_slot` | 波表地址范围 | 说明 |
|---|---|---|
| 0 | 0 ~ 2047 | 钢琴（示例） |
| 1 | 2048 ~ 4095 | 吉他（示例） |
| 2 ~ 7 | … | 预留（每槽 2048 点） |

- **每槽点数：2048 点**（单周期波形，12 位内索引的高 11 位）
- 波表**总深度：16384 点** = 8 × 2048
- 波表**地址位宽：14 位** = `{timbre_slot[2:0], addr[10:0]}`
- 波表容量：`16384 × 16 bit = 256 Kbit` → **16 块 BSRAM**（16 Kbit 模式，每块 16384 bit）
- `wave_sel` 接口位宽：**2 位**（波表**索引**预留，当前只用 `[0]`；与"音色槽数"是两个概念）
- `timbre_slot` 接口位宽：**3 位**
- 波表数据为 **16 位有符号补码**：`−1` 写 `FFFF`，`32767` 写 `7FFF`

> **为什么取 2048 点/槽而不是 4096**：总容量锁定 256 Kbit（16 块）时，
> 槽数与每槽点数成反比。取 8 槽 × 2048 点可满足赛题"≥2 种音色"并留足扩展，
> 同时**总深度与扩展指南一致（都是 16384）**，以后加音色不必再动地址拼接。
> 2048 点 + 两点线性插值的量化噪声约 −66 dBFS，对单周期波形足够。

### 2. 音色参数表 ROM 深度

每个字段一个独立 ROM，**地址深度 = 音色槽数 = 8**，**地址位宽 = 3 位**（接口预留 4 位）。

> ⚠ **本节曾长期停留在"2 槽"旧稿**（深度 2 / 位宽 1 位 / 字段表按 `2×` 列），

### 4. 波表读取（多声部并发）

**问题**

波表是所有声部共享的资源。在 **P = 8 条并行泳道 × G = 4 个串行时隙** 结构下，同一时隙内 8 条泳道同时工作，**同一时钟拍会出现 8 个不同地址要同时读出**（若做插值，每声部需读相邻两点 → 每拍 16 次读）；而单口 BSRAM 每拍只能读 1 次，无法直接支持。

若为**每个声部各复制一份**波表 ROM，32 声部要占用 **512 块 BSRAM（占全片 340 块的 151%）**，再叠加主通道的效果器 + 延迟线（**146 块**）**更必然超出片上总量**。⇒ 复制方案不可行。

**方案：时隙内串行读 + 寄存器缓存**

核心：**全片只保留 1 份波表 ROM（16 块 BSRAM，16 Kbit 模式），用「时间换口数」** —— 时隙开始处用若干拍把该时隙所需样本**依次读出并存入寄存器**，之后 8 条泳道照常并行计算。

```
地址（来自取数器）──▶ 波表 ROM（全局 1 份，**16384 × 16 bit**，14 位地址）
                       │ 每拍读 1 个地址，串行
                       ▼
                 [ P 个声部的样本寄存器 ]（每声部 2 个：n 与 n+1）
                       ▼
                 P 条泳道并行做 线性插值 → SVF → VCA
```

时序（1 个时隙、P = 8、含插值两点）：

```
拍:   0      1      2      3    ...   14     15     16...
操作: 读n0 → 读n0+1 → 读n1 → 读n1+1 → ... 读n7 → 读n7+1 → [8 条泳道并行计算]
      └──────────── 16 拍串行读（单口）────────────┘
```

开销核算（`N_cyc = 1024` 拍）：

| 项 | 拍数 |
|---|---|
| 每时隙串行读（单口，2 × P） | 16 |
| 每采样共 G 个时隙 | 16 × 4 = **64 拍（6.3%）** |
| 若 ROM 用双口（每拍读一个声部 2 点） | 8 拍/时隙 → 每采样 32 拍（3.1%） |

现有声部处理只占 `G × L ≈ 80` 拍（7.8%，`L` ≈ 20 的**估算**口径；注意与 §三.七 的 `G × STRIDE = 32` 拍、§六.7 实测的「首→末 24 拍」是三种不同口径，不要混用），加上本项仍**余量充足**；若把读取做成**预取**（读 slot g+1 的地址时 slot g 正在计算），这几十拍可**完全隐藏在计算时间之后，额外开销 ≈ 0**。

**实现要点**

1. **同步读延迟**：BSRAM 输出比地址晚 1 拍，串行读循环要把这 1 拍计入（地址与数据错开一拍）。
2. **插值两点先入寄存器**：`tab[n]` 与 `tab[n+1]` 都取回后，再由泳道算插值。
3. **地址来源**：每个声部的 `phase_acc` 由**声部取数器**在时隙开始时取出；
   波表地址 = `{timbre_slot[2:0], phase_acc[31:21]}`（11 位表内索引 + 3 位槽号 = 14 位）。
   插值还需 `+1` 的相邻点，注意**跨槽回绕**（索引到槽末时相邻点取该槽首点，不是下一槽首点）。
4. **不能按泳道分 bank**：声部状态表可按泳道分 bank，但**波表地址是任意相位**，无法按泳道划分，只能靠时间复用。

> **结论**：波表**全局 1 份、不复制**；每时隙用 8~16 拍串行读出 P 个声部所需样本（含插值两点）存入寄存器，再并行计算。代价约 3%~6% 的时间（可预取隐藏），换来**约 496 块 BSRAM**（= 32 声部 × (16 − 0.5) 的净节省，按 16 Kbit 模式块折算）。

### 7. 实现注意

- **SVF 关键路径**：递归路径上有**乘法 + 减法** → 关键路径较长。`f_clk = 49.152 MHz`（周期 20.345 ns），余量较充足。
  > **建议**：若时序不满足，可考虑改用 **TPT / ZDF 拓扑**、在非递归路径插流水寄存器，或降低 `f_clk`。
- **ADSR 时间换算**：`adsr_attack` 等来自音色表，公式含除法，实现上可能需要**查表或分段近似**。
- **延迟对齐**：包络路径与音频路径的**流水级数需对齐**（详见 `技术文档.md`「单声部层」）。

### 8.5 周期类模块的时序契约（与模块三 / 单声部层的接口）

> **本节是"调度层 ↔ 音频层"的对接规范**：周期类模块（声部时序器、声部取数器）
> 必须按这里的时序与接口向单声部层与模块三交付数据；模块三与单声部层按此设计即可对接。
> 参数取值：`P = 8`、`G = 4`、`N = 32`、`NCH = 16`、`N_cyc = 1024`、`f_s = 48 kHz`。

#### 8.5.1 周期类模块接口

**（1）声部时序器 → 通道处理层**

| 信号 | 位宽 | 方向 | 定义 |
|---|---|---|---|
| `slot` | 2 | 输出 | 当前时隙号 `0 ~ G-1` |
| `slot_vld` | 1 | 输出 | **单拍脉冲**，在时隙开始时拉高 1 拍 |
| `frame_stb` | 1 | 输入 | 采样帧起始（来自 `pt8211_tx.sample_stb`），用它复位内部拍计数 |

> `slot_vld` **同时送往单声部层**（其端口名为 `sample_en`）——全系统只有这一根时隙节拍线（见 §一.3「节拍链」）。

**硬性时序契约**（违反则通道层行为未定义）：

1. 每采样周期**恰好发 `G` 个** `slot_vld` 脉冲，且**位置固定**；
2. **每个 `slot_vld` 脉冲恰好 1 拍宽**；
3. `slot` 在 `slot_vld` 那一拍有效，且取值 `0,1,…,G-1` 顺序递增；
4. 第一个脉冲距 `frame_stb` **至少 1 拍**（不能同拍，否则时隙计数再同步会错）。

> 模块三侧已有实现可对照：`rtl/voice_slot_seq.v`（每采样发 G 个固定位置脉冲，
> `cyc` 由 `frame_stb` 复位，**默认 `STRIDE = 32` 拍间距**，时隙落在 `cyc = 1/33/65/97`，
> 跨度 96 拍）。
> **调度层可直接用它，或按同一契约自写。**
> ⚠ `STRIDE` 必须同时满足两个条件：**① 调度层与声部层取值一致**（否则 `slot`/`slot_vld` 不同相）；
> **② ≥ `2P + 余量`**（`wave_fetch` 每时隙要串行扫 `2P` 个地址）。详见 §声部层 `wave_fetch` 的说明。

**（2）声部取数器 → 单声部处理层（每声部一份上下文）**

| 信号 | 位宽 | 定义 |
|---|---|---|
| `vld[P-1:0]` | 1 × P | 本时隙第 i 条泳道是否有有效声部 |
| `phase_inc[P-1:0]` | 32 × P | 频率控制字（⚠ **目前不含 `bend_ratio` 调制**，弯音未接；见文末勘误） |
| `wave_sel[P-1:0]` | 2 × P | 波表索引（当前只用 `[0]`） |
| `timbre_slot[P-1:0]` | **3 × P** | 音色槽（0~7） |
| `f_coeff[P-1:0]` / `q_coeff[P-1:0]` | 16 × P | SVF 频率/阻尼系数（Q1.15） |
| `filter_type[P-1:0]` | 2 × P | SVF 输出类型（0=LP，1=BP，2=HP） |
| `attack_step` / `decay_step` / `sustain_level` / `release_step` | 16 × P | ADSR 步进（公式见 `技术文档.md` §五.1.6；取值由**调度层取数器**按声部上下文提供） |
| `gate` / `sustain_pedal` | 1 × P | 按键 / 延音踏板 |
| `velocity_gain` / `vca_gain` | 16 × P | 力度增益 / 音色总增益（Q1.15） |

**时序**：这些量必须在**时隙开始前**（上一个时隙内）就已经稳定并被单声部层寄存。
单声部层用 `sample_en`（= 帧内时隙节拍）在时隙边界采样它们，**不需要握手**。
**做法**：取数器**预取下一时隙**的参数（读延迟隐藏在上一时隙的计算时间里）。

**（3）单声部处理层 → 通道处理层**

| 信号 | 位宽 | 定义 |
|---|---|---|
| `aud_in` | **24 × P** | P 路并行干信号（Q1.23，单声道），与 `slot` 同拍有效 |
| `ch_in` | **4 × P** | 每路声部所属的 MIDI 通道号（**0~15**，即 `midi_channel − 1`） |
| `vld` | 1 × P | 同 (2) |

**（4）状态写回（声部取数器 ← 单声部层）**

每采样周期，单声部层要把运行状态写回声部状态表：

| 字段 | 位宽 | 说明 |
|---|---|---|
| `phase_acc` | 32 | DDS 相位累加器（**不清零**，频率切换保持相位连续） |
| `env_value` | 16 | Q1.15，满量程 **32767** |
| `env_state` | 3 | IDLE / ATTACK / DECAY / SUSTAIN / PENDING_RELEASE / RELEASE |
| `filter_ic1` / `filter_ic2` | 32 × 2 | SVF 两个积分器状态 |
| `lfo_phase`（**预留**，LFO 暂缓但位宽保留） | 24 | 恢复 LFO 时不用改结构 |
| **合计** | **139 bit / 声部** | |

**时序**：**采样边界统一写回**（不是"算完立即写"）——
好处是写回时刻固定（符合确定性延迟要求），且与下一时隙的预取读不重叠。
实现上需要一组**写回缓冲**（`N = 32` 声部 × **139 bit = 4448 bit ≈ 4.3 Kbit**，寄存器实现）。

#### 8.5.2 通道状态表的读取方案

通道层每采样要**读遍 16 个通道**（用于通道增益/声像、效果发送），
即每采样 `16` 次读；同时通道表是**事件驱动写**（B 档）。定稿方案：

| 项 | 结论 |
|---|---|
| 表本体 | **双缓冲**（两份参数），由**采样帧边界**切换 bank |
| 读取侧 | **寄存器实现**，配 `P` 个**并行读口** —— 取数器在每时隙一次性读走该时隙所需的全部通道参数，存入 `P` 组寄存器 |
| 为什么不用单口 BSRAM | 通道层要在**一个时隙内**并发使用 `P` 个声部的通道参数，单口 BSRAM 每拍只能读 1 次，会导致停拍 |
| 为什么用寄存器而不是 BRAM | 16 项 × 约 200 bit = **3.2 Kbit**，寄存器实现很便宜，且天然支持多读口 |
| 提交相位 | **采样帧边界**（全系统唯一提交时刻：通道表、效果参数表、主输出参数表都在此提交） |
| 双缓冲切换 | 1 bit bank 选择位，在提交时翻转；读方整帧只读"当前 bank" |
| 一致性 | 帧内读到的永远是**同一版本**的参数，不会出现"半新半旧" |

> **为什么帧边界提交是充分的**：读方（通道层/效果层）在帧内的固定时刻取参数，
> 提交发生在无人读的帧边界上，因此**效果参数不需要三缓冲**（双缓冲足够）。

### 10. 扩展新音色指南

**当前已是 8 槽 × 2048 点（总深度 16384）**，槽数与点数呈反比。
要继续扩音色的两条路线：

| 路线 | 做法 | 代价 |
|---|---|---|
| **A. 加槽、减点数** | 16 槽 × 1024 点 | 仍 16 块 BSRAM，但每槽点数减半、量化噪声上升约 6 dB |
| **B. 加槽、加容量** | 16 槽 × 2048 点 = 32768 点 | BSRAM 从 16 块 → **32 块**，`timbre_slot` 用 4 位、地址 15 位 |

**具体步骤（以路线 B 为例）**：

| 步骤 | 修改内容 | 从 | 到 |
|---|---|---|---|
| 1 | 波表 `.mi` 的 `Address_depth` | 16384 | 32768 |
| 2 | 波表地址拼接 | `{timbre_slot[2:0], addr[10:0]}` | `{timbre_slot[3:0], addr[10:0]}` |

## 六、通道处理与混音

> 本节覆盖**模块三**：通道处理层 → 效果发送 → 效果运算 → 主混音 → 主输出。
> 算法与接口见 `技术文档.md` §五.2「多通道层」/ §五.3「主通道层」；本节只讲**电路实现、拍数与资源**。
> 状态：**RTL 已实现并通过验证**（23 个模块 = 20 主设计 + 3 留档；**28 个 TB、回归 31 条全绿**）。

### 1. 通道处理层（`chan_layer` / `chan_buf` / `chan_coef`）

```
slot_vld, slot[1:0], vld[7:0], ch_in[8×4], aud_in[8×24]
        │
   ┌────▼─────┐  32 × 28 bit 寄存器堆（896 FF）
   │ chan_buf │  按 (slot,lane) 写入 —— P 路并行写**必须用寄存器堆**，BSRAM 无多写口
   └────┬─────┘
        │ rd_addr = 声部号 0..31（串行读，组合输出）
   ┌────▼──────────┐
   │ 通道总线累加   │ 32 位累加器 × 16，32 拍串行加完
   │ ch_acc[0:15]   │ 组合读 + 寄存写 → 相邻拍可见新值，无需旁路
   └────┬───────────┘
        │
   ┌────▼─────┐  vol_q = vol<<8, exp_q = exp<<8
   │ chan_coef│  g_ch = sat16((vol_q*exp_q)>>>15)
   │ 2 级流水 │  gL/gR = sat16((g_ch*pan)>>>15)
   │ 3 乘法器 │  自由运行，32 拍刷完 16 通道
   └────┬─────┘
        │ gL_flat / gR_flat（16 × 16 bit × 2）
   ┌────▼──────────────┐
   │ acc_sat = sat24()  │  32 → 24 位
   │ ChL = sat24((acc_sat*gL + 2^14) >>> 15)  │  24×16 = 40 位
   │ ChR 同理           │
   └────┬───────────────┘
        │ 16 拍串行输出：ch_vld / ch_addr / ch_l / ch_r + frame_done
        ▼
   主混音 与 效果发送（**共用同一条通道流**）
```

**定点与位宽**（对应 §四）

| 量 | 位宽 / 格式 | 说明 |
|---|---|---|
| `aud_in` / `ch_l` / `ch_r` | 24 bit Q1.23 | 音频 |
| `ch_acc[]` | **32 bit** Q6.26 | `\|Σ\| ≤ 32 × 2²³ = 2²⁸`，32 位留足 |
| `vol_q` / `exp_q` | 16 bit Q1.15 | `7 bit << 8` → 0 ~ 32512 |
| `g_ch` / `gL` / `gR` | 16 bit Q1.15（`sat16`） | 三级合并，**每步都压回 16 位** |
| `acc_sat` | 24 bit Q1.23 | **先饱和再乘**，避免 32 位直接进乘法 |
| 增益乘法 | **24 × 16 = 40 bit** | 这正是"三级合并"的目的：否则 40 × 16 = 56 位，超 DSP 的 48 位累加 |
| 四舍五入 | `+ 2¹⁴` 后 `>>>15` | 与全项目归一化单元一致 |

**⚠ 实现红线（踩过的坑）**：`sat24` 的**入口必须是 48 位**。调用点是
`(pl + RND) >>> 15`（48 位），若函数声明成 32 位，会在**比较大小之前先被截断**，
溢出判断直接失效。

### 2. 效果发送总线（`send_bus`）

- **3 条总线 × 左右两路 = 6 个累加器**，每采样需 `3 × 16 × 2 = 96` 次乘法。
- **用 2 个乘法器（左右各一）做 TDM**，每个做 `3 × 16 = 48` 次 → 计算段 **48 拍**。
  > 注意**不是** 96 拍：左右两路已分给两个乘法器。省下的 DSP 让给效果器。
- **总拍数 = 捕获 16 + 计算 48 + 输出 1 = 65 拍/采样**（占 `N_cyc` 的 6.3%）：
  先把 16 条通道流捕获进寄存器堆（16 × 48 bit），再 TDM 乘累加，最后打一拍输出。
- **定点**：`send_q = send << 8`（`0 ~ 0x7F00`，即 0.0 ~ 0.9922）；
  乘积 24 × 16 = 40 位，**符号扩展到 48 位**后累加；`|Σ| ≤ 16 × 2³⁸ = 2⁴²`，48 位装得下。
- **输出**：`sat24( (acc + 2¹⁴) >>> 15 )` → 压回 24 位送效果器。
- 发送量在**通道层**施加；效果器只乘自己的 `*_return`，主混音不再重复乘。

### 3. 效果器运算（`fx_top` + `fx_reverb` / `fx_chorus` / `fx_delay`）

**总线与握手**

- 三条效果器**全部挂在并行湿路上**，干信号不经过效果器 → **干路额外延迟为零**。
- `fx_top` 用**固定完成时刻**握手：从 `bus_vld` 起数 `LAT_MAX = 128` 拍统一汇总输出；
  另设 `pend`（4 bit）积压计数，处理中再来的 `bus_vld` **排队而不丢**。
- **实测各效果延迟**：`fx_delay` 3 拍、`fx_chorus` 11 拍、`fx_reverb` **121 拍**（最慢）
  → 顶层固定延迟 **130 拍**。
- **必须的兜底**：下游 `main_mix` 的 `ST_WAIT` 有 **1024 拍超时**。
  否则 `fx_vld` 丢一次（上游时序抖动、`frame_stb` 打断计数）会让主混音**永久冻结**。
- **参数平滑**（`fx_top` 内）：12 个参数各一份 16 位平滑值，每采样移动 1/64，
  最坏 1024 采样（约 21 ms）收敛；**复位时同步为当前目标值**（避免上电爬坡）。
  > ⚠ `reverb_pre_delay` **故意不平滑**：它是可变深度延迟线，平滑会引入多普勒音高扭曲，
  > 详见 `rtl/pre_delay.v` 头注释。

**混响（`fx_reverb`）** —— Freeverb 结构

| 项 | 值 |
|---|---|
| 并联梳状 | **8 条**，长度 1215 / 1293 / 1390 / 1476 / 1548 / 1623 / 1695 / 1760 |
| 串联全通 | **4 条**，长度 605 / 480 / 371 / 245（反馈 0.5，用移位 + 加法，**不占 DSP**） |
| 立体声展宽 | 右声道各线 **+25** 点 |
| 缓冲布局 | 左声道 `0 ~ 14745`，右声道从 `14746` 起，共 **29492 × 24 bit** |
| 访问方式 | **单时钟、时分复用一块 BSRAM**（一写一读同拍），5 状态机 **122 拍/采样** |
| 状态机 | `ST_IDLE / ST_RD / ST_ADS / ST_WR / ST_CM / ST_WB` |
| 实现要点 | 读地址用组合 `cur`、写地址在 `ST_ADS` 锁存；全通链输入用 `ap_wire` 链**当拍传递**（否则第 2~4 级读到 0） |

**合唱（`fx_chorus`）**

| 项 | 值 |
|---|---|
| LFO | 相位累加 + 正弦表；`相位增量 = p_rate << 6` → `0 ~ 65535` 对应 `0 ~ 46.9 Hz` |
| 立体声 | 左右**反相** LFO（`lfo_ph + 2³¹`） |
| 调制延迟 | 线性插值（整数 + 小数部分） |
| 缓冲 | **2048 × 24 bit × 2**（左右各一条） |

**延迟（`fx_delay`）**

| 项 | 值 |
|---|---|
| 缓冲 | 深度 `MAXLEN = 32768`（2¹⁵），**有效延迟上限 `DLY_MAX = 24576` 点 = 512 ms @48 kHz**（延迟量在内部限幅到该值）、左右**各一条独立 BSRAM**（共用会串音） |
| 地址 | `ABW = 15`，环形写指针 + 偏移 |
| 运算 | `line[wptr] = bus + (fb × wet) >>> 15`；出 `sat24((bus×(1−mix) + wet×mix) >>> 15)`，再乘 `ret` |

### 3.5 参数写口（调度层 → 效果 / 主输出参数表）

两张表都是**事件驱动写**（B 档）+ **双缓冲**：写入由调度层（MIDI 解析侧）发起，在本层提交。

| 信号 | 位宽 | 方向 | 定义 |
|---|---|---|---|
| `par_wr_vld` | 1 | 输入 | 写请求，单拍脉冲；保持到 `par_wr_rdy` |
| `par_wr_grp` | 2 | 输入 | 0 = 混响组，1 = 合唱组，2 = 延迟组，3 = 主输出组 |
| `par_wr_idx` | 4 | 输入 | 参数号（组内序号，见下方映射表） |
| `par_wr_data` | 16 | 输入 | 参数值（已由调度层按定义域裁剪） |
| `par_wr_rdy` | 1 | 输出 | 可接收（写侧缓冲未满） |

**提交相位**：写入先落**后台 bank**，在 `frame_stb` 边界**整帧一次性提交**（与通道状态表同一时刻，见 §一.3「节拍链」）；1 bit bank 选择位翻转，读方整帧只读当前 bank ⇒ 不会"半新半旧"，**双缓冲足够，不需要三缓冲**。

**参数号映射**（与 `技术文档.md` §四.4 的声明顺序一致）：

| `par_wr_grp` | `par_wr_idx` → 参数 |
|---|---|
| 0（混响） | 0 `reverb_size`、1 `reverb_decay`、2 `reverb_damping`、3 `reverb_pre_delay`、4 `reverb_return` |
| 1（合唱） | 0 `chorus_rate`、1 `chorus_depth`、2 `chorus_mix`、3 `chorus_return` |
| 2（延迟） | 0 `delay_time`、1 `delay_feedback`、2 `delay_mix`、3 `delay_return` |
| 3（主输出） | 0 `master_volume`、1 `limiter_threshold`、2 `limiter_release`、3 `dither_bits` |

> 调度层侧对应的 SysEx：`F0 7D <slot> <param> <val_hi> <val_lo> F7`（`slot` = 组号、`param` = 组内序号）与主音量 `F0 7F <dev> 04 01 ll mm F7`（→ 组 3、号 0）。
> `reverb_pre_delay` **故意不做参数平滑**（可变深度延迟线，平滑会引入多普勒音高扭曲）；其余参数由 `fx_top` 内部平滑，见本节 §3。

### 4. 主混音求和（`main_mix`）

```
ST_ACC ： 边收边加 16 条通道（ch_addr==0 视为新一轮开始），记入 dry（48 位）
ST_WAIT： 等 fx_vld → main = sat24(dry + fx)，打 mix_vld，回 ST_ACC
         等不到则 1024 拍超时，按干声输出（防僵死）
```

- 累加器 **48 位**（`AWX = 48`）：`|Σ| ≤ 16 × 2²³ = 2²⁷`，绰绰有余。
- **不在中途饱和**，只在最后 `sat24` 一次 —— 避免逐级饱和造成的非线性失真。
- 输入 24 位先**符号扩展**到 48 位再相加。

### 5. 主输出处理（`master_chain`）

```
主音量 master_volume → 软限幅 soft_limiter → 隔直 dc_block（可选） → 抖动+截断 dither16
```

| 级 | 实现要点 |
|---|---|
| 主音量 | `G_Q15 = vol << 1`（`14 bit → Q1.15`，误差 < 0.006%）；**±64/采样斜坡**（约 10.7 ms）防咔哒；`24 × 16 = 40 位` |
| 软限幅 | `Env = max(\|L\|,\|R\|)`；`Env ≤ THRESH` 时增益 **1.0**（内部用 17 位中间量 32768 表示，输出前截到 Q1.15 上限 32767），否则算 `THRESH/Env` 的 Q1.15 值；**Attack 立即、Release 一阶**（`>>>4`，差值 ≤1 时直接到位）；阈值默认 `0x600000`（−2.5 dBFS）。<br>**倒数用「正规化 + 32 项 LUT + 线性插值」**（`g = (recip_mant × THRESH) >> k`），**不是综合器推断的 48 位组合除法** —— 后者在 49.152 MHz 下几乎必然过不了时序；实测相对误差 **0.021%**（0.0018 dB），再留 **0.39% 保守余量**（`g −= g>>7`）防包络反馈放大 |
| 隔直 | `y[n] = x[n] − x[n−1] + a·y[n−1]`，`a = 0.995` = Q1.15 的 **32604**；`diff` 先显式扩展到 `W+15` 位再左移（`<<<` 不会自动加宽） |
| 抖动 | 两组独立 LFSR 生成 **TPDF** 噪声（±127 LSB），先**扩到 25 位**再相加；然后 `sat24` → 取 `[23:8]` 得 16 位 |
| I2S 发送 | `DIV_BIT = 32`；`bit_cnt[4] = 0` 时送左字；**`WS_INVERT = 1`**（手册：WS 高 = 左声道，已上板实测确认） |

> ⚠ **软限幅的两条实测红线**：
> ① 输出必须用**组合的当拍增益** `g_cur`，不能用打一拍后的寄存器 ——
>    否则过载出现那一拍用旧增益 1.0，输出**瞬间超过阈值**（实测 6312337 > 6291456）。
> ② 一阶释放要保证能收敛：步长至少 +1，且 `g + step > 目标` 时直接取目标 ——
>    否则增益永远停在 32753，到不了目标 32768（32768 只存在于内部 17 位中间量，输出仍是 Q1.15 上限 32767）。

### 6.5 完整链路顶层（`full_top` + `voice_slot_seq`）

`mix_top` 是**最小闭环**（测试音 → 主输出链 → I2S），只验证 DAC 通路；
**`full_top` 才是模块三的完整集成**：

```
voice_slot_seq（时隙时序器）──┐
test_voice_gen（声部源，暂代）─┴→ chan_layer → send_bus → fx_top → main_mix
                                                                │
                                              master_chain ←────┘
                                                    │
                                              pt8211_tx → DAC
```

**`voice_slot_seq`（时隙时序器）**：每采样发出 **G 个固定位置**的时隙脉冲
（`slot` / `slot_vld`）。位置必须固定，否则无法保证 `G × L + 开销 ≤ 1024`
与"延迟恒定无抖动"。`cyc` 由 `frame_stb` 复位；`slot_vld` 为单拍脉冲；
时隙数 = `G`，扩展声部数只改 `G`、不增硬件。

**`full_top` 的两个关键参数**：

| 参数 | 默认 | 作用 |
|---|---|---|
| `USE_PLL` | 0 | `0` = P16 的 50 MHz 直连（不需配 MS5351）；`1` = N22 的 24.576 MHz + PLL → 49.152 MHz |
| `TEST_MODE_DEFAULT` | 1 | 上电即进测试模式（32 条谱线、效果全关、限幅固定增益），便于现场验证 |

> **声部源现状**：单声部处理层（DDS / SVF / VCA）尚未完成，故用 `test_voice_gen`
> 充当声部源。接入真实声部时只需替换 `u_voices`，接口不变。

### 7. 拍数与资源（**实测值**，非估算）

用拍数剖视 TB `tb_full_top_timing.v`（放仿真目录，见 §三.十一 的路径约定）从 **`full_top` 实际 RTL** 上测出的各段拍数
（40 帧稳定后取值，`USE_PLL=0`、48.828 kHz）：

| 环节 | 文档估算 | **实测** | 基准点 |
|---|---|---|---|
| 声部时隙段（4 时隙，间距 8） | `G×L` 估 | **24 拍** | `slot_vld` 首→末 |
| 通道层收声部 + 累加 | — | **34 拍** | `slot_vld` 末 → `ch_vld` 首 |
| 通道层串行输出 | 16 | **14 拍** | `ch_vld` 首→末 |
| 效果发送（捕获 16 + 计算 48 + 输出 1） | 65 | **63 拍** | `ch_vld` **首次** → `bus_vld` |
| 效果运算（`LAT_MAX=128` + 2） | 130 | **130 拍** | `bus_vld` → `fx_vld` |
| 主混音 | 约 17 | **2 拍** | `fx_vld` → `mix_vld` |
| **全程占用** | — | **256 拍 / 1024** | `sample_stb` → `mix_vld` |
| **余量** | — | **768 拍（75%）** | — |

**结论：实测全程 256 拍，仅占 `N_cyc = 1024` 的 25%，时间预算充裕。**

> ⚠ **测这个必须注意基准点**：`效果发送` 要从 **`ch_vld` 首次**算起，不能从末次 ——
> `send_bus` 是"边收边存"，`ST_CAP` 的 16 拍与 `ch_vld` 的 16 拍**重叠**。
> 从末次算会少 15 拍，把 63 拍误读成 50 拍（写这个 TB 时踩过）。
>
> 另注：`主混音` 实测只有 2 拍（不是估算的 17），因为效果返回在干路通道流到达前就绪，
> `ST_WAIT` 几乎立刻命中；只有效果器失联时才会走 1024 拍超时兜底。

| `chan_layer` | 2 | `acc_sat*gL`、`acc_sat*gR`（采样率） |

| `master_volume` | 2 | L/R 各 1 |
| `soft_limiter` | 3 | `l_in*g_cur`、`r_in*g_cur`（增益施加）+ **倒数 LUT 的插值乘**（`ldiff × mant[1:0]`） |
| **合计** | **33** | 上界（综合器的共享复用会再降；最终以 IDE 报告为准） |

**与文档原估（效果器约 39）对照**：全链实测 **33** 个，其中效果器 20（`fx_delay` 8 + `fx_reverb` 7 + `fx_chorus` 5）、其余 13。逐项差异：
① 混响的 8 条梳状**共用**左右各 1 个乘法器（TDM，省 14）；
② 合唱的插值与干湿合并（省 2）；
③ 效果返回电平并入各效果自身的最后一次乘法（省 4）；
④ 软限幅的倒数用 **LUT + 插值**（3 个乘法器）实现，**避开了 48 位组合除法** —— 省的是时序而非 DSP。
反过来 `fx_delay` 比原估多 4 个（原估按"延迟反馈加干湿"4 个算，实际干湿分 `onem`/`mixx` 两次）。

> **软限幅的倒数实现沿革**（供组内知晓，现口径已统一）：
> 文档原方案是"倒数 LUT + 线性插值"；实现时曾改为**32 位整数除法**（精度更高、无需 LUT），
> 但 48÷24 的组合除法在 **49.152 MHz 下几乎必然过不了时序**，
> 故**改回"正规化 + 32 项 LUT + 线性插值"**（`g = (recip_mant × THRESH) >> k`），
> 实测相对误差 **0.021%**，并留 **0.39% 保守余量**（`g −= g>>7`）防包络反馈放大。
> 与 §六.5 正文一致。

## 附录：2026-10-16 代码/文档同步勘误

> 本附录记录**当前 RTL 与本文档不一致、或文档未覆盖**的内容。**与正文冲突时以本附录为准**；
> 后续整理文档时应把这些内容合并回正文。

### 1. 主输出链：`soft_limiter` 已改为 3 级流水线

**现状**：`rtl/global/soft_limiter.v` 内部已拆成 3 级流水（第 1 级 `env → nk/mant`、
第 2 级 `mant/nk → recip_final`、第 3 级 `recip_final → g_tgt → g` 并施加增益），
**音频 `l_d1/d2/d3`、`r_d1/d2/d3` 同步打拍**，增益与音频始终对齐。

**原因**：原单周期实现在 P&R 后出现 **566 个建立时间违例**、最差 slack **−25.907 ns**
（时钟周期 20.345 ns，数据延迟 46.208 ns），真板上主输出链路会出错。

**代价**：整体晚 **3 个采样 = 62.5 µs @48 kHz**。**做延迟预算时必须计入**。

**实测（2026-10-16）**：修复后 Setup Violated Endpoints 从 1092 降到 **210**，
最差 slack **−0.613 ns**（剩余全部在 `svf_voice` 的加法进位链，属预存在问题）。

### 2. 主增益：`master_volume` 的右移量是 11，不是 15

**现状**：`rtl/global/master_volume.v` 里 `norm_sat #(.SHIFT(11))`，
即 **+24 dB（×16）主增益**，不是正文写的 `>>> 15`。

**原因**：`chan_layer` 的符号性 bug 修好后（见第 3 条），信号不再"整流+饱和"，
单音满力度只剩约 14%（−17 dBFS），实板听不到声音。**修复前那个"响"是 bug 造成的虚假响度。**

**调节方法**：改这个 `SHIFT` 即可，**每减 1 = +6 dB**。
当前 11（×16）经实板确认**听感合适**；更轻可用 12（×8）/13（×4），更响用 10（×32）。

### 3. `chan_layer` 的符号性修复（影响主输出动态范围）

**问题**：原代码 `sat24((pl + {{(AWX+16-AWX){1'b0}}, RND}) >>> 15)` ——
**位拼接在 Verilog 里永远是无符号**，会让整个表达式变无符号，`>>>` 退化成逻辑右移（补 0），
**负数被转成巨大正数后饱和到 `0x7FFFFF`**。

**现象**：`ch_l` 恒为 `[0, 8388607]`、从不为负；主混音恒饱和；限幅器持续工作（2313380 拍）；
**任何依赖幅度的表现（力度 / 音量 / 音色）全部失真**。

**修法**：`RND` 改成 **48 位有符号**常量，中间量写成**显式 `signed` wire**：
```verilog
localparam signed [AWX+16-1:0] RND = 48'sd16384;
wire signed [AWX+16-1:0] pl_r = pl + RND;
wire signed [AW-1:0]     chl_nxt = sat24(pl_r >>> 15);
```

**同类问题**：`fx_reverb.v` 的 `fs_new` 也有，已一并修复（拆成 `fs_new_x` + 移位）。
**全库已复查，再无第三处。**

**⚠ 值得做成 lint 规则**：同一行内既有 `>>>` 又有 `{{` 且无 `$signed` —— 必然有隐患。

### 4. `wave_fetch` 的地址锁存时序修复（音色切换曾完全无效）

**问题**：地址锁存的使能是 `sample_en`（= `slot_vld`），而 `pf_timbre` **在同一个上升沿更新**，
导致 `an_r` 锁存到的是**上一个时隙**的音色槽。声部只活在一个时隙里，于是永远读到
"空闲时隙的音色"（槽 0）→ **音色切换听不出任何变化**。

**修法**（`rtl/voice/wave_fetch.v`）：
```verilog
reg start_d, start_dd;                       // sample_en 分别延后 1 / 2 拍
always @(...) begin start_d <= sample_en; start_dd <= start_d; end
end else if (start_d)  begin an_r <= addr_n_flat; ... end   // 锁存改用 start_d
if (start_dd) begin  ...扫描开始... end                      // 扫描改用 start_dd
```

### 5. `vca_gain` 目前不读音色表，写死 1.0

**现状**：`voice_fetch.v` 的 `apply_alloc` 写 **`V_VCAGAIN = 16'd32768`（1.0）**，
**并未读取音色参数表的 `vca_gain` 字段**（正文表格里列的 52428 / 45875 等值目前用不上）。

**原因**：`adsr_vca` 是 `g_vt = (velocity_gain × vca_gain) >>> 15`，
若两者同源会变成**力度平方**（`vel=1` 完全无声）。修复时把 `V_VCAGAIN` 定为 1.0。

**后续**：若要启用音色表的 `vca_gain`，必须先确认它与 `velocity_gain` 的职责划分。

## 附录：跨模块接口的"数据自带元信息"约定（2026-10-19）

> 这一节是给**新增模块**（例如可视化）看的。它记录了一次真实的踩坑教训和一个通用约定。

### 问题

本工程是**时分复用**结构：P 条泳道 × G 个时隙 = P×G 个声部。
下游模块（如 `chan_buf`）需要同时知道三件事：

```
① 音频数据是多少     (aud)
② 它属于哪个声部     (gate / ch)
③ 它什么时候有效     (vld)
```

**如果这三件事分别来自不同的信号，就极易错位。**

**真实案例**：`voice_fetch` 是**预取**结构 —— 在 `slot_vld` 那一拍就把 `pf_*`
更新成**下一个时隙**的声部。而 `voice_mono` 在同一个上升沿采样 `pf_*`，
拿到的是"更新前"的值（= 当前时隙的声部，音频正确）。
于是时隙中段 `pf_gate` / `pf_ch` 已经是**下一个**声部的了，
`chan_buf` 若直接使用它们，门控/通道号与音频就差了一个时隙
→ 门控为 0 → 写入 0 → **整链静音**。

**另一个案例**：`chan_buf` 原本在 `slot_vld`（时隙起点）采样，
但音频要经过「波表扫描 17 拍 + SVF 4 级流水」共约 23 拍才有效
→ 存进去的是上一个时隙的音频。

### 约定

**由数据的产生者把"元信息"和"数据"一起锁存输出，下游不要再从别处取。**

参考 `voice_mono` 的实现：

```verilog
// 在 dds_en（与音频同拍）把元信息和数据一起锁存
always @(posedge clk) if (dds_en) begin
    data_gate_r <= gate;      // ← 此刻的 gate 就属于这个声部
    data_ch_r   <= ch_in;
end
assign data_gate = data_gate_r;   // 与 voice_out 同源同拍
assign data_ch   = data_ch_r;
assign data_vld  = vca_en;        // 数据就绪脉冲（不是"节拍"）
```

**下游（`chan_buf`）只认这三个信号 + 音频本身，不再引用 `pf_*`。**

### 检查清单（写新模块时逐条核对）

```
□ 数据有效用专门的就绪脉冲，不要拿"节拍信号"凑
  （slot_vld 表示"时隙开始"，不表示"数据就绪"，两者可差 20+ 拍）
□ 元信息（通道号、门控、音色…）必须在与数据同一拍锁存
□ 串行资源的处理周期 < 调度间隔（否则会被下一个时隙打断）
□ 静态检查：每个时隙的"就绪"脉冲数量应当等于时隙数
  （本工程实测过：4 个时隙只出了 1 次就绪脉冲 → 音频变成噪音）
```

> 更完整的诊断过程见 `documents/时序违例处理.md` 第十节。

## 附录 C：PT8211 关键规格

> 此部分的内容全部来自PT8211手册

| 项 | 规格 |

| WS 上限 | **384 kHz** |
| VDD | 3 ~ 6 V（典型 5 V）；VIH 最小 **1.8 V** |
| MCLK | **不需要** |
| 引脚 | 1=BCK 2=WS 3=DIN 4=GND 5=VDD 6=LCH 7=NC 8=RCH |
