## 二、时钟

### 2.1 时钟源现状

| 源                     | 频率            | 引脚                      | 说明                 |
| --------------------- | ------------- | ----------------------- | ------------------ |
| 板载有源晶振（SOM）           | **50 MHz**    | **V22**                 | 直接可用，进 RPLL0/RPLL1 |
| MS5351 #1 / \#2（Dock） | 可编程           | **`USR_CLK_IN`（引脚待确认）** | 可精确合成音频时钟          |
| 片内 OSC                | 210/Param MHz | —                       | 精度差，不可用于音频         |

### 2.2 f_clk 选型

**主频：49.152 MHz**
**采用方案：由 MS5351 提供 12.288 MHz，FPGA 内部 PLL ×4 得到 49.152 MHz**

```
MS5351（25 MHz 晶振）
    │  N = 31 + 1429/3125 = 31.45728，输出整数分频 ÷64
    ↓
12.288 MHz（= 256 × f_s）
    │  进 FPGA 时钟引脚（USR_CLK_IN → 引脚待确认）
    ↓
FPGA PLL：IDIV=1, FBDIV=2, MDIV=64, ODIV0=32（CLKFB_SEL = INTERNAL，内部反馈）
    │  Fpfd = 12.288 MHz ✓（10~400）
    │  VCO  = 12.288 × 2 × 64 = 1572.864 MHz ✓（800~2000）
    ↓
f_clk = 1572.864 / 32 = 49.152 MHz ✓
```

**优势**
1. **抖动更低**：MS5351 的杂散/抖动经过 FPGA PLL 会被滤除一部分；比直接送 49.152 MHz 更干净

**分频结果核对**（`f_clk = 49.152 MHz`，`N_cyc = 49.152e6 / 48e3 = 1024`）

| 信号 | 频率 | 分频比 | 是否是 `2 的幂` | 占空比 |
|---|---|---|---|---|
| `f_s` / LRCK | 48 kHz | 1024 | ✓ | 50% |
| BCLK | 1.536 MHz（= 32 × f_s） | 32 | ✓ | 50%（每 16 拍翻转） |
| MIDI 位时钟 | 31250 Hz | 1572.864 ✗ → **1573** | — | 误差 **0.0086%** |
| I2C SCL | 400 kHz | 122.88 ✗ → 123（399.6 kHz）或 128（**384 kHz**） | — | — |

> `N_cyc` 是 2 的幂，**所有 I2S 相关分频都是整数且占空比 50%** —— 这是选 49.152 MHz 的最大好处。
> MIDI / I2C 的微小误差远小于各自容差（UART ±2%，I2C 无严格下限）。

**⚠️ 本方案依赖一项硬件事实（待确认）**

`USR_CLK_IN` 究竟接到哪个 FPGA 引脚？文字提取指向 BTB 的 **75 / 76 脚（→ N22 / N23）**，
**但需看图或用 KiCad 源确认**，并确认该引脚能否驱动 PLL。

### 2.3 时钟树

```
MS5351（25 MHz）×1
    │
    ↓ 12.288 MHz ──→ USR_CLK_IN ──→ FPGA 时钟引脚
    │
PLL：IDIV=1 / FBDIV=2 / MDIV=64（CLKFB_SEL = INTERNAL，内部反馈）
    └── CLKOUT0 → ODIV0=32  → 49.152 MHz ──→ f_clk（全逻辑）
    │
f_clk = 49.152 MHz（单一主时钟域）
    │
    ├── sample_enable   ÷1024  → 48 kHz，周期类节拍
    ├── bclk_enable     ÷32    → 1.536 MHz，I2S 移位（每 16 拍翻转）
    ├── lrck_enable     ÷1024  → 48 kHz，I2S 声道切换
    ├── midi_tick       ÷1573  → 31250 Hz（误差 0.0086%）
    └── i2c_tick        ÷128   → 384 kHz
    │
    └── 输出时钟生成（普通寄存器输出）
         ├── BCLK   1.536 MHz  → DAC（PT8211）
         └── LRCK   48 kHz     → DAC
```

### 2.4 clock enable 与真实时钟

**内部逻辑：全部使用 clock enable，仅有一个时钟域。**

- 所有寄存器都挂在 `f_clk` 上，用 `sample_enable` / `bclk_enable` 等使能控制节拍
- 好处：**内部无跨时钟域问题**，不需要同步器 / 异步 FIFO
- 代价：使能信号需要扇出到全芯片，需注意扇出平衡

**对外输出：普通寄存器输出即可。**

- BCLK = 1.536 MHz（÷32）、LRCK = 48 kHz（÷1024）均为整周期分频，普通寄存器输出即得 50% 占空比
- 可选加 IOB 约束，让输出寄存器进 IOB
- PLL 的 CLKOUT 由工具自动接入全局时钟网络（GCLK）

**仍需处理的三处时钟域边界：**

| 边界 | 处理 |
|---|---|
| MIDI 输入（外部异步串行） | 两级触发器同步，必要时加去毛刺 |
| I2S 输出时钟 | 与主逻辑同源，无需 FIFO |
| 复位（异步输入） | 同步释放（见 §三） |

### 2.5 外部时钟源 MS5351（待确认）

板上 2 颗 `MS5351M` 是 Si5351 的国产替代，**分数分频的分母是可配置的 20 位整数（最大 1048575）**，
因此能精确合成音频标准时钟（与 FPGA 内部 PLL 只能提供 2 的幂不同）。

**合成 12.288 MHz 的参数（从 25 MHz 晶振，误差 0 ppm）**

```
VCO  = 12.288 × 64 = 786.432 MHz     ✓（MS5351 VCO 范围约 600~900 MHz）
N    = 786.432 / 25 = 31.45728 = 31 + 1429/3125
       → a = 31（需 15~90）✓，b = 1429，c = 3125（需 ≤ 1048575）✓
输出分频 = 64（整数、偶数 → 占空比 50%）
结果 = 25 × (31 + 1429/3125) / 64 = 12.288 MHz   ✓ 误差 0
```

（也可让它直接输出 49.152 MHz：同一 VCO 786.432，输出分频改 ÷16）

**使用注意**

- **扩频（Spread Spectrum）必须关闭**，否则会毁掉音频时钟
- 用「PLL 分数 + 输出整数分频」的配置，抖动比「输出也分数」好
- MS5351 输出为 3.3 V CMOS 方波；需确认与 FPGA 时钟引脚的电平兼容

**⚠️ 待确认（需查图 / KiCad 源）**

1. **N22 能否作 PLL 的 CLKIN**（该脚为 PLL 反馈脚，见 §1.2）
2. MS5351 上电默认输出什么频率（是否有 EEPROM 自动加载）
3. 两颗 MS5351 的分工（哪颗给 `USR_CLK_IN`）

> 参考：`vdalex/tangmega-138k-fpga-projects` 是同板卡的第三方项目，含 **PT8211 DAC 发射器** 与 PLL 配置，可对照。

## 三、复位

### 3.1 方案

采用 **异步复位、同步释放**：

```
rst_n (异步)  ──→ [触发器1] ──→ [触发器2] ──→ rst_sync_n
                   ↑          ↑
                 f_clk      f_clk
```

- **异步断言**：复位到来立即生效，不依赖时钟（上电、外部复位都能立刻起作用）
- **同步释放**：释放沿与 `f_clk` 对齐，避免亚稳态
- 复位信号应走**专用复位网络**（Gowin 的全局复位资源），不要用普通布线

### 3.2 复位情况表

| 模块 / 资源                        | 复位后的状态                                            | 说明                   |
| ------------------------------ | ------------------------------------------------- | -------------------- |
| **声部状态表**                      | 全部置 IDLE；`gate` = 0；运行状态字段归零                      | 不得残留上一轮的相位 / 包络      |
| **通道状态表**                      | 运行参数归零或默认；配置项（`max_voices`、`default_timbre`）载入默认值 |                      |
| **音色参数表 / 波表 / 音色映射表 / 鼓组映射表** | **不受复位影响**                                        | BRAM 初值已固化；复位不清 BRAM |
| **效果参数表**                      | 载入默认值                                             | 由上位机 / 混音器后续修改       |
| **主输出参数表**                     | 载入默认值                                             | 同上                   |
| **效果器延迟线**                     | 清零                                                | 避免残留旧数据产生噪声          |
| **MIDI 消息解析**                  | 状态机回 IDLE；运行状态缓存清零                                | 复位后必须等待新的状态字节        |
| **声部时序器**                      | 计数器归零                                             | 与采样边界重新对齐            |
| **声部取数器**                      | 预取寄存器置无效                                          |                      |
| **声部分配 / 释放器**                 | 无待处理事件                                            |                      |
| **I2S 发送**                     | 停止移位输出                                            |                      |
| **全局 `ready`**                 | 复位释放后置低，**各表载入完成后置高**                             | 门控 I2S 输出，避免载入期间发声   |

**关键点：**

- **BRAM 初值不受复位影响** —— 只读表（音色 / 波表 / 映射表）无需复位逻辑，靠综合时写入的初值
- **延迟线必须清零** —— 否则上电会有残留噪声
- **`ready` 门控** —— 保证「表载入完成前不发声」（对应技术文档的启动时序要求）

### 4.2 引脚连接（已验证）

| **PA_EN** | **H17** | `IOB91A` | 5 | J3-23 |

> ⚠️ **BCLK 在 bank5，LRCK/DIN 在 bank4** —— **需确认两个 bank 的 IO 电压一致**（Dock 给 bank2/4/5 供电）。
> ⚠️ F24/G24 未出现在跟踪长度表（可能该表未覆盖全部 I/O），已用 UG986 引脚表确认其存在与 bank。

### 4.3 数据格式【关键：PT8211 不是标准 I2S】

**PT8211 使用 LSBJ（Least Significant Bit Justified）格式，又称「日本格式」。**

| 特性 | PT8211（LSBJ） | 标准 I2S |
|---|---|---|
| 位序 | **MSB 先出**，二进制补码 | MSB 先出 |
| MSB 位置 | **紧贴 WS 跳变** | 跳变后**延后 1 个 BCK** |
| WS 极性 | **WS 高 = 左声道**，低 = 右声道 | WS **低** = 左声道 |
| 位宽 | **16 bit**（多出的位被截断） | 视器件 |

**⇒ 若直接套用标准 I2S，会出现：左右声道颠倒**（WS 极性相反），且位对齐差 1 拍。

**帧结构**

```
WS:    ┌── 左声道 ──┐┌── 右声道 ──┐
       │  16 × BCK  ││  16 × BCK  │
DIN:   MSB ... LSB   MSB ... LSB
       ↑                ↑
       紧贴 WS 跳变      紧贴 WS 跳变
```

- 每声道 **16 个 BCK**，一帧共 **32 个 BCK** → `BCLK = 32 × 48 kHz = 1.536 MHz` ✓
- 数据在 **BCK 下降沿**更新，**上升沿**被 DAC 采样
- **PT8211 不需要 MCLK**（内部自有时钟）

**PT8211 电气约束（已核对）**

| 项 | 限制 | 我们 |
|---|---|---|
| BCK 频率 | ≤ 18.4（可到 20）MHz | 1.536 MHz ✓ |
| WS 频率 | ≤ 384 kHz | 48 kHz ✓ |
| 输入高电平 VIH | ≥ 1.8 V（VDD=5V 时） | FPGA 3.3 V ✓ |
| 供电 | 板载 +5V（`5V0A`） | ✓ |
| 内部结构 | 8 倍过采样 R-2R | — |
| 群延迟 | 手册未给 | 保守估 ≤ 0.2 ms，待实测 |

### 4.5 实现要点

**移位与对齐**
- MSB 先出，**紧贴 WS 跳变**（不是 I2S 的延后 1 拍）
- 每声道恰好移 16 位
- **WS 高 = 左声道**

**时钟沿**
- BCLK / LRCK 用普通寄存器输出（整周期分频，50% 占空比），可选加 IOB 约束
- 数据在 BCLK **下降沿**更新，DAC 在上升沿采样

**位深匹配**
- 我们内部可保持 24 bit 精度，**送 DAC 前截断/舍入到 16 bit**（建议带抖动 dither，否则小信号失真）
- 若误按 24 bit 对齐发送，数据会整体错位 → 音量异常或噪声

**验证手段**
- 先用单频正弦（如 1 kHz）测试，示波器同时看 BCLK / LRCK / DIN
- **重点核对两个点**：① MSB 是否紧贴 WS 跳变；② WS 高电平对应左声道

> **需要的资料**：`PT8211` 数据手册**不在** `material/` 目录内，建议下载 PTC 官方 V1.5 版
> （princeton.com.tw → Multi-Media Audio → DAC → PT8211），以核对波形图。
> 另可参考同板卡项目 `vdalex/tangmega-138k-fpga-projects` 的 PT8211 发射器实现。

## 五、数据格式（定点数）

**统一约定**（各模块对接的基础）：

| 量 | 格式 | 位宽 | 说明 |
|---|---|---|---|
| 音频样本 | Q1.23 | 24 bit 有符号 | 范围 −1 ~ (1 − 2⁻²³) |
| 系数（增益、发送量、滤波器系数等） | Q1.15 | 16 bit 有符号 | 范围 −1 ~ (1 − 2⁻¹⁵) |
| 单个乘积 | Q2.38 | 40 bit 容器 | Q1.23 × Q1.15 |
| 多路累加 | Q6.38 | 48 bit 容器 | 用 DSP 的 48-bit 累加器 |

> `Qm.n` 的总位数 = `m + n`（`m` 含符号位），故 Q1.23 = 24 bit、Q1.15 = 16 bit。

**归一化规则**

Q1.15 乘法之后必须**算术右移 15 位**才能回到 Q1.23：

```
Q1.23 × Q1.15 = Q2.38  ──(>>>15)──▶  Q1.23
```

若不右移，等于把结果乘了 2¹⁵（增益错约 90 dB）。

## 六、溢出与饱和
> 各个模块对溢出的处理可能各不相同，此处总结复用部分与区别的部分
### 6.1 全模块复用：通用「归一化 + 饱和」单元

用于把 48-bit 累加结果安全压回 24-bit。

输入 `acc`（48-bit 有符号，Q6.38 量级）→ 输出 `y`（24-bit Q1.23，已饱和）：

1. **四舍五入（可选）**：`acc_rnd = acc + 2^14`（在 48-bit 容器里加，不要先截断）
2. **归一化**：`sh = acc_rnd >>> 15`，得 29-bit 有效（Q6.23）
3. **取低 29 位**：`v = sh[28:0]`
4. **溢出判断**：`ovf = (v[28:24] != {5{v[23]}})`
5. **输出**：`ovf = 0` 时 `y = v[23:0]`；`ovf = 1` 时按 `v[28]` 判正负，正溢出给 `0x7FFFFF`、负溢出给 `0x800000`

> 判据含义：24-bit 有符号要装得下，要求第 23 位以上全是符号位，故比较 `v[28:24]` 是否等于 `v[23]` 的 5 位复制。

### 6.2 各位置的处理

- **相位累加器**：靠自然回绕（2³² 模）实现周期，**用取模截断，禁止饱和**（饱和会破坏波形）
- **包络值**：无符号，饱和到 `[0, 65535]`（负包络无意义）
- **VCA 乘法后**：饱和到 24 bit
- **通道总线累加 / 主混音求和**：饱和
- **滤波器内部状态**：先对系数 `f` **限幅**（保证稳定），再对状态幅值钳位兜底
  （SVF 是递归结构，简单饱和不足以阻止发散）

## 七、表读写

> 本项目多张表同时被**事件路径**（消息到达时写）与**逐采样路径**（每采样读）访问。
> 本节汇总各表的**读写冲突**与**处理方式**。

### 7.1 通道状态表

**问题**：通道状态表编辑器（事件路径）写，而声部取数器 / 通道增益 / 声道像 / 效果发送（逐采样路径）读 —— 直接写会让读方读到「半更新」的行。

**处理**：**待写缓冲 + 采样边界提交**

- 写入事件极稀疏（最快 MIDI 一帧 960 µs ≈ 46 个采样周期才一条），只需极浅 FIFO（深度 2~4）存「通道号 + 字段号 + 值」，约 20 bit × 几条
- 每采样在 `sample_enable` 边界统一提交 → 读方在一个采样周期内看到的值恒定
- 提交延迟 ≤ 1 个采样周期 = 20.8 µs，远低于人耳可辨阈值
- 对比：整表影子寄存器需多约 3200 FF（占设备 FF 4.6%）偏大；双端口 RAM 端口不够

### 7.2 声部状态表

**问题**：分配 / 释放器写「分配类字段」（`note`/`velocity`/`gate`/`timbre_slot`/`channel`/`drum_mode`/`velocity_gain`…），取数器读写「运行状态字段」（`phase_acc`/`env_value`/`filter_ic*`/`lfo_phase`…），同块存储上会冲突。

**处理**：**字段分区** —— 声部表按性质分 5 组（DSP 运行状态 / 演奏控制 / 音色引用 / 派生缓存 / 管理调度），物理上分开存储；分配器只碰分配类，取数器只碰运行状态。
- 分配器**不直接改写**计算路径正在使用的字段，用「已分配 / 已释放」标记通知时序器

### 7.3 效果参数表 / 主输出参数表

**问题**：混音器可运行时改参数（B 档），效果器 / 主输出处理逐采样读 —— 改参数瞬间可能读到半更新值。

**处理**：**双缓冲**。字段少（效果 13 × 16 bit ≈ 210 bit、主输出 4 × 16 bit），多花约 420 FF，比做 FIFO 简单。

### 7.4 只读表（音色参数表 / 波表 / 映射表）

**问题**：A 档只读，运行时不写 —— 无写冲突，也不存在「读到半更新」；但**多泳道并发读**会带来端口数问题（见 7.5）。

**处理**：无需读写仲裁逻辑；并发读用 §7.5 的办法解决。

### 7.5 BRAM 端口：多泳道并发读

**问题**：P 条泳道同一拍要读 P 行状态。若用单块 RAM 需 P 个读端口，扩展时端口数爆炸。

**处理**：

- **声部状态表按泳道分 bank**：每泳道一个单口 bank（存 voice `l, l+P, l+2P…`），端口数恒为 P、与 `G` 无关；扩声部（加 `G`）只让 bank 变深
- **音色参数表 / 通道表：参数预取**：时隙 g 计算时**同时预取 g+1** 所需参数，提前一拍取到寄存器 → 表可保持单口，且顺带隐藏 BRAM 读延迟

```
时隙 g ：[取数器预取 g+1 的参数] ‖ [计算单元处理 g 的参数]
              ↑                            ↑
       发起 BRAM 读                  用上一拍预取好的参数
```
