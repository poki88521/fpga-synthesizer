## 二、调度层

### 事件类

| 模块 | 输入（来源） | 输出（去向） | 涉及的表 | 职责 | 复位后状态 |
|---|---|---|---|---|---|
| **MIDI 消息解析** | MIDI 字节流<br>（乐器端口 ×3、混音器端口） | 通道消息 → 通道状态表编辑器<br>Note On/Off → 声部分配器 | — | 解析字节流、区分消息类型并分发；**丢弃乐器端口的混音类 CC** | 状态机回 IDLE；运行状态缓存清零 |
| **通道状态表编辑器** | 通道消息<br>（CC、Program Change、Bank Select、Pitch Bend、RPN） | 写通道状态表 | 写：通道状态表 | 维护通道状态表 | 待写缓冲清空 |
| **音色映射** | `(bank_msb, program)`<br>（来自通道状态表） | `timbre_slot` → 声部分配器 | 读：音色映射表 | 把 MIDI 音色号映射为内部音色槽 | 无状态（查表） |
| **鼓组映射** | `note`<br>（来自 Note On） | `timbre_slot` → 声部分配器 | 读：音色参数表、鼓组映射表 | 鼓通道（`bank MSB = 120`）内，把音符号映射为某件鼓的音色槽 | 无状态（查表） |
| **声部分配 / 释放器** | Note On/Off<br>`timbre_slot`（来自音色/鼓组映射） | 写声部表<br>「已分配 / 已释放」标记 → 声部时序器 | 读：通道状态表（`note_count`、`max_voices`）<br>写：声部表（分配类字段） | 声部分配、抢断、释放；<br>**鼓声部忽略 Note Off**；<br>**互斥组内新音起时静掉旧音** | 无待处理事件；分配状态清零 |

### 周期类

| 模块 | 输入（来源） | 输出（去向） | 涉及的表 | 职责 | 复位后状态 |
|---|---|---|---|---|---|
| **声部时序器** | 分配器标记 | 声部索引 `(组, 泳道)` → 声部取数器 | — | 产生声部索引与轮转节拍（不含取数逻辑） | 计数器归零，与采样边界重新对齐 |
| **声部取数器** | 声部索引 | 声部上下文 → 单声部处理层 | 读：声部表（运行状态）、通道状态表、音色参数表<br>写：声部表（运行状态） | 按索引并行取出声部上下文；预取下一时隙参数以隐藏读延迟 | 预取寄存器置无效 |

## 三、单声部处理层

**每个声部一份实例**（`P` 条泳道 × `G` 个串行组）。声部上下文由声部取数器提供，各模块**自身不直接读表**（表读取集中在取数器）。

| 模块 | 输入 | 输出（去向） | 职责 | 复位后状态 |
|---|---|---|---|---|
| **DDS + 波表** | 声部上下文：`phase_acc`、`phase_inc`、`note`、`timbre_slot`<br>调制：`bend_ratio`、`vibrato_depth`（通道表）、LFO 颤音、ADSR 的 FM 包络调制 | 波形样本 → SVF 滤波器 | 生成基础波形 | `phase_acc` 归零 |
| **ADSR 包络** | 声部上下文：`env_value`、`env_state`、`gate`、`pending_release`<br>通道表：`attack_mod`、`release_mod`、`sustain_pedal` | 包络值 → VCA<br>（另调制 SVF、DDS） | 产生包络，控制音量与调制 | `env_state` → IDLE；`env_value` = 0 |
| **SVF 滤波器** | 声部上下文：`filter_ic1`、`filter_ic2`<br>通道表：`filter_cutoff_mod`、`resonance_mod`<br>调制：ADSR 滤波包络、LFO 滤波调制 | 滤波后样本 → VCA | 滤波（平滑化） | `filter_ic1` / `filter_ic2` 归零 |
| **LFO** | 声部上下文：`lfo_phase`<br>通道表：`mod_wheel`、`vibrato_depth` | 调制值 → DDS（颤音）、SVF（滤波调制） | 产生低频调制信号 | `lfo_phase` 归零 |
| **VCA** | 滤波后样本<br>包络值（来自 ADSR）<br>`velocity_gain`、`expression` | 声部音频 → 通道总线累加 | 施加包络与力度（= 包络 × 力度） | 无状态（纯运算） |

> **注意**：`volume` 与声像**不在本层**，它们在通道处理层施加。

## 六、接口与边界

| 位置 | 名称 | 说明 |
|---|---|---|
| 板外 → FPGA | **乐器端口 ×3** | 每个端口 I2C / MIDI 二选一；进 FPGA 前统一转为 MIDI |
| 板外 → FPGA | **混音器端口** | **独立接口**；全部消息进混音/控制路径 |
| FPGA → 板外 | **I2S** | BCLK / LRCK / DATA → DAC |
| 板外 | **DAC → 功率放大 → 输出设备** | 模拟链路 |

**输入侧规则**
- 乐器端口的**混音类 CC（7 / 10 / 91 / 93 / 94）直接丢弃**
- 混音器端口提供：`volume`、`pan`、`send_reverb`、`send_chorus`、`send_delay`、效果参数、主音量

## 七、表清单速查

| 表 | 规模 | 可变性 | 读它的模块 | 写它的模块 |
|---|---|---|---|---|
| **通道状态表** | 16 项 | A / B | 通道状态表编辑器（写）、取数器、通道增益、通道声像、效果发送、分配器 | 通道状态表编辑器 |

## 八、开发时需注意的点

**时钟与节拍**
- `f_clk` = **49.152 MHz**（由板载 MS5351 合成 12.288 MHz 送入，FPGA PLL ×4；见 `硬件实现.md` §2.2）
- `f_s` = 48 kHz；`N_cyc` = **1024**（为 2 的幂，各类分频均为整数）
- 周期类模块必须在 `N_cyc` 拍内跑完全部声部
- 内部统一使用 **clock enable**，不真实分频出多个内部时钟（见 `硬件实现.md` §2.4）

**I2S 输出**
- 位宽 **16 bit**、格式 **LSBJ（日本格式）**，非标准 I2S（板载 DAC 为 PT8211）
- **WS 高 = 左声道**（与标准 I2S 相反）；MSB **紧贴 WS 跳变**
- **BCLK = 1.536 MHz**（每声道 16 个 BCK）
- 内部保持 24 bit，**送 DAC 前截断到 16 bit**（建议加 dither）
- 详见 `硬件实现.md` §四

**复位**
- **异步复位、同步释放**（见 `硬件实现.md` §二）
- 各模块的复位后状态见上表「复位后状态」列
- 只读表（音色 / 波表 / 映射表）由 BRAM 初值提供，**不受复位影响**

**声部扩展**
- `N = P × G`；扩展只改 `G`，泳道逻辑不变
- 声部编号 → (组, 泳道) 映射**固定**，保证确定性无抖动延迟

**事件类与周期类的隔离**
- 分配器**不得**直接改写计算路径正在使用的字段，用「已分配 / 已释放」标记传递

**读表并发**
- 声部表：按泳道分 bank
- 音色表 / 通道表：由取数器**参数预取**，隐藏 BRAM 读延迟

## 十、硬件实现细节

> 本节汇总**计算模块**（单声部 / 通道 / 全局三层）在 RTL 实现时需处理的具体问题。
> 标记：无标记 = 已确定；【建议】= 工程判断，可推翻；【待确认】= 需先定才能动手。

### 单声部处理层

#### DDS + 波表【最大风险点】

**波表并发读问题**

`P = 16` 条泳道并行，每条每采样要查一次波表 → **需要 16 路并发读**。

| 方案          | 代价                                        | 评价                        |
| ----------- | ----------------------------------------- | ------------------------- |
| 复制 P 份波表    | 32 Kbit × 16 = 512 Kbit/波形；8 种波形 = 4 Mbit | **接近设备 6.12 Mbit 极限，不可行** |
| LUTRAM 多端口  | 32 Kbit/波形，16 端口约 8000 LUT                | 只够 1~2 种波形                |
| **时隙内串行查表** | 时隙延长 16 拍                                 | **推荐**                    |

**【建议】把波表读改为「时隙内串行」**

```
时隙开始
 ├─ 前 16 拍：用一个单口 BRAM，串行读出 16 条泳道各自的样本 → 存入 16 个寄存器
 └─ 之后：16 条泳道并行计算
```

时间预算只用掉一小部分，**加 16 拍后仍很充裕**，而 BRAM 只需 1 份。
⇒ **波表用单口 BRAM，泳道数不影响波表资源。**

**相位累加与插值**
- `phase_acc[31:0]` 取高位作查表地址（如高 11 位查 2048 点表）
- 低位用于线性插值 → 需要 2 次查表 + 1 次乘法
- 【待确认】是否真需要插值？不插值会有量化噪声（可听），建议保留

**FM**
- `fm_ratio_c` / `fm_ratio_m` 是 8 bit 比例值 → 需要「比例 → 相位增量」的换算（查表或乘法）
- 结构是「调制器输出加到载波相位」→ 注意相位累加的位宽对齐

**`base_pitch`（鼓）**
- 鼓声部的音高不来自 `note`，而来自 `base_pitch`
- 【待确认】它直接作为 `phase_inc`，还是要做音符号 → 频率的换算？换算方式未定

**频率 → 相位增量换算**
- `phase_inc = f_note / f_s × 2³²` → 需要**音符号 → 相位增量**的查表
- 128 音符号 × 32 bit = 4 Kbit（很小）
- 【待确认】是否支持弯音 / 颤音后的实时微调（那就要乘法而非纯查表）

#### SVF 滤波器【关键路径风险】

**递归结构**

Chamberlin SVF：

```
ic1 = ic1 + f × ic2
ic2 = ic2 − f × ic1 − q × ic2
```

- **递归路径上有乘法 + 减法** → 关键路径长
- `f_clk = 49.152 MHz` → 时钟周期 **20.345 ns**，比 98.304 MHz 宽松一倍，余量较充足

【建议】若时序不满足，考虑：
- 改用 **TPT / ZDF 拓扑**（数值更稳，递归路径可能更短）
- 在非递归路径插流水寄存器
- 或降低 `f_clk`

**系数计算**
- `filter_cutoff`（基准）+ `filter_cutoff_mod`（CC 调制）+ ADSR 的 `filter_env_depth` + LFO 的 `filter_lfo_depth` → 合成实际截止频率 → **再换算成系数 `f`**
- 换算涉及指数 / sin → 必须**查表**（表规模待定）
- 【待确认】系数表放在哪一层（音色表内预存？还是全局查表？）

**稳定性**
- `f` 系数有稳定范围（Chamberlin 形式约 `f < 2`），**必须限幅**，否则滤波器发散
- 高 Q 时更容易不稳定

**内部位宽**
- 状态变量 `filter_ic1/2` 是 24 bit，但中间运算需更宽（建议 32 bit+），避免累积误差

#### ADSR 包络

**状态机**
- IDLE / ATTACK / DECAY / SUSTAIN / RELEASE / PENDING_RELEASE
- 【待确认】`PENDING_RELEASE` 与 `pending_release` 标志如何配合

**非线性曲线**
- `adsr_curve` = 线性 / 指数
- 指数实现：查表，或用「移位 + 减法」近似（`env -= env >> k`）——后者资源极省，【建议】优先考虑

**时间参数**
- `adsr_attack` 等是 16 bit「时间」→ 需换算成**每采样的增量**（或计数阈值）
- 换算涉及除法 / 指数 → 查表或分段

**鼓声部**
- 鼓「固定时长、忽略 Note Off」→ 通常 Sustain = 0，衰减到 0 自行结束
- `excl_group` 触发「静掉旧音」→ 【待确认】立即切断还是快速淡出（立即切断有 click）

#### LFO
- 相位累加 + 波形查表（`lfo_wave`：正弦 / 三角 / 方波）
- 【建议】正弦查表（可复用 DDS 的表或单独小表）；三角 / 方波用逻辑直接生成
- `lfo_delay` / `lfo_fade`：相对**该声部按下时刻**计时 → 需每个声部自己的计数器
- 速率参数 → 相位增量换算（同 DDS）

#### VCA
- `样本 × 包络 × 力度` → 两次乘法
- **饱和**
- 延迟对齐（包络路径与音频路径）

### 通道处理层

#### 通道总线累加【需仔细设计】

**问题**：P 条泳道并行输出，**同一拍可能有多个声部属于同一通道** → 无法直接累加到同一寄存器（写冲突）。

| 方案 | 说明 |
|---|---|
| **每泳道一组累加器** | P × 16 个累加器，最后汇总。资源 ≈ 8 Kbit，可接受 |
| 流水累加 | 利用时间余量串行累加 |

【建议】方案 1：每条泳道 16 个通道累加器，时隙结束时把 P 组汇总（16 个加法器树）。

**累加器清零**
- 每个采样周期开始时要清零
- 【待确认】时隙边界与采样边界的关系（时隙 0 开始前清零？）

#### 通道增益
- `volume × expression` → 每采样 16 次
- 【建议】时分复用：`N_cyc / 16` 拍每通道，完全可以串行做
- 两个增益都是 7 bit → 可先查表合成一个 16 bit 增益（省一次乘法）

#### 通道声像
- 用 `pan_gL` / `pan_gR`（预计算的 16 bit 增益）→ 两次乘法
- 时分复用同上

#### 效果发送
- 从**通道声像输出**抽出
- 3 条发送量 × 16 通道 → 需要 3×16 次乘加

### 全局处理层

#### 效果器【资源大头】

**BRAM 需求估算**

| 效果 | 延迟线规模（单声道 24 bit） | BRAM |
|---|---|---|
| 延迟 | 1 秒 = 48000 样本 × 24 bit | 1.15 Mbit |
| 混响 | 梳状 + 全通，总延迟 0.5~2 秒 | 0.6~2.3 Mbit |
| 合唱 | 短延迟（几十 ms） | 数十 Kbit |
| **合计（立体声）** | | **可能 3~6 Mbit** |

设备 B-SRAM 总量 **6.12 Mbit** → **可能吃掉一半以上**，必须专门规划。

【建议】
- 先定各效果的最大延迟时间
- 评估是否值得做立体声效果（单声道可省一半）
- 延迟线位宽可考虑用 16 bit（而非 24 bit），省 1/3

**DSP 占用**
- 混响 / 合唱 / 延迟各有多个乘法（梳状滤波器各一路）
- 【待确认】`D_fx` 未估，需在方案确定后核算

**参数多缓冲**
- 混音器运行时可改参数 → 需双缓冲避免读到半更新状态
- 【建议】字段少（13 × 16 bit ≈ 210 bit），直接双缓冲（多花 420 FF）

#### 主混音求和
- 16 条通道 + 3 条效果返回 → 加法树
- 32 bit 累加 + 饱和
- 【待确认】效果返回是「按通道」还是「整体」返回？

#### 主输出处理

**限幅器**
- 需检测峰值 + 增益衰减 + 释放恢复
- 涉及**除法或查表**（算衰减系数）
- 【待确认】实现方式（硬限幅 / 软限幅 / 前馈压缩）

**抖动（dither）**
- 需要**伪随机数发生器**（LFSR）
- 【建议】用一个 LFSR 取低位作为抖动，省资源

**主音量**
- 一次乘法

#### I2S 发送【有特殊格式要求】

**时钟生成**
- BCLK / LRCK 由 `f_clk = 49.152 MHz` 整数分频，**必须用专用时钟资源驱动**
- `BCLK = 1.536 MHz`（÷32，每 16 拍翻转 → 50% 占空比）
- `LRCK = 48 kHz`（÷1024）
- **PT8211 不需要 MCLK**

**数据格式【关键：不是标准 I2S】**

板载 DAC 为 **PT8211**，使用 **LSBJ（日本格式）**：

| 项 | PT8211 | 标准 I2S |
|---|---|---|
| 位宽 | **16 bit** | 视器件 |
| MSB 位置 | **紧贴 WS 跳变** | 跳变后延后 1 个 BCK |
| WS 极性 | **高 = 左声道** | 低 = 左声道 |
| 每声道 BCK 数 | **16** | 通常 32 |

- 数据在 **BCK 下降沿**更新，DAC 在**上升沿**采样
- 内部保持 24 bit，**送 DAC 前截断到 16 bit**（建议加 dither，否则小信号失真）
- 【待确认】MSB / WS 的确切波形，需对照 PT8211 数据手册（见 §九 待定项 4）

**跨时钟域**
- I2S 与主逻辑同源（主模式），无需异步 FIFO
