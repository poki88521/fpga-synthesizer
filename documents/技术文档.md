## 一、简介
- 基于 FPGA 的实时多音色合成电子乐器引擎
- 此文档着重介绍此项目的技术实现与协议，具体硬件参数与实现请参考[硬件实现](documents/硬件实现)，有关MIDI的内容请参考[MIDI协议](documents/MIDI协议)
- 使用 Mega 138K Pro 开发，此开发板的文档见material

**功能**

> 按**实现层**组织；每项标注状态：**已实现** / **已设计待 RTL** / **暂缓**（暂缓项的字段与模块见 [[#附录 B：暂缓功能]]）。

**一、演奏输入与消息**

- **MIDI 消息解析**（已设计待 RTL）：4 路 UART（乐器端口 ×3 + 混音器端口 ×1，31250 baud）；支持运行状态（Running Status）；实时字节（`F8`–`FE`）可插入任意位置；SysEx 带超时 / 长度上限保护。
- **输入统一为 MIDI**（已实现）：乐器端口的 I2C / MIDI 二选一，进 FPGA 前统一转为 MIDI；**乐器端口的混音类 CC（7 / 10 / 91 / 93 / 94）丢弃**，混音调节只认混音器端口。
- **多维交互**：本项目以 **MIDI / I2C 乐器输入**承载演奏维度（力度、弯音、表情、调制轮）；赛题的"自研传感器（触摸 / 光电 / 压力 / 手势）"**未设计**。

**二、发声（单声部处理层，每声部一份实例）**

- **DDS + 波表**（已设计待 RTL）：单周期波表查表，**8 张 × 2048 点 × 16 bit = 256 Kbit（16 块 BSRAM，16 Kbit 模式）**；`phase_inc` 由基准音高 + 弯音比率换算；按 `P = 8` 泳道 × `G = 4` 时隙分时复用。
- **ADSR 包络**（已设计待 RTL）：IDLE / ATTACK / DECAY / SUSTAIN / PENDING_RELEASE / RELEASE 状态机；支持通道级 `attack_mod` / `release_mod`、延音与持音踏板。
- **SVF 滤波器**（已设计待 RTL）：Chamberlin 状态变量滤波；通道级 `filter_cutoff_mod` / `resonance_mod` 调制。
- **VCA**（已设计待 RTL）：包络 × 力度；**音量与声像不在本层**（在通道层施加）。

**三、通道处理层（16 通道）**（**已实现，有 `tb_chan_layer` / `tb_mix_chain` 验证**，详见 [[#2. 多通道层]]）

- **通道总线累加**：32 个声部按 `(slot, lane)` 并入各自通道（32 位累加器，留足 32 × 2²³ 余量）。
- **通道增益**：`volume` × `expression` 合并为单个 Q1.15 系数（控制率计算，2 级流水 / 32 拍刷完 16 通道）。
- **通道声像**：等功率律 `pan_gL` / `pan_gR`（16 位 Q1.15），与增益合并成 `gL` / `gR`，采样率路径只做 24 × 16 乘法。
- **效果发送**：按 `send_reverb` / `send_chorus` / `send_delay`（7 bit → Q1.15）抽出三路湿信号。
- **串行输出**：16 条通道在采样周期内串行流出（`ch_vld` / `ch_addr` / `ch_l` / `ch_r`），并与效果发送共用同一条通道流。

**四、全局处理层（单实例）**（**已实现，有 7 个 TB 验证**，详见 [[#3. 主通道层]]）

- **效果器运算**（全部在 FPGA 内，挂**并行湿路**，干路不串入）：
  - **混响**：Freeverb 结构——8 条并联低通反馈梳状（1215 / 1293 / 1390 / 1476 / 1548 / 1623 / 1695 / 1760）+ 4 条串联全通（605 / 480 / 371 / 245），右声道 +25 做立体声展宽；参数 `size` / `decay` / `damping` / `pre_delay` / `return`。
  - **合唱**：LFO 正弦调制延迟 + 线性插值，左右反相 LFO；参数 `rate` / `depth` / `mix` / `return`。
  - **延迟**：环形缓冲 + 反馈 + 干湿混合；参数 `time` / `feedback` / `mix` / `return`。
- **主混音求和**：16 条通道先累加（48 位，**不提前饱和**），再与三路效果返回相加，最后统一饱和回 24 位。
- **主输出处理**：主音量（14 bit → Q1.15，带 ±64/采样斜坡防咔哒）→ **软限幅**（包络检测 + 阈值倒数，Attack 立即 / Release 一阶）→ 隔直（可选，`a = 0.995`）→ 抖动 + 24 → 16 bit 截断。
- **I2S 发送**：16 bit / **LSBJ**，BCLK = `f_clk / 32`（1.536 MHz @49.152 M）；**WS 高 = 左声道**。

**五、调度与状态表**（已设计待 RTL）

- 共 **7 张表**：通道状态表（16 项）、声部状态表（32 项）、音色参数表、效果参数表、主输出参数表、音色映射表、波表；按可变性分 **A**（只读）/ **B**（事件驱动写）/ **C**（逐采样读写）三档。
- **读写冲突处理**：通道表用「待写缓冲 + 采样边界提交」；效果 / 主输出参数表用双缓冲。

**六、测试与合规**

- **测试模式（TEST_MODE，现场验证必需）**：一键关闭全部效果、关闭限幅动态增益、输出 **32 个对数均匀分布的频率**（200 Hz → 8 kHz）、声像左右交替 → 频谱仪数谱峰即可佐证复音数（详见 [[#七、合规性与验收]]）。
- **纯硬件实时合成**：逐音、逐样本实时生成；波表仅单周期波形；**无任何预录 PCM / 整段回放**；AE350 硬核不参与逐样本音频运算。

**规格小结**

| 指标 | 值 | 备注 |
|---|---|---|
| 复音数 | **32**（`P = 8` 泳道 × `G = 4` 时隙） | 赛题基础 ≥4、拓展 ≥32 |
| 通道数 | **16** | 对应 MIDI 16 通道 |
| 采样率 | **48.000 kHz**（49.152 MHz / 1024） | **唯一正式口径**；50 MHz 直连仅作 bring-up 验证用（48.828 kHz） |
| 输出格式 | I2S **16 bit / LSBJ** | 板载 DAC 为 PT8211 |
| 主时钟 | **49.152 MHz** | MS5351 CLK2 出 24.576 → PLL ×2（**已上板实测锁定**） |
| 演奏延迟 | 干路约 **1.3 ms**（优于 ≤5 ms 拓展指标） | 详见 `硬件实现.md` §一 |
| 每采样预算 | **1024 拍**（49.152 MHz / 48 kHz） | 时隙边界固定、与采样同步，保证确定性延迟 |

## 二、数据流
- 乐器 → MIDI 信号 → 接入 FPGA
- **单声部处理**
    + DDS + 波表（生成波形）
    + SVF 滤波
    + VCA（包络 × 力度）
- **通道处理**
    + 通道总线累加（声部并入所属通道）
    + 通道增益 / 声像
    + 效果发送（混响 / 合唱 / 延迟 三条总线）
- **全局处理**
    + 效果器运算（混响 / 合唱 / 延迟）
    + 主混音求和（通道 + 效果返回）
    + 主输出处理（音量 / 限幅 / 抖动）
- I2S 发送 → DAC → 功率放大 → 输出

## 三、技术方案

#### 重要概念

**输入统一为 MIDI。** 乐器输入可能是 I2C 或 MIDI 两种形态，进入 FPGA 前统一转为 MIDI 信号。这样 FPGA 内部只需实现一套消息解析逻辑，同时保持对板级输入形态的兼容性。

**内部按四层组织。** 单声部处理层（逐声部实例，负责发声）、通道处理层（以通道为单位，负责声部汇总与通道级调节）、全局处理层（单实例，负责效果与主输出）、调度层（解析消息、维护各表，向上述三层提供参数）。

**声部并行架构。** 采用 P 条并行泳道 × G 个串行组的结构，声部数 `N = P × G`。泳道内并行以保证时间，泳道间串行复用硬件以节省 DSP。声部编号到（组, 泳道）的映射固定不变，因此每个声部的处理时刻固定，不随活跃声部数变化——这是实现确定性无抖动延迟的基础。扩展声部数只需增大 `G`，泳道逻辑不变。

> **术语区分**：**MIDI 通道固定 16 个**（消息的作用域），而复音**声部数 `N = P × G`** 是硬件并行/串行维度，两者是不同的概念，勿混用。

**音色切换采用「新音起效」。** 切换音色后只影响之后按下的音符，正在发声的音符保持原音色。这一行为来自 GM2 规范的明文要求（收到 Program Change 时不得释放或静音正在发声的音符），而非自选策略。其实现方式是在声部分配时锁定音色槽 `timbre_slot`，因此记住「当前音色」的是声部而非通道。

**混音控制权交给外部设备。** 通道混音与主输出的调节由独立接口接入的外部混音设备完成，乐器端不参与混音、其混音类消息直接忽略。但音频效果的**运算**仍全部在 FPGA 内部完成，外部设备只提供参数。

#### 设计重点

- 输入统一为 MIDI（I2C / MIDI 二选一接入，板上芯片转换）
- FPGA 内部四层组织：单声部 / 通道 / 全局 / 调度
- 声部并行结构 `P × G`，固定映射保证确定性无抖动延迟
- 音色切换「新音起效」（GM2 规范要求），音色槽在分配时锁定
- 混音参数来自外部混音设备；效果运算在 FPGA 内
- 时钟与输出：I2S 48 kHz / **16 bit**，立体声（板载 DAC 为 PT8211）；主时钟 `f_clk` = **49.152 MHz**（来源与分频见 [[硬件实现]]）

> 暂缓功能（LFO / FM / 双波表混合 / 鼓组）见 [[#附录 B：暂缓功能]]。

## 四、状态表

#### 0. 为什么维护状态表
本项目在内存中维护以下数个表格，从**作用域**和**可变性**两个角度进行设计和分析，旨在提高 FPGA 内的信息处理效率。

- **作用域**：分为全局级、通道级、声部级，以及被索引引用的资源池。
- **可变性**：分为三档——**A** 只读（综合/启动载入）；**B** 事件驱动写（消息到达时）；**C** 逐采样读写。

1~4 节是**主表**（原子表），5 节是由主表派生的速查视图。

#### 1. 通道状态表
（16 项，每项对应一个 MIDI 通道）

| 字段                  | 位宽    | 可变性   | 含义                         | 更新来源      |
| ------------------- | ----- | ----- | -------------------------- | --------- |
| `attack_mod`        | 7     | B     | 包络 Attack 调制               | 乐器        |
| `bank_lsb`          | 7     | B     | 音色库号低 7 位（Bank Select LSB） | 乐器        |
| `bank_msb`          | 7     | B     | 音色库号高 7 位（Bank Select MSB） | 乐器        |
| `bend_range`        | 7     | B     | 弯音范围（半音）                   | 乐器        |
| `bend_ratio`        | 16    | B     | 频率比率（预计算）                  | 派生        |
| `bend_value`        | 14    | B     | 弯音值，中心 8192                | 乐器        |
| `default_timbre`    | 8     | A     | 默认音色槽                      | 上位机配置     |
| `expression`        | 7     | B     | 表情                         | 乐器        |
| `filter_cutoff_mod` | 7     | B     | 滤波器截止调制                    | 乐器        |
| `max_voices`        | 6     | A     | 该通道最大声部数                   | 上位机配置     |
| `note_count`        | 6     | B     | 该通道当前占用声部数                 | 声部分配器     |
| `pan`               | 7     | B     | 声像 0–127（64 = 居中）          | 混音器       |
| `pan_gL`            | 16    | B     | 左增益（预计算）                   | 派生        |
| `pan_gR`            | 16    | B     | 右增益（预计算）                   | 派生        |
| `program`           | 7     | B     | 音色号 0–127                  | 乐器        |
| `release_mod`       | 7     | B     | 包络 Release 调制              | 乐器        |
| `resonance_mod`     | 7     | B     | 谐振调制                       | 乐器        |
| `send_chorus`       | 7     | B     | 合唱发送量                      | 混音器       |
| `send_delay`        | 7     | B     | 延迟发送量                      | 混音器       |
| `send_reverb`       | 7     | B     | 混响发送量                      | 混音器       |
| `sostenuto_pedal`   | 1     | B     | 持音踏板状态                     | 乐器        |
| `sustain_pedal`     | 1     | B     | 延音踏板状态                     | 乐器        |
| `volume`            | 7     | B     | 通道音量                       | 混音器       |

**备注**
1. `bank_msb` / `bank_lsb` 为待用值：单独发送 Bank Select 不生效，须待下一个 Program Change 一起生效。
2. `pan` 为原始值；混合时使用由 `pan` 派生的 `pan_gL` / `pan_gR`。

#### 2. 声部状态表
（N 项，N = 声部数）

字段按性质分为 5 组，组间是不同性质的数据，物理存储上建议分区。可变性列含义同通道表。

**（1）DSP 运行状态组**（逐采样读写，属**积分器/累加器**，无法从别处重算）

| 字段           | 位宽  | 可变性 | 含义         | 更新来源                                |
| ------------ | --- | --- | ---------- | ----------------------------------- |
| `phase_acc`  | 32  | C   | DDS 相位累加器  | 每采样周期更新                             |
| `phase_inc`  | 32  | C   | 相位增量       | 每采样周期更新（由 `note` / `bend_ratio` 派生） |
| `env_value`  | 16  | C   | 当前包络值      | 每采样周期更新                             |
| `env_state`  | 3   | C   | 包络状态机状态    | 包络状态机                               |
| `filter_ic1` | 32  | C   | SVF 状态变量 1 | 每采样周期更新                             |
| `filter_ic2` | 32  | C   | SVF 状态变量 2 | 每采样周期更新                             |
| `lfo_phase`  | 24  | C   | LFO 相位     | 每采样周期更新                             |

> `filter_ic1` / `filter_ic2` 为 SVF 内部 32 位有符号状态，输出时取 `[31:8]`。
> `lfo_phase` 为**占位保留**字段：LFO 暂缓（见 [[#附录 B：暂缓功能]]），当前不更新。

**（2）演奏控制组**（来自 Note 事件，含音乐/演奏语义）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `note` | 7 | B | 音符号 | Note On |
| `velocity` | 7 | B | 力度 | Note On |
| `gate` | 1 | B | 是否按键按下 | Note On/Off |

> **已移除 `pending_release` 字段。** 它与 ADSR 的 `PENDING_RELEASE` 状态**语义完全重复**
> （都是"延音踏板还按着、等它松开才真正进入释放"），故以**状态机的状态为唯一权威**，
> 不再保留独立标志位。字段移除后每个声部省 1 bit，且消除了"两处状态不一致"的隐患。
> 详见 [[#（1）ADSR 状态机]] 下的职责划分说明。

**（3）音色引用组**（指向资源池的索引）

| 字段            | 位宽  | 可变性 | 含义                | 更新来源                               |
| ------------- | --- | --- | ----------------- | ---------------------------------- |
| `timbre_slot` | **3** | B   | 本声部正在用的音色槽（分配时锁定） | 分配时由通道表 `(bank, program)` 查音色映射表得到 |

**（4）派生缓存组**（可由其他字段重算，保留以省每采样乘法）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `velocity_gain` | 16 | B | 力度增益 | 分配时计算（由 `velocity` + 音色表 `vel_sensitivity` 派生） |

**（5）管理与调度组**（**非音乐内容**，仅调度器/分配器使用）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `channel` | 4 | B | 所属通道（用于索引通道表） | Note On 分配时写入 |
| `age` | 16 | B | 分配时间戳，用于抢断 | 分配时记录 |

#### 3. 音色参数表
（按 `timbre_slot` 索引，每个音色槽一项）

本表为**只读资源池**（可变性 **A**）：综合时固化或启动时一次性载入，运行时不写入。因此不需要写端口，也不存在「读到半更新行」的风险。

当前按 **8** 个音色槽规划（`timbre_slot` **3 位**，0 ~ 7）。

| 字段                 | 位宽  | 可变性 | 含义                   |
| ------------------ | --- | --- | -------------------- |
| `wave_main`        | 8   | A   | 主波表索引                |
| `adsr_attack`      | 16  | A   | Attack 时间            |
| `adsr_decay`       | 16  | A   | Decay 时间             |
| `adsr_sustain`     | 16  | A   | Sustain 电平           |
| `adsr_release`     | 16  | A   | Release 时间           |
| `adsr_curve`       | 2   | A   | 包络曲线类型（线性/指数）        |
| `filter_type`      | 2   | A   | 滤波器输出类型（LP/BP/HP）    |
| `filter_cutoff`    | 16  | A   | 基准截止频率               |
| `filter_resonance` | 16  | A   | 基准谐振（Q 值）            |
| `filter_env_depth` | 16  | A   | 滤波器包络调制深度            |
| `filter_lfo_depth` | 16  | A   | 滤波器 LFO 调制深度（LFO 暂缓期间不起作用） |
| `vca_gain`         | 16  | A   | 音色总增益                |
| `vel_sensitivity`  | 8   | A   | 力度灵敏度                |

> 备注：`wave_main` 索引到只读波表（波形采样点，综合时固化或启动载入）。

## 五、计算模块

### 1. 单声部层

#### 1.1 单声部链路

单声部是合成引擎的最小发声单元：

```
波表 DDS 生成波形 → SVF 滤波塑形 → VCA 包络增益 → 输出至通道混音总线
```

所有模块在 `sample_en`（每 1024 个时钟拍一个脉冲）有效时更新。

#### 1.2 音色参数含义与换算

- 时间参数单位：**毫秒**
- Sustain：`sustain_level = 65535 × 10^(−dB/20)`；钢琴衰减 6 dB → 32844，吉他衰减 12 dB → 16476
- 截止频率系数：`f = 2 × sin(π × fc / fs)`，Q1.15 格式
- 阻尼系数：`q = 1/Q`，Q1.15 格式

#### 1.3 DDS（波形生成）

- 32 位相位累加器产生数字相位
- 波表**每槽 2048 点** → 表内**整数索引取 `phase_acc[31:21]`（11 位）**；
  小数部分取 `phase_acc[20:13]`（8 位，代表 0~255/256）
- 波表**总地址 = `{timbre_slot[2:0], phase_acc[31:21]}`（14 位）**；
  插值的相邻点在同一槽内 `+1`，**槽末回绕到本槽首点**（不是跳到下一槽）
- 读取相邻两点做**线性插值**：

  `wave_out = tab[n] + (tab[n+1] − tab[n]) × frac / 256`

- 输出 24 位有符号波形样本
- **相位累加器不清零** → 频率切换时保持相位连续

> **幅度 / 定点**：插值结果需**右对齐到 24 位**（`tab_n` 16 位 + 插值项，符号扩展后即可）；注意不要多做一次除以 256 的移位，否则整体幅度缩小。DDS 输出的缩放会一路影响 SVF / VCA，建议用**单频正弦仿真核对幅度**。

#### 1.4 频率 → 相位增量换算

- `phase_inc = f_note / f_s × 2³²`
- 需要**音符号 → 相位增量**的查表（128 音符号 × 32 bit = 4 Kbit，很小）
- `note` 与 `bend_ratio` 的调制如何并入 `phase_inc`（每采样更新）需明确

**结论：支持弯音实时微调，用"查表 + 一次乘法"实现。** 具体口径：

```
phase_inc_base = 查表(note)                 // 128 项 × 32 bit，只读
phase_inc      = (phase_inc_base × bend_ratio) >>> 15   // 32 × 16 → 48 位，Q1.15 归一化
```

- `bend_ratio` 是通道状态表的**派生字段**，由调度层在**控制率**预算好
  （收到 Pitch Bend 时算一次，不必逐采样算），中心值 1.0 = Q1.15 的 32768。
- 因此**逐采样路径上只有 1 次 32 × 16 乘法**（不是一个完整的"比例 → 增量"换算链），
  代价可接受；纯查表无法覆盖弯音的连续取值，故必须保留这一次乘法。
- 乘法结果取高 32 位即可（相位累加器 32 位）；`bend_ratio = 32768` 时结果等于原表值。
- **颤音（vibrato）的调制源是 LFO，本期暂缓**（见 [[#附录 B：暂缓功能]]）；
  恢复时把 LFO 输出作为第二个乘数并入即可，不必改本节的换算结构。

#### 1.5 SVF（滤波）

采用 **Chamberlin 数字状态变量滤波器**，同时提供低通、带通、高通输出。

差分方程：
```
low  = low  + f × band
high = input - low - q × band
band = band + f × high
```

> **状态变量 ↔ 状态表字段对应**：`low` ↔ `filter_ic1`，`band` ↔ `filter_ic2`（积分器状态）。

**effective_fc 合成**：

```
env_term     = (filter_env_depth × env_value) >>> 15;   // 16 位，来自 ADSR
effective_fc = filter_cutoff + env_term + filter_cutoff_mod;
// 饱和：限制在 0 ~ 65535
```

| 信号 | 位宽 | 格式 | 范围 |
|---|---|---|---|
| `filter_cutoff` | 16 | 无符号整数 | 0~65535 |
| `filter_env_depth` | 16 | Q1.15 | 0~1.0 |
| `env_value` | 16 | 无符号 | 0~65535 |
| `filter_cutoff_mod` | 16 | 有符号 | −32768~32767 |

**系数计算**：
- 频率系数：`f = 2 × sin(π × effective_fc_scaled / fs)`，使用 128 点查找表
- 阻尼系数：`q = 1/Q`，Q1.15 格式

**结论：系数表放"全局 128 项查找表"，音色表内不预存**。理由与口径：

| 项 | 结论 |
|---|---|
| 表的位置 | **全局一张**（`f` 表），不放音色表内。因为 `effective_fc` 是**逐采样合成**的（音色基准 + 包络调制 + 通道调制），音色表无法预存所有组合 |
| 表规模 | **128 项 × 16 bit = 2 Kbit**（原估 4 Kbit，实际地址只用 7 位） |
| 索引方式 | 取 `effective_fc`（16 位）的**高 7 位**做地址 → 索引步长 512，频率分辨率 = `fs / 256` |
| 频率分辨率 | 步长 512 / 65535 × (fs/2) ≈ **94 Hz @48 kHz**（对音色滤波够用；若要更细，表扩到 256 项即可，8 Kbit） |
| 系数格式 | **Q1.15**。因 `f = 2·sin(π·fc/fs) < 2` 恒成立（`fc < fs/2`），**恰好落在 Q1.15 范围**内 |
| **必须限幅** | `effective_fc` 要**饱和到 `≤ 32767` 对应的上限**。否则 `f → 2.0` 会超出 Q1.15（32768 装不下），且 Chamberlin 在 `f → 2` 时发散 |
| 工程建议上限 | 把 `effective_fc` 限到 **`fc ≤ fs/4 = 12 kHz`**（此时 `f ≤ 1.414`），高 Q 下仍有充足稳定余量 |

**调制量的合成与表规模**：

```
env_term     = (filter_env_depth × env_value) >>> 15      // 16 位，来自 ADSR
effective_fc = filter_cutoff + env_term + filter_cutoff_mod
// 饱和限幅到 [0, FC_MAX]（建议 FC_MAX 对应 12 kHz，见上）
```

- 三项**都是 16 位**，相加用 17 位中间量后饱和，**不需要额外乘法表**。
- `resonance_mod` 与音色的基准谐振合成 `Q`，再取倒数得 `q`；`q` 也可用一张
  **128 项表**（与 `f` 表并列，共 4 Kbit）以避免逐采样做除法。
- 两张表（`f` / `q`）合计 **4 Kbit**（128 × 16 × 2），占器件 BSRAM 约 0.07%，可忽略。

**稳定性**：
- `f` 系数有稳定范围（Chamberlin 形式约 `f < 2`），**必须限幅**，否则滤波器发散；高 Q 时更容易不稳定。

#### 1.6 ADSR / VCA

**（1）ADSR 状态机**

状态：IDLE、ATTACK、DECAY、SUSTAIN、PENDING_RELEASE、RELEASE。

关键转移：
- SUSTAIN 时若 `gate = 0`：
  - `sustain_pedal = 1` → PENDING_RELEASE
  - `sustain_pedal = 0` → RELEASE
- PENDING_RELEASE 时：
  - `gate = 1` → SUSTAIN
  - `sustain_pedal = 0` → RELEASE

**职责划分结论：状态机的状态是唯一权威，不再保留 `pending_release` 标志。**

| | `PENDING_RELEASE` **状态**（保留，权威） | ~~`pending_release` 标志~~（**已移除**） |
|---|---|---|
| 存什么 | 该声部当前"踏板还按着、等松开" | 同一件事 |
| 放哪 | ADSR 状态机内（`env_state` 的一个取值） | 声部状态表（额外 1 bit） |
| 谁写 | ADSR 自己（SUSTAIN + `gate=0` + `sustain_pedal=1` → 进入） | 分配器/取数器 |
| 谁读 | ADSR 自己 | ADSR |
| 问题 | — | **与状态重复**，两者不一致时行为未定义 |

- `sustain_pedal` 本身是**通道级**字段（在通道状态表），ADSR 直接从通道表取用，
  **不需要在声部表里再存一份**。
- 因此声部表里既不需要 `pending_release`，也不需要 `sustain_pedal`：
  一个声部只需知道"我现在处在哪个 `env_state`"，其余从通道表实时读。
- 事件时序里的 Note Off 处理相应简化为只写 `gate = 0`（不再写 `pending_release`）。

**（2）时间参数换算**

时间参数单位：**毫秒**。

```
attack_step = 65536 / (adsr_attack_ms × fs / 1000)
```

例如 `adsr_attack = 125 ms`：`attack_step = 65536 / 6000 ≈ 11`。

**（3）包络曲线**

`adsr_curve` = 线性 / 指数。指数可用「移位 + 减法」近似（`env −= env >> k`），资源极省。

> **建议**：优先考虑「移位 + 减法」近似，并仿真确认与目标曲线的贴合度。

**（4）VCA 运算与定点**（✅ 口径已定，无歧义）

**输入量程（统一为 Q1.15，全为 16 位无符号语义上的 0~32767）**：

| 量 | 位宽 | 格式 | 说明 |
|---|---|---|---|
| `audio_in` | 24 | Q1.23 有符号 | 来自 SVF，±2²³ |
| `env_value` | 16 | **Q1.15** | 0 ~ 32767 表示 0.0 ~ 0.99997（ADSR 步进按此口径生成） |
| `velocity_gain` | 16 | Q1.15 | 力度增益 |
| `vca_gain` | 16 | Q1.15 | 音色总增益（`timbre_gain`） |

> ⚠ `env_value` **不采用** 0~65535 的 Q1.16 口径 —— 那样它与另两个 Q1.15 系数量程不统一，
> 是原稿"口径混用"的根源。ADSR 的满量程即 `32767`（对应公式里的 `65536` 上限取 `32768 >> 1`）。

**归一化口径（唯一定义）**：

```
voice_out = sat24( (audio_in × env_value × velocity_gain × vca_gain) >>> 45 )
```

- **右移量 = 15 × 3 = 45**（三个 Q1.15 系数各贡献 15 位）。
- 分子是四个量**直接连乘**，**中途不截断、只在最后饱和一次** ——
  这是"口径混用=增益出错"的正解：只要中途取一次 16 位，就会丢掉低位、增益偏小。
- 位宽核算：`24+16+16+16 = 72` 位。**实现上不必真的搭 72 位乘法器**，
  见下面的等效实现。

**实现方案（二选一，结果完全等价）**：

| 方案 | 做法 | 资源 |
|---|---|---|
| **A（推荐，省乘法器）** | **控制率先合并两个慢变系数**：`g_vt = (velocity_gain × vca_gain) >>> 15`（Q1.15）。采样率路径只需 **1 次 24×16**：<br>`p48 = audio_in × env_value`（40 位，符号扩展进 48 位）<br>`voice_out = sat24( (p48 × g_vt) >>> 30 )` | **1 个 16×16（控制率）+ 1 个 24×16（采样率）** |
| B（直算） | 先 `p = audio_in × env_value`（40 位）→ `>>>15` 得 Q1.23；再 `× g_vt` → `>>>15` | 2 个 24×16，精度比 A 略低（中途截断一次） |

> **为什么推荐 A**：`velocity_gain` 与 `vca_gain` 都是**事件/控制率**变化（分配时/音色切换时），
> 完全可以预先合并；采样率路径只留一次 24×16 乘法。这与本项目既有的
> "**控制率三级增益合并**"（通道层 `vol×exp→pan`）是同一个手法，口径一致。
>
> 合并时的截断误差：`(vel×vca)>>>15` 最大损失 1 LSB（约 −90 dBFS），可忽略。

**（5）调制来源与延迟对齐**

- `attack_mod` / `release_mod` 来自通道表，实时调制 A / R 时间。
- **延迟对齐**：包络路径（ADSR → VCA 增益）与音频路径（DDS → SVF → VCA 数据）**流水级数需对齐**，否则包络与波形错拍。

### 2. 多通道层

> 本节覆盖**多通道部分**：通道总线累加 → 通道增益 / 声像 → 效果发送 → 串行输出。
> 定点格式与归一化见 `硬件实现.md` §四。
> 状态：**RTL 已实现并通过验证**（`tb_chan_layer` 96 次比对、`tb_mix_chain` 24 次比对）。

#### 1. 总体结构

**按通道（`NCH = 16`）工作**，每采样周期把 `N = P × G = 32` 个声部的干信号并入各自通道，
施加通道级增益与声像，输出立体声串行通道流，并同时抽出三路效果发送。

```
声部干信号（P 路并行 × G 个时隙）
        │
        ├─ 通道总线累加 ──► 通道音频（32 位累加器，16 条）
        │                        │
        │                  通道增益 × 声像 ──► ChL / ChR（24 位 Q1.23）
        │                        │
        │                        ├──► 主混音干路（串行通道流）
        │                        └──► 效果发送（3 条总线）
```

#### 2. 第一步：通道总线累加

- **输入**：`aud_in`（`P × 24 bit` Q1.23，单声道）、`ch_in`（`P × 4 bit` 通道号）、
  `vld`（`P` 位有效标记）、`slot`（2 bit 时隙号）、`slot_vld`（时隙有效）
- **输出**：`ChAcc[0..15]`（**32 位**累加器，单声道）
- **实现**：
  1. 每个采样周期内 32 个声部分 `G = 4` 个时隙到达，每时隙 `P = 8` 路并行。
  2. 先把并行数据按 `(slot, lane)` 写入一块 **32 × 28 bit 的暂存寄存器堆**
     （`chan_buf`），锁住本采样周期的全部声部样本。**声部号 = `slot × P + lane`**。
     - 用寄存器堆而非 BSRAM：P 路并行写需要 P 个写端口，BSRAM 做不到；
       896 个触发器对本器件不算什么。
     - **无效泳道写 0**：空闲声部对通道总线的贡献必须是 0。
  3. 再在采样周期的剩余拍数里，按声部号 `0 ~ 31` 顺序串行读出，用 `ch_in`
     选择累加器，做 `ChAcc[ch] = ChAcc[ch] + aud`。
     - **串行化是为了避开 16 × 16 的交叉开关**；本层有约 1000 拍余量。
  4. **累加器位宽 32 bit**：`|Σ| ≤ 32 × 2²³ = 2²⁸`，留足余量。
  5. 32 个声部共 **32 拍**，占采样周期约 **3.1%**。
  6. 累加器读是组合的、写是寄存的，所以同一通道在相邻两拍被累加时，
     第二拍能直接看到第一拍写入的新值，**不需要额外旁路**。

#### 3. 第二步：通道增益与声像

- **输入**：`ChAcc[c]`（32 位）、`volume`（7 bit）、`expression`（7 bit）、
  `pan_gL[c]` / `pan_gR[c]`（16 bit Q1.15）
- **输出**：`ChL_c` / `ChR_c`（24 位 Q1.23）
- **三级增益先合并到控制率**，每帧重算一遍：

  ```
  vol_q = volume     << 8              // 7 bit 0~127 → Q1.15 0~32512
  exp_q = expression << 8
  g_ch  = sat16( (vol_q * exp_q)  >>> 15 )
  gL    = sat16( (g_ch  * pan_gL) >>> 15 )
  gR    = sat16( (g_ch  * pan_gR) >>> 15 )
  ```

  **必须合并的理由**：若按「先乘音量得 40 bit，再乘声像」写，
  40 bit × 16 bit = **56 bit**，已超过 DSP 的 48 位累加器。
  合并后每一步都能压回 16 位 Q1.15，**采样率路径永远是 24 × 16 = 40 bit**。
- `pan_gL` / `pan_gR` 是通道状态表的**派生字段**，由调度层按**等功率律**预算好
  （中心点 0.7071，即 −3 dB，满足 `pan_gL² + pan_gR² = 1`），本层直接取用，
  **不做 cos / sin 查表**。
- 源信号是单声道，左右两路是对同一信号施加不同增益：

  ```
  a24   = sat24( ChAcc[c] )                       // 32 → 24 位先饱和
  ChL_c = sat24( (a24 × gL + 2¹⁴) >>> 15 )        // +2¹⁴ 是四舍五入
  ChR_c = sat24( (a24 × gR + 2¹⁴) >>> 15 )
  ```
- **系数计算用 2 级流水线、3 个乘法器**，32 拍把 16 个通道刷新一遍，
  **自由运行、不需要握手**；参数变化后最多 32 拍（约 0.65 µs）生效。
  算好的 `gL` / `gR` 存在 16 项寄存器里，采样率路径只做 2 次乘法。
- 空通道累加器为零，结果自然为零。

> ⚠ **实现注意（踩过的坑）**：`sat24` 的**入口位宽必须是 48 位**。
> 调用点传进来的 `(pl + RND) >>> 15` 是 48 位，若函数声明成 32 位，
> 会在**比较大小之前**先被截断，溢出判断直接失效。

#### 4. 第三步：串行输出与对齐

- **输入**：`ChL_c` / `ChR_c`（24 位 Q1.23）
- **输出**：`ch_vld` / `ch_addr` / `ch_l` / `ch_r`（串行通道流）+ `frame_done`
- **实现**：
  1. 16 条通道在采样周期内串行流过（每条 **1 拍**），共 **16 拍**，占采样周期约 **1.6%**。
  2. 同时给出 `ch_addr`（通道号）与 `ch_vld`（有效标志），后级的**主混音**与
     **效果发送**直接按序取用，不需要额外地址生成。
  3. 第 16 条通道那一拍同时拉高 `frame_done`，并**清空累加器**，供下一帧使用。
- **时隙计数再同步**：`slot_cnt` 由 `frame_stb`（采样帧起始）复位，
  保证**时隙边界与采样同步、固定不变**——这是确定性延迟的前提。

#### 5. 第四步：效果发送

- 按通道状态表的 `send_reverb` / `send_chorus` / `send_delay`（7 bit）
  **归一化为 Q1.15**（16 位扩展后**左移 8 位** → `0x0000 ~ 0x7F00`），
  与通道音频相乘，抽出三路湿信号，送往全局处理层。
- 三条总线各含 L / R，故共 **6 条**湿信号线。
- **发送量在通道层施加，效果器只乘自己的返回电平**（`*_return`），
  第五步的求和不再重复乘。

#### 6. 拍数预算

| 步骤 | 拍数 | 占比（1024 拍预算） |
|---|---|---|
| 暂存写入（4 个时隙） | 4 | 0.4% |
| 通道总线累加（32 声部） | 32 | 3.1% |
| 设系数刷新（自由运行，与上面重叠） | 32 | — |
| 通道增益 + 声像（16 通道） | 16 | 1.6% |
| **本层合计（关键路径）** | **约 52 拍** | **约 5%** |

### 3. 主通道层

> 本节覆盖**主通道部分**：效果发送 → 效果运算 → 主混音 → 主输出。
> 定点格式与归一化见 `硬件实现.md` §四。

#### 1. 效果发送总线

- 3 条总线：`BusRev` / `BusCho` / `BusDel`，各含 L / R 两声道
- 发送量来自通道状态表 `send_reverb` / `send_chorus` / `send_delay`（7-bit，0~127），先归一化为 Q1.15：
  16 位扩展后**左移 8 位** → `0x0000 ~ 0x7F00`（0.0 ~ 0.9922）
- 逐声部相乘 `Ch × Send_Q15`（24×16，得 Q2.38），再按总线**累加**
- 累加用 DSP 的 **48-bit 累加器**（非加法树）；32 声部时单总线 6×32 = 192 拍/声道，占 1024 拍的 18.8%
- 累加后经统一单元 `>>>15` + 饱和，压回 24-bit 送效果器

#### 2. 效果器运算

三条效果器**并联在湿路**上，干信号不经过效果器（**干路额外延迟为零**）；每条内部乘一次返回电平 `xxx_return`。

**混响（Schroeder / Freeverb）**

- 预延迟：`x_pre[n] = x[n − D_pre]`，`D_pre` 取 10~100 ms（100 ms @48 kHz = 4800 点），纯延迟无乘法
- 并联 8 条梳状（含环路阻尼）：
  `y_comb[n] = x_pre[n] + g_decay · y_damp[n − D_comb]`，`y_damp[n] = (1−d)·y_comb[n] + d·y_damp[n−1]`
  - `D_comb` 由 Freeverb 44.1 kHz tuning 换算（系数 **1.08844**）：`1215 / 1293 / 1390 / 1476 / 1548 / 1623 / 1695 / 1760` 点
  - `g_decay` 由 `reverb_decay`、`d` 由 `reverb_damping` 映射，均限 **0~0.98** 保证稳定
- 串联 2 条全通：`y_ap[n] = −g_ap·x_in[n] + x_in[n − D_ap] + g_ap·y_ap[n − D_ap]`
  - `D_ap` = `605 / 480 / 371 / 245`；`g_ap = 0.5`（Q1.15 = 16384）
- 输出：`RevOut = sat24((y_ap × reverb_return) >>> 15)`；右声道各延迟再加 25 点做立体声展宽

**合唱（Chorus）**

- LFO：1024 点正弦表 + 相位累加器，`FTW = round(chorus_rate / f_s × 2³²)`，`chorus_rate` 取 0.1~5 Hz；立体声两声道用**反相 LFO**
- 调制延迟 + 线性插值：`D_mod = D_base + chorus_depth·LFO`（含小数 `frac`），
  `x_delayed = x[n−k] + frac·(x[n−k−1] − x[n−k])`，`k = floor(D_mod)`
  - `D_base` 15~25 ms（20 ms = 960 点）；`chorus_depth` ≤ 5 ms（240 点）
- 干湿混合：`y_mix = sat24(( (1−chorus_mix)·x[n] + chorus_mix·x_delayed ) >>> 15)`

**延迟（Delay）**

- 读取：`x_del[n] = x[n − D_delay]`，`D_delay = round(delay_time × f_s)`；地址 = 环形写指针 + 偏移
- 反馈：`y_fb[n] = x[n] + sat24((delay_feedback × x_del[n]) >>> 15)`；反馈系数 Q1.15 **≤ 32000**（≈0.977）防自激
- 干湿：`y_mix = ((1−delay_mix)·x[n] + delay_mix·y_fb[n]) >>> 15`

**效果返回混合**

- `FxRet_L = RevOut_L + ChoOut_L + DelOut_L`（右同理），中间取 26-bit（`24 + ⌈log₂3⌉`），先符号扩展再相加
- （GM2 可选）合唱按比例汇入混响：`BusRev += sat24((ChoOut × ChoToRev) >>> 15)`

**参数平滑（消拉链噪声）**

- 所有控制量经一阶低通：`p[n] = p[n−1] + α·(p_target − p[n−1])`，`α ≈ 2⁻⁸ ~ 2⁻¹²`
- 每采样周期只更新 1/N 个声部的参数（轮转），保证单周期工作量恒定

#### 3. 主混音求和

- 对每个声部施加通道音量与声像，生成左右分量（等功率法则）：
  `gL = vol·cos(θ)`、`gR = vol·sin(θ)`，`θ = (pan+1)/2 · π/2`（中心 `pan = 0` 时 `gL = gR = 0.7071`，即 −3 dB）
- 逐声部相乘后按 L / R **串行累加**（DSP 48-bit 累加器），`>>>15` + 饱和压回 24-bit
- 干湿混合：`Mix = sat26((Dry × master_dry) >>> 15) + sat26((FxRet × master_wet) >>> 15)`，默认各 0.7071

#### 4. 主输出处理

处理顺序：**主音量 → 软限幅 → 隔直（可选）→ 抖动与位深转换 → PT8211 串行化**。

- **主音量**：`Vol = sat24((Mix × G_master) >>> 15)`；主音量 SysEx 为 14-bit，`G` 量化为 Q1.15 即 `V << 1`（误差 < 0.006%）
- **软限幅**：`Env = max(|L|, |R|)`；`G_target = min(1, 阈值/Env)`，除法用 256 项倒数 LUT + 线性插值，增益缓升
- **隔直**（可选）：`y[n] = x[n] − x[n−1] + a·y[n−1]`，`a = 0.995` → fc ≈ 38.2 Hz
- **抖动**：24→16 bit 截断前加 TPDF 抖动（两个 32-bit LFSR 相减 `>>>8`，幅度 ±1 LSB@16-bit）
- **PT8211 串行化**：16 bit / LSBJ / MSB 先出 / WS 高 = 左声道（见 `硬件实现.md` §四）

## 六、调度模块与时序

#### 0. 为什么分两类调度
本项目设计了以下调度模块，并按照**事件类**和**周期类**两种不同的时序类型将调度模块进行分类，旨在同时满足时间延迟与硬件规模的限制，并提高信息调度效率。

- **事件类**：消息到达时工作，延迟预算宽松，不参与逐采样路径。
- **周期类**：每采样周期工作，须在时钟预算内跑完全部声部。

#### 1. 周期类模块

| 模块 | 职责 |
|---|---|
| 声部时序器 | 只产生声部索引与轮转节拍（`(组, 泳道)` 序列），不含取数逻辑 |
| 声部取数器 | 按索引并行取出声部上下文（声部表运行状态、通道表调制参数、音色表音色参数），送单声部处理；预取下一时隙参数以隐藏读延迟 |

#### 2. 事件类模块

| 模块 | 职责 |
|---|---|
| MIDI 消息解析 | 解析字节流、区分消息类型并分发；乐器端口的混音类 CC 丢弃 |
| 通道状态表编辑器 | 维护通道状态表（音量、声像、弯音、踏板、调制、发送量等） |
| 音色映射 | 由 `(bank_msb, program)` 查音色映射表，输出 `timbre_slot` |
| 声部分配 / 释放器 | 声部分配、抢断、释放；写声部表的分配类字段 |

**与周期类的关系**：分配器不直接改写计算路径正在使用的字段，而是通过「声部已分配 / 已释放」标记通知时序器。声部编号 → (组, 泳道) 的映射固定不变，保证每个声部延迟确定。

#### 3. 周期时序
由于系统受到时序和资源双重约束，故本系统采用并行泳道和串行组混合的工作方案：

| 约束       | 内容                           | 说明          |
| -------- | ---------------------------- | ----------- |
| 约束 A（时间） | 在 `T_s = 1/f_s` 内必须把全部声部算完一遍 | 采样率决定的时间预算  |
| 约束 B（资源） | 乘法器（DSP）总数有上限                | 器件硬件决定的资源上限 |

- **纯轮询**：一套运算单元分时跑 N 次 → 省 DSP，但耗时随声部数线性增长
- **纯并行**：N 套运算单元 → 省时间，但 DSP 直接 ×N
**混合模式 = 同时满足 A 与 B：P 条并行泳道 × G 个串行轮转组。**
**（1）时间计算**

基础时间量：

| 量 | 符号 | 值 |
|---|---|---|
| 音频采样率 | `f_s` | 48 kHz |
| 采样周期 | `T_s` | 20.833 µs |
| 系统时钟 | `f_clk` | **49.152 MHz** |
| 时钟周期 | `T_clk` | 20.345 ns |
| 每采样时钟拍数 | `N_cyc` | **1024** |

> `49.152 MHz = 24.576 MHz × 2`，而 `24.576 MHz = 512 × f_s`。
> 该时钟由板载 MS5351 合成后送入 FPGA（50 MHz 晶振无法得到 48 kHz 一族，见 [[硬件实现]]）。

声部处理的时钟分解（`P = 8`、`G = 4` 时）：

| 量 | 符号 | 值 | 说明 |
|---|---|---|---|
| 并行泳道数 | `P` | **8** | 硬件复制份数 |
| 串行组数 | `G` | **4** | 时间复用次数 |
| 声部总数 | `N` | 32 | `P × G` |
| 单声部流水线深度 | `L` | **设计目标 ≤ 48 拍**（估算 ~20 拍） | 由 RTL 实测回填，测量方法见下 |
| 全声部扫描耗时 | `G × L` | ≤ 192 拍（估算 ~80 拍） | 占 `N_cyc` 的 ≤ 18.8%（估算 7.8%） |
| 时钟余量 | `N_cyc − G×L` | ≥ 832 拍 | 极充裕 |

**`L` 的定义与测量方法**（用于回填与验收）：

- **定义**：`L` = 单声部处理链 **`DDS → SVF → VCA`** 从"该声部参数就绪"到
  "波形样本可写入通道总线"所经历的**时钟拍数**，即该声部在同一时隙内独占流水线的拍数
  （**不是组合路径延迟**）。
- **测量方法**：写单声部 TB，在时隙起始拍给入已知相位 / 包络，用打拍链记录
  "输出样本第一次有效"的拍号差；对 `DDS`、`SVF`、`VCA` 各测一次再相加（含其间对齐寄存）。
- **为什么必须实测**：`L` 决定 `G × L` 能否塞进 `N_cyc`；同时它也是
  [[#（5）调制来源与延迟对齐]] 里"包络路径与音频路径必须对齐"的基准值 ——
  `L` 一旦确定，调制路径要用打拍链补到同一深度。
- **验收门限**：`G × L ≤ N_cyc / 2`（即 `L ≤ 128`）时认为时间预算安全。
  若实测 `L > 128`，优先**在 DDS / SVF / VCA 内部插流水**（把组合链切短），
  **而不是增大 `G`** —— 因为增大 `G` 只增加时间占用，不改善单声部时序。
- **当前状态**：单声部层 RTL 尚未实现，故此值待回填；上表"设计目标 ≤ 48 拍"
  取的是把 DDS（1 拍查表 + 1 拍插值）、SVF（3 拍递归）、VCA（1 拍）
  各自留足流水后的**保守预算**，便于先按此约束设计。

> **分工依据**：`P` 由 **DSP 数量**决定（资源紧约束），`G` 由**时间预算**决定（时间极宽裕）。
> 故取较小 `P`（省 DSP）+ 较大 `G`（用掉宽裕的时间）。扩展声部数时**固定 `P`，只加 `G`**。
> **拓展方式**：固定 `P`，只加 `G`（`G` 只增加时间占用，不增加 DSP 与端口数）

延迟预算：

```
Note On → 出声
  = 解析 + 分配（事件驱动，若干拍）        ≈ 0
  + 采样对齐                             ≤ 1 个采样周期 `T_s` = 20.833 µs
  + 组等待                               ≤ (G−1) × L = 3 × 20 = 60 拍 = 1.22 µs
  ─────────────────────────────────────
  合计                                   ≈ 22 µs
```

对比赛题要求（基础 ≤ 10 ms，拓展 ≤ 5 ms）：**余量约 220 倍**。延迟瓶颈不在架构，而在 ADSR 起音时间与滤波器状态建立时间。

**整链路延迟预算**（自 MIDI 输入至模拟输出）：

| 环节 | 延迟 |
|---|---|
| MIDI 接收与解析 | 事件路径，不阻塞音频（不增加音频往返延迟） |
| 事件 → 声部表更新 | ≤ 1 个采样周期 `T_s` = 20.833 µs |
| 单声部流水线（DDS / ADSR / SVF / VCA） | < 1 µs（约 16 级 @ 49.152 MHz ≈ 0.33 µs，同一采样周期内完成） |
| 通道 / 全局处理（发送、效果、混音、主输出） | ≤ 2 `T_s` = 0.042 ms |
| I2S 串行输出 | ≤ 1 帧 = 32 BCK = `T_s` = 20.833 µs |
| PT8211 内部（8× 过采样 R-2R） | 手册未给群延迟，保守估 ≤ 0.2 ms（待实测） |
| XPT4809 耳放（AB 类） | ≈ 0（模拟器件，只贡献相移） |
| **合计（干路）** | **约 1.3 ms**，优于赛题 ≤ 5 ms |

> 三条效果器**不得串入干路**，故上表不含效果器；干路延迟与效果参数无关。

#### 4. 事件时序

**（1）事件顺序表**

## 七、合规性与验收

#### 1. 评分规则对应

- **独立发声单元**：含独立相位累加器、频率调控、包络控制的完整振荡器。发送总线、混音、混响 / 合唱 / 延迟**不计入**振荡器数。故本设计的核心目标是：**用最少的 DSP 与 BSRAM 把混音与效果做干净，把资源让给振荡器。**
- **吞吐量** = 同时活跃的独立振荡器数 × 实际输出采样率。**过采样不叠加加分**；输出采样率以送到 DAC 的实际 `f_s` 为准（由 BCLK / 32 决定），不是内部计算率。
- 本项目 32 复音时：`32 × 48.000 kHz = 1.536 M 振荡器样本/秒`。

#### 2. 测试模式（TEST_MODE，现场验证必需）

一键进入可验证状态：

- 关闭所有效果（`send_*` 全为 0、`master_wet = 0`）
- 关闭软限幅的动态增益（阈值设为 1.0，即固定增益）
- 32 个振荡器分配互不重合的频率（例：200 Hz 起，对数均匀分布到 8 kHz）
- 每声部幅度缩放 `1/N` 或 `1/√N`，避免叠加削顶
- 声像左右交替（L / R / L / R …），顺带验证声像与声道极性
- 可选：把主输出接 LED / WS2812 做简易电平指示

现场用频谱仪或示波器 FFT 数谱峰，即可佐证复音数。

#### 3. 合规红线

- 所有音频必须由 FPGA **逐音、逐样本实时生成**；波表只能是**单周期波形**，严禁任何形式的预录 PCM 或整段录音回放。
- 板上 AE350 RISC-V 硬核只能用于控制、UI、曲库与参数管理，**不得参与逐样本音频运算**。

## 附录 A：资源预算

（以 `P = 8`、`G = 4`、`N = 32` 计；器件上限：LUT / FF 各 138,240、BSRAM 6,120 Kbit、DSP 298）

| 项 | 估算 | 占器件 |
|---|---|---|
| 声部状态表 | 32 × ~220 bit ≈ 7 Kbit | < 1% BSRAM |
| 通道状态表 | 16 × ~200 bit ≈ 3 Kbit | 寄存器实现 |
| 音色参数表 | 32 × ~300 bit ≈ 10 Kbit | < 1% |
| 波表 | **8 槽 × 2048 点 × 16 bit = 256 Kbit** | **16 块 BSRAM**（16 Kbit 模式） |
| 效果器 + 延迟线（**延迟上限 512 ms**） | 混响 44 + 合唱 6 + 延迟 96 = **146 块** | 146 / 340 块（**42.9%**） |
| DSP：单声部阵列 `P × m` | 8 × m（`m` 待实测） | — |
| DSP：效果器 `D_fx` | ~39 | 13% |

> **全片 BSRAM 合计（16 Kbit 模式，340 块）**：

| 项 | 块数 |
|---|---|
| 效果器 + 延迟线 | 146 |
| 波表（8 槽 × 2048 点） | 16 |
| 声部状态表 / 音色参数表 / 映射表 / 正弦表等 | 约 1.6 |
| **合计** | **约 164 / 340 = 48%**（**余量 176 块**） |

> - 效果器 / 延迟线 / 波表的逐项折算见 `documents/主通道部分/`。
> - **波表并发读**：复制 P 份的方案（32 Kbit/波形 × 8）会吃掉约 256 Kbit/波形，不可行 → 采用**时隙内串行查表**。
> - `m`、`L`、`D_fx` 为待实测值，最终以 IDE 资源报告为准。

## 附录 B：暂缓功能

> 以下功能**本期暂不实现**，其字段与模块**已从 §四 状态表、§六 调度模块中移出**，集中记录于此，以免丢失设计信息。
> 将来恢复时：把对应字段加回主表、模块加回调度层即可。

**（1）LFO**

- 作用：产生低频调制，送往 DDS（颤音）与 SVF（滤波调制）。
- 实现：相位累加 + 波形查表（`lfo_wave`：正弦 / 三角 / 方波）；`lfo_delay` / `lfo_fade` 相对**该声部按下时刻**计时，需每声部计数器；速率 → 相位增量换算同 DDS。
- 涉及字段（音色参数表）：`lfo_freq`、`lfo_wave`、`lfo_delay`、`lfo_fade`。
- 涉及字段（通道状态表）：`mod_wheel`（调制轮）、`vibrato_depth`（颤音深度，预计算）。
- 说明：声部状态表的 `lfo_phase`、音色参数表的 `filter_lfo_depth` **保留为占位**，LFO 暂缓期间不更新/不起作用。

**（2）FM 合成**

- 作用：调制器输出加到载波相位，扩展音色。
- 实现：`fm_ratio_c` / `fm_ratio_m`（8 bit 比例）→「比例 → 相位增量」换算（查表或乘法）；注意相位累加的位宽对齐；`fm_env_depth` 由 ADSR 包络调制。
- 涉及字段（音色参数表）：`fm_ratio_c`、`fm_ratio_m`、`fm_depth`、`fm_env_depth`。

**（3）双波表混合**

- 作用：DDS 同时查主 / 辅波表并按比例加权，扩展波形。
- 实现：查 `wave_main` 与 `wave_aux`，按 `wave_mix`（Q1.15）加权求和；波表读取量翻倍（每声部 4 点）→ 需重算波表串行读拍数。
- 涉及字段（音色参数表）：`wave_aux`、`wave_mix`。

**（4）鼓声部 / 鼓组映射**

- 作用：鼓通道（`bank MSB = 120`，GM2 做法）内，音符号映射为某件鼓的音色槽；鼓声用**合成方式实时生成**，固定时长、忽略 Note Off。
- 音色参数表字段（已移出）：
  - `drum_mode`：是否鼓组模式（1 = 本槽为鼓组）
  - `drum_map_base`：鼓组映射表子表基址，步长 128（仅 `drum_mode=1` 时有效）
  - `excl_group`：互斥组编号（0 = 无互斥）；同组内新音起时静掉旧音
  - `base_pitch`：基准音高（鼓声部的 `note` 用于选音色，音高取自此字段）
- 声部状态表字段（已移出）：
  - `drum_mode`：本声部是否为鼓声部（Note Off 时据此忽略）
- 鼓组映射表（已移出）：

  | 字段 | 位宽 | 可变性 | 含义 |
  |---|---|---|---|
  | `drum_map[drum_map_base + note]` | **3** | A | 输出 `timbre_slot`（3 位，对应 8 个音色槽） |

  > 备注：仅当音色参数表 `drum_mode = 1` 时启用；由 `drum_map_base` 选择子表（步长 128）；当前按 2 套鼓组规划，扩到 8 套需将 `drum_map_base` 加宽至 11 位。
- 调度层模块（已移出）：**鼓组映射** —— 鼓通道内由音符号查鼓组映射表，输出 `timbre_slot` 给声部分配。
- 事件时序（已移出）：Note On 处理链中的「（鼓：再查鼓组映射）」及写声部表的 `drum_mode`；Note Off 的「鼓声部忽略」。

**（5）散见于调度 / 复位描述的暂缓项**

- 复位情况表：**鼓组映射表**（属暂缓资源，不纳入复位表）。
- 通道状态表编辑器：派生项 **CC1 → `vibrato_depth`**。
- 音色映射模块：标题及适用范围中的**鼓组映射**部分。
- 声部分配 / 释放器：**互斥组静音（`excl_group`）**、**鼓声部忽略 Note Off（`drum_mode`）**。
- 声部取数器：写回字段中的 **`lfo_phase`**。
