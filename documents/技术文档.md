- 基于 FPGA 的实时多音色合成电子乐器引擎

## 二、数据流
- 乐器 → MIDI 信号 → 接入 FPGA
- **单声部处理**
    + DDS + 波表（生成波形）
    + SVF 滤波
    + VCA（包络 × 力度）
- **通道处理**
    + 通道总线累加（声部并入所属通道）
    + 通道增益 / 声像
    + 效果发送（混响 / 合唱 / 延迟 三条总线）
- **全局处理**
    + 效果器运算（混响 / 合唱 / 延迟）
    + 主混音求和（通道 + 效果返回）
    + 主输出处理（音量 / 限幅 / 抖动）
- I2S 发送 → DAC → 功率放大 → 输出

## 三、技术方案

#### 重要概念

**输入统一为 MIDI。** 乐器输入可能是 I2C 或 MIDI 两种形态，进入 FPGA 前统一转为 MIDI 信号。这样 FPGA 内部只需实现一套消息解析逻辑，同时保持对板级输入形态的兼容性。

**内部按四层组织。** 单声部处理层（逐声部实例，负责发声）、通道处理层（以通道为单位，负责声部汇总与通道级调节）、全局处理层（单实例，负责效果与主输出）、调度层（解析消息、维护各表，向上述三层提供参数）。

**声部并行架构。** 采用 P 条并行泳道 × G 个串行组的结构，声部数 `N = P × G`。泳道内并行以保证时间，泳道间串行复用硬件以节省 DSP。声部编号到（组, 泳道）的映射固定不变，因此每个声部的处理时刻固定，不随活跃声部数变化——这是实现确定性无抖动延迟的基础。扩展声部数只需增大 `G`，泳道逻辑不变。

> **术语区分**：**MIDI 通道固定 16 个**（消息的作用域），而复音**声部数 `N = P × G`** 是硬件并行/串行维度，两者是不同的概念，勿混用。

**音色切换采用「新音起效」。** 切换音色后只影响之后按下的音符，正在发声的音符保持原音色。这一行为来自 GM2 规范的明文要求（收到 Program Change 时不得释放或静音正在发声的音符），而非自选策略。其实现方式是在声部分配时锁定音色槽 `timbre_slot`，因此记住「当前音色」的是声部而非通道。

**混音控制权交给外部设备。** 通道混音与主输出的调节由独立接口接入的外部混音设备完成，乐器端不参与混音、其混音类消息直接忽略。但音频效果的**运算**仍全部在 FPGA 内部完成，外部设备只提供参数。

#### 设计重点

- 输入统一为 MIDI（I2C / MIDI 二选一接入，板上芯片转换）
- FPGA 内部四层组织：单声部 / 通道 / 全局 / 调度
- 声部并行结构 `P × G`，固定映射保证确定性无抖动延迟
- 音色切换「新音起效」（GM2 规范要求），音色槽在分配时锁定
- 鼓组：鼓通道（`bank MSB = 120`）内音符号映射为音色槽，鼓声用合成方式实时生成
- 混音参数来自外部混音设备；效果运算在 FPGA 内
- 时钟与输出：I2S 48 kHz / **16 bit**，立体声（板载 DAC 为 PT8211）；主时钟 `f_clk` = **49.152 MHz**（来源与分频见 [[硬件实现]]）

## 四、状态表

#### 0. 为什么维护状态表
本项目在内存中维护以下数个表格，从**作用域**和**可变性**两个角度进行设计和分析，旨在提高 FPGA 内的信息处理效率。

- **作用域**：分为全局级、通道级、声部级，以及被索引引用的资源池。
- **可变性**：分为三档——**A** 只读（综合/启动载入）；**B** 事件驱动写（消息到达时）；**C** 逐采样读写。

1~4 节是**主表**（原子表），5 节是由主表派生的速查视图。

#### 1. 通道状态表
（16 项，每项对应一个 MIDI 通道）

| 字段                  | 位宽    | 可变性   | 含义                         | 更新来源      |
| ------------------- | ----- | ----- | -------------------------- | --------- |
| `attack_mod`        | 7     | B     | 包络 Attack 调制               | 乐器        |
| `bank_lsb`          | 7     | B     | 音色库号低 7 位（Bank Select LSB） | 乐器        |
| `bank_msb`          | 7     | B     | 音色库号高 7 位（Bank Select MSB） | 乐器        |
| `bend_range`        | 7     | B     | 弯音范围（半音）                   | 乐器        |
| `bend_ratio`        | 16    | B     | 频率比率（预计算）                  | 派生        |
| `bend_value`        | 14    | B     | 弯音值，中心 8192                | 乐器        |
| `default_timbre`    | 8     | A     | 默认音色槽                      | 上位机配置     |
| `expression`        | 7     | B     | 表情                         | 乐器        |
| `filter_cutoff_mod` | 7     | B     | 滤波器截止调制                    | 乐器        |
| `max_voices`        | 6     | A     | 该通道最大声部数                   | 上位机配置     |
| `mod_wheel`         | 7     | B     | 调制轮                        | 乐器        |

| `pan_gR`            | 16    | B     | 右增益（预计算）                   | 派生        |
| `program`           | 7     | B     | 音色号 0–127                  | 乐器        |
| `release_mod`       | 7     | B     | 包络 Release 调制              | 乐器        |
| `resonance_mod`     | 7     | B     | 谐振调制                       | 乐器        |
| `send_chorus`       | 7     | B     | 合唱发送量                      | 混音器       |
| `send_delay`        | 7     | B     | 延迟发送量                      | 混音器       |
| `send_reverb`       | 7     | B     | 混响发送量                      | 混音器       |
| `sostenuto_pedal`   | 1     | B     | 持音踏板状态                     | 乐器        |
| `sustain_pedal`     | 1     | B     | 延音踏板状态                     | 乐器        |
| `vibrato_depth`     | 16    | B     | 颤音深度（预计算）                  | 派生        |

1. `bank_msb` / `bank_lsb` 为待用值：单独发送 Bank Select 不生效，须待下一个 Program Change 一起生效。

#### 2. 声部状态表
（N 项，N = 声部数）

字段按性质分为 5 组，组间是不同性质的数据，物理存储上建议分区。可变性列含义同通道表。

**（1）DSP 运行状态组**（逐采样读写，属**积分器/累加器**，无法从别处重算）

| 字段           | 位宽  | 可变性 | 含义         | 更新来源                                |
| ------------ | --- | --- | ---------- | ----------------------------------- |
| `phase_acc`  | 32  | C   | DDS 相位累加器  | 每采样周期更新                             |
| `phase_inc`  | 32  | C   | 相位增量       | 每采样周期更新（由 `note` / `bend_ratio` 派生） |
| `env_value`  | 16  | C   | 当前包络值      | 每采样周期更新                             |
| `env_state`  | 3   | C   | 包络状态机状态    | 包络状态机                               |
| `filter_ic1` | 24  | C   | SVF 状态变量 1 | 每采样周期更新                             |
| `filter_ic2` | 24  | C   | SVF 状态变量 2 | 每采样周期更新                             |
| `lfo_phase`  | 24  | C   | LFO 相位     | 每采样周期更新                             |

**（2）演奏控制组**（来自 Note 事件，含音乐/演奏语义）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `note` | 7 | B | 音符号 | Note On |
| `velocity` | 7 | B | 力度 | Note On |
| `gate` | 1 | B | 是否按键按下 | Note On/Off |
| `pending_release` | 1 | B | 延音踏板待释放标记 | Note Off + 踏板 |

**（3）音色引用组**（指向资源池的索引）

| 字段            | 位宽  | 可变性 | 含义                | 更新来源                               |
| ------------- | --- | --- | ----------------- | ---------------------------------- |
| `timbre_slot` | 8   | B   | 本声部正在用的音色槽（分配时锁定） | 分配时由通道表 `(bank, program)` 查音色映射表得到 |

**（4）派生缓存组**（可由其他字段重算，保留以省每采样乘法）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `velocity_gain` | 16 | B | 力度增益 | 分配时计算（由 `velocity` + 音色表 `vel_sensitivity` 派生） |

**（5）管理与调度组**（**非音乐内容**，仅调度器/分配器使用）

| 字段 | 位宽 | 可变性 | 含义 | 更新来源 |
|---|---|---|---|---|
| `channel` | 4 | B | 所属通道（用于索引通道表） | Note On 分配时写入 |
| `age` | 16 | B | 分配时间戳，用于抢断 | 分配时记录 |
| `drum_mode` | 1 | B | 本声部是否为鼓声部（Note Off 时据此忽略） | 分配时由音色参数表快照 |

**（3）音色映射表**

可变性 **A**。用途：把 `(bank_msb, program)` 映射为 `timbre_slot`。

| 字段 | 位宽 | 可变性 | 含义 |
|---|---|---|---|
| `map[bank_msb][program]` | 8 | A | 输出 `timbre_slot` |

> 备注：起步采用恒等映射（`timbre_slot = program`，单库），保留真映射表接口。理由：MIDI 音色号有 128（含库可达 16384 库），而 `timbre_slot` 槽数受 BRAM 限制，两者数量级不同。`bank` 用于区分音色集合（如「基础音色库」/「自定义音色库」）。鼓组使用 `bank MSB = 120`。

**（4）鼓组映射表**

可变性 **A**。用途：鼓通道内，把音符号映射为某件鼓的音色槽。

| 字段 | 位宽 | 可变性 | 含义 |
|---|---|---|---|
| `drum_map[drum_map_base + note]` | 8 | A | 输出 `timbre_slot` |

> 备注：
> 1. 仅当音色参数表 `drum_mode = 1` 时启用；由音色参数表的 `drum_map_base` 选择子表（步长 128）。
> 2. 鼓通道判定依据：`bank MSB = 120`（GM2 做法），经音色映射表得到 `kit` 后由音色参数表判定。
> 3. 当前按 2 套鼓组规划（`base` 8 位恰好容纳 2 个子表）；扩到 8 套需将 `drum_map_base` 加宽至 11 位。

## 五、计算模块

> 单声部处理链（DDS / ADSR / SVF / LFO / VCA）见 `documents/单声部部分/`；
> 本节覆盖**主通道部分**：效果发送 → 效果运算 → 主混音 → 主输出。
> 定点格式与归一化见 `硬件实现.md` §五 / §六；逐模块实现细节见 `模块速查表.md` §十。

#### 1. 效果发送总线

- 3 条总线：`BusRev` / `BusCho` / `BusDel`，各含 L / R 两声道
- 发送量来自通道状态表 `send_reverb` / `send_chorus` / `send_delay`（7-bit，0~127），先归一化为 Q1.15：
  16 位扩展后**左移 8 位** → `0x0000 ~ 0x7F00`（0.0 ~ 0.9922）
- 逐声部相乘 `Ch × Send_Q15`（24×16，得 Q2.38），再按总线**累加**
- 累加用 DSP 的 **48-bit 累加器**（非加法树）；32 声部时单总线 6×32 = 192 拍/声道，占 1024 拍的 18.8%
- 累加后经统一单元 `>>>15` + 饱和，压回 24-bit 送效果器

#### 2. 效果器运算

三条效果器**并联在湿路**上，干信号不经过效果器（**干路额外延迟为零**）；每条内部乘一次返回电平 `xxx_return`。

**混响（Schroeder / Freeverb）**

- 预延迟：`x_pre[n] = x[n − D_pre]`，`D_pre` 取 10~100 ms（100 ms @48 kHz = 4800 点），纯延迟无乘法
- 并联 8 条梳状（含环路阻尼）：
  `y_comb[n] = x_pre[n] + g_decay · y_damp[n − D_comb]`，`y_damp[n] = (1−d)·y_comb[n] + d·y_damp[n−1]`
  - `D_comb` 由 Freeverb 44.1 kHz tuning 换算（系数 **1.08844**）：`1215 / 1293 / 1390 / 1476 / 1548 / 1623 / 1695 / 1760` 点
  - `g_decay` 由 `reverb_decay`、`d` 由 `reverb_damping` 映射，均限 **0~0.98** 保证稳定
- 串联 2 条全通：`y_ap[n] = −g_ap·x_in[n] + x_in[n − D_ap] + g_ap·y_ap[n − D_ap]`
  - `D_ap` = `605 / 480 / 371 / 245`；`g_ap = 0.5`（Q1.15 = 16384）
- 输出：`RevOut = sat24((y_ap × reverb_return) >>> 15)`；右声道各延迟再加 25 点做立体声展宽

**合唱（Chorus）**

- LFO：1024 点正弦表 + 相位累加器，`FTW = round(chorus_rate / f_s × 2³²)`，`chorus_rate` 取 0.1~5 Hz；立体声两声道用**反相 LFO**
- 调制延迟 + 线性插值：`D_mod = D_base + chorus_depth·LFO`（含小数 `frac`），
  `x_delayed = x[n−k] + frac·(x[n−k−1] − x[n−k])`，`k = floor(D_mod)`
  - `D_base` 15~25 ms（20 ms = 960 点）；`chorus_depth` ≤ 5 ms（240 点）
- 干湿混合：`y_mix = sat24(( (1−chorus_mix)·x[n] + chorus_mix·x_delayed ) >>> 15)`

**延迟（Delay）**

- 读取：`x_del[n] = x[n − D_delay]`，`D_delay = round(delay_time × f_s)`；地址 = 环形写指针 + 偏移
- 反馈：`y_fb[n] = x[n] + sat24((delay_feedback × x_del[n]) >>> 15)`；反馈系数 Q1.15 **≤ 32000**（≈0.977）防自激
- 干湿：`y_mix = ((1−delay_mix)·x[n] + delay_mix·y_fb[n]) >>> 15`

**效果返回混合**

- `FxRet_L = RevOut_L + ChoOut_L + DelOut_L`（右同理），中间取 26-bit（`24 + ⌈log₂3⌉`），先符号扩展再相加
- （GM2 可选）合唱按比例汇入混响：`BusRev += sat24((ChoOut × ChoToRev) >>> 15)`

**参数平滑（消拉链噪声）**

- 所有控制量经一阶低通：`p[n] = p[n−1] + α·(p_target − p[n−1])`，`α ≈ 2⁻⁸ ~ 2⁻¹²`
- 每采样周期只更新 1/N 个声部的参数（轮转），保证单周期工作量恒定

#### 3. 主混音求和

- 对每个声部施加通道音量与声像，生成左右分量（等功率法则）：
  `gL = vol·cos(θ)`、`gR = vol·sin(θ)`，`θ = (pan+1)/2 · π/2`（中心 `pan = 0` 时 `gL = gR = 0.7071`，即 −3 dB）
- 逐声部相乘后按 L / R **串行累加**（DSP 48-bit 累加器），`>>>15` + 饱和压回 24-bit
- 干湿混合：`Mix = sat26((Dry × master_dry) >>> 15) + sat26((FxRet × master_wet) >>> 15)`，默认各 0.7071

#### 4. 主输出处理

处理顺序：**主音量 → 软限幅 → 隔直（可选）→ 抖动与位深转换 → PT8211 串行化**。

- **主音量**：`Vol = sat24((Mix × G_master) >>> 15)`；主音量 SysEx 为 14-bit，`G` 量化为 Q1.15 即 `V << 1`（误差 < 0.006%）
- **软限幅**：`Env = max(|L|, |R|)`；`G_target = min(1, 阈值/Env)`，除法用 256 项倒数 LUT + 线性插值，增益缓升
- **隔直**（可选）：`y[n] = x[n] − x[n−1] + a·y[n−1]`，`a = 0.995` → fc ≈ 38.2 Hz
- **抖动**：24→16 bit 截断前加 TPDF 抖动（两个 32-bit LFSR 相减 `>>>8`，幅度 ±1 LSB@16-bit）
- **PT8211 串行化**：16 bit / LSBJ / MSB 先出 / WS 高 = 左声道（见 `硬件实现.md` §四）

## 六、调度模块与时序

#### 0. 为什么分两类调度
本项目设计了以下调度模块，并按照**事件类**和**周期类**两种不同的时序类型将调度模块进行分类，旨在同时满足时间延迟与硬件规模的限制，并提高信息调度效率。

- **事件类**：消息到达时工作，延迟预算宽松，不参与逐采样路径。
- **周期类**：每采样周期工作，须在时钟预算内跑完全部声部。

#### 1. 周期类模块

| 模块 | 职责 |
|---|---|
| 声部时序器 | 只产生声部索引与轮转节拍（`(组, 泳道)` 序列），不含取数逻辑 |
| 声部取数器 | 按索引并行取出声部上下文（声部表运行状态、通道表调制参数、音色表音色参数），送单声部处理；预取下一时隙参数以隐藏读延迟 |

#### 2. 事件类模块

| 模块 | 职责 |
|---|---|
| MIDI 消息解析 | 解析字节流、区分消息类型并分发；乐器端口的混音类 CC 丢弃 |
| 通道状态表编辑器 | 维护通道状态表（音量、声像、弯音、踏板、调制、发送量等） |
| 音色映射 | 由 `(bank_msb, program)` 查音色映射表，输出 `timbre_slot` |
| 鼓组映射 | 鼓通道（`bank MSB = 120`）内，由音符号查鼓组映射表输出 `timbre_slot` |
| 声部分配 / 释放器 | 声部分配、抢断、释放；写声部表的分配类字段；**鼓声部忽略 Note Off**；**互斥组内新音起时静掉旧音** |

**与周期类的关系**：分配器不直接改写计算路径正在使用的字段，而是通过「声部已分配 / 已释放」标记通知时序器。声部编号 → (组, 泳道) 的映射固定不变，保证每个声部延迟确定。

#### 3. 周期时序
由于系统受到时序和资源双重约束，故本系统采用并行泳道和串行组混合的工作方案：

| 约束       | 内容                           | 说明          |
| -------- | ---------------------------- | ----------- |
| 约束 A（时间） | 在 `T_s = 1/f_s` 内必须把全部声部算完一遍 | 采样率决定的时间预算  |
| 约束 B（资源） | 乘法器（DSP）总数有上限                | 器件硬件决定的资源上限 |

- **纯轮询**：一套运算单元分时跑 N 次 → 省 DSP，但耗时随声部数线性增长
- **纯并行**：N 套运算单元 → 省时间，但 DSP 直接 ×N
**混合模式 = 同时满足 A 与 B：P 条并行泳道 × G 个串行轮转组。**
**（1）时间计算**

基础时间量：

| 量 | 符号 | 值 |
|---|---|---|
| 音频采样率 | `f_s` | 48 kHz |
| 采样周期 | `T_s` | 20.833 µs |
| 系统时钟 | `f_clk` | **49.152 MHz** |
| 时钟周期 | `T_clk` | 20.345 ns |
| 每采样时钟拍数 | `N_cyc` | **1024** |

> `49.152 MHz = 12.288 MHz × 4`，而 `12.288 MHz = 256 × f_s`。
> 该时钟由板载 MS5351 合成后送入 FPGA（50 MHz 晶振无法得到 48 kHz 一族，见 [[硬件实现]]）。

声部处理的时钟分解（`P = 8`、`G = 4` 时）：

| 量 | 符号 | 值 | 说明 |
|---|---|---|---|
| 并行泳道数 | `P` | **8** | 硬件复制份数 |
| 串行组数 | `G` | **4** | 时间复用次数 |
| 声部总数 | `N` | 32 | `P × G` |
| 单声部流水线深度 | `L` | ~20 拍（待定） | 需 RTL 实测 |
| 全声部扫描耗时 | `G × L` | ~80 拍 | 占 `N_cyc` 的约 7.8%（`80 / 1024`） |
| 时钟余量 | `N_cyc − G×L` | ~944 拍 | 极充裕 |

> **分工依据**：`P` 由 **DSP 数量**决定（资源紧约束），`G` 由**时间预算**决定（时间极宽裕）。
> 故取较小 `P`（省 DSP）+ 较大 `G`（用掉宽裕的时间）。扩展声部数时**固定 `P`，只加 `G`**。
> **拓展方式**：固定 `P`，只加 `G`（`G` 只增加时间占用，不增加 DSP 与端口数）

延迟预算：

```
Note On → 出声
  = 解析 + 分配（事件驱动，若干拍）        ≈ 0
  + 采样对齐                             ≤ 1 个采样周期 `T_s` = 20.833 µs
  + 组等待                               ≤ (G−1) × L = 3 × 20 = 60 拍 = 1.22 µs
  ─────────────────────────────────────
  合计                                   ≈ 22 µs
```

对比赛题要求（基础 ≤ 10 ms，拓展 ≤ 5 ms）：**余量约 220 倍**。延迟瓶颈不在架构，而在 ADSR 起音时间与滤波器状态建立时间。

**整链路延迟预算**（自 MIDI 输入至模拟输出）：

| 环节 | 延迟 |
|---|---|
| MIDI 接收与解析 | 事件路径，不阻塞音频（不增加音频往返延迟） |
| 事件 → 声部表更新 | ≤ 1 个采样周期 `T_s` = 20.833 µs |
| 单声部流水线（DDS / ADSR / SVF / VCA） | < 1 µs（约 16 级 @ 49.152 MHz ≈ 0.33 µs，同一采样周期内完成） |
| 通道 / 全局处理（发送、效果、混音、主输出） | ≤ 2 `T_s` = 0.042 ms |
| I2S 串行输出 | ≤ 1 帧 = 32 BCK = `T_s` = 20.833 µs |
| PT8211 内部（8× 过采样 R-2R） | 手册未给群延迟，保守估 ≤ 0.2 ms（待实测） |
| XPT4809 耳放（AB 类） | ≈ 0（模拟器件，只贡献相移） |
| **合计（干路）** | **约 1.3 ms**，优于赛题 ≤ 5 ms |

> 三条效果器**不得串入干路**，故上表不含效果器；干路延迟与效果参数无关。

**（2）时间轴图**

以 `P = 8`、`G = 4`、`L ≈ 20` 为例：

```
|<---------------- T_s = 20.833 µs = 1024 拍 ---------------->|
|< 时隙0(组0) >|< 时隙1(组1) >|< 时隙2(组2) >|< 时隙3(组3) >|<-- 空闲 944 拍 -->|
```

## 七、合规性与验收

#### 1. 评分规则对应

- **独立发声单元**：含独立相位累加器、频率调控、包络控制的完整振荡器。发送总线、混音、混响 / 合唱 / 延迟**不计入**振荡器数。故本设计的核心目标是：**用最少的 DSP 与 BSRAM 把混音与效果做干净，把资源让给振荡器。**
- **吞吐量** = 同时活跃的独立振荡器数 × 实际输出采样率。**过采样不叠加加分**；输出采样率以送到 DAC 的实际 `f_s` 为准（由 BCLK / 32 决定），不是内部计算率。
- 本项目 32 复音时：`32 × 48.000 kHz = 1.536 M 振荡器样本/秒`。

#### 2. 测试模式（TEST_MODE，现场验证必需）

一键进入可验证状态：

- 关闭所有效果（`send_*` 全为 0、`master_wet = 0`）
- 关闭软限幅的动态增益（阈值设为 1.0，即固定增益）
- 32 个振荡器分配互不重合的频率（例：200 Hz 起，对数均匀分布到 8 kHz）
- 每声部幅度缩放 `1/N` 或 `1/√N`，避免叠加削顶
- 声像左右交替（L / R / L / R …），顺带验证声像与声道极性
- 可选：把主输出接 LED / WS2812 做简易电平指示

现场用频谱仪或示波器 FFT 数谱峰，即可佐证复音数。

#### 3. 合规红线

- 所有音频必须由 FPGA **逐音、逐样本实时生成**；波表只能是**单周期波形**，严禁任何形式的预录 PCM 或整段录音回放。
- 板上 AE350 RISC-V 硬核只能用于控制、UI、曲库与参数管理，**不得参与逐样本音频运算**。
