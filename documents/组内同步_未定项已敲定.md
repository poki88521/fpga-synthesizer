## 二、7 项敲定结果（逐条）

### ① 波表：**8 槽 × 2048 点 × 16 bit = 256 Kbit → 16 块 BSRAM**

| 项 | 定稿值 |
|---|---|
| 音色槽数 | **8**（`timbre_slot` **3 位**，0~7） |
| 每槽点数 | **2048 点**（表内索引取 `phase_acc[31:21]`，11 位；小数取 `[20:13]`） |
| 波表总深度 | **16384 点** = 8 × 2048 |
| 波表地址 | **14 位** = `{timbre_slot[2:0], phase_acc[31:21]}` |
| 插值相邻点 | 同槽内 `+1`，**槽末回绕到本槽首点**（不跳下一槽） |
| 容量 / 块数 | 256 Kbit / **16 块**（16 Kbit 模式） |
| `wave_sel` | 2 位（波表**索引**预留，与"槽数"是两个概念） |
| `.mi` 文件 | `Address_depth = 16384`，`Data_width = 16` |

**为什么选 2048 点/槽**：总容量锁 256 Kbit 时槽数与点数成反比；取 8 槽可满足赛题"≥2 音色"并留扩展，
且**总深度与扩展指南本来就写着的一致（都是 16384）**，以后加音色不必再动地址拼接。
2048 点 + 两点线性插值的量化噪声约 **−66 dBFS**，对单周期波形足够。

> ⚠ **对 majiao 的影响**：DDS 的波表读地址从"取 `phase_acc[31:20]`"改成
> "取 `phase_acc[31:21]` + 拼 `timbre_slot[2:0]`"，**并且要做槽末回绕**。

### ② VCA 归一化：**确定公式 + 推荐实现**

输入量程统一为 **Q1.15**（`env_value` 不再是 0~65535）：

```
voice_out = sat24( (audio_in × env_value × velocity_gain × vca_gain) >>> 45 )
```

- **右移量 = 15 × 3 = 45**（三个 Q1.15 系数各 15 位）
- 四个量**直接连乘、中途不截断、只在最后饱和一次** —— 这是"口径混用=增益出错"的正解
- 实现推荐 **控制率合并法**（与模块三既有的"三级增益合并"同一手法）：
  - `g_vt = (velocity_gain × vca_gain) >>> 15`（Q1.15）**在控制率**算（这两个量只在分配/换音色时变）
  - 采样率路径：`voice_out = sat24( (audio_in × env_value × g_vt) >>> 30 )`
  - 只需 **1 个 16×16（控制率）+ 1 个 24×16（采样率）**

> **ADSR 满量程相应改为 32767**（原来是 65535）。`attack_step = 65536/(ms×fs/1000)` 公式不变，
> 只是 `env_value` 寄存器取 `[15:1]` 或直接把上限设为 32767。

### ③ 采样率：**48.000 kHz 为唯一正式口径**

- 49.152 MHz / 1024 = 48.000 kHz（**正式**）
- 50 MHz / 1024 = 48.828 kHz（**仅 bring-up 验证用**，不是交付口径）
- 所有吞吐量/延迟指标按 **48.000 kHz** 报

### ④ 延迟上限：**512 ms**（`DLY_MAX = 24576` 点 @48 kHz）

- 文档原写"延迟限 500 ms"；现定 **512 ms**（略保守取整，满足预算）
- `fx_delay` 缓冲深度仍是 `MAXLEN = 32768`（2¹⁵，便于 BSRAM 按 2 的幂分配），
  但**延迟量在内部限幅到 `DLY_MAX = 24576`** ——已改 RTL 并在 `tb_fx_delay` 验证通过

### ⑤ `bend_ratio`：**128 项指数表 + 线性插值**

- 表 128 × 16 bit = **2 Kbit**；`bend_value`（14 位，中心 8192）取**高 7 位**查表、**低 7 位**插值
- 精度 **±1 LSB ≈ ±0.006%**，远超听感需要（曲线形状按 `bend_range` 缩放的指数律）

### ⑥ 效果参数 SysEx：**自定义厂商 ID 格式**

主音量沿用标准 Universal Real-Time SysEx（`F0 7F 7F 04 01 ll mm F7`，已写在 `MIDI协议.md`）。
效果参数在 MIDI 里**无标准 CC**，定稿为：

```
F0 7D <slot> <param> <val_hi> <val_lo> F7
    │   │      │        └────┬────┘
    │   │      │        16 位值的两个 7 位字节（MSB 先）
    │   │      └─ 参数号 0~15
    │   └─ 0=混响组 1=合唱组 2=延迟组
    └─ 0x7D = Educational / Non-Commercial 厂商 ID
```

- 参数号 0~5 对应各组参数的**声明顺序**（见 `技术文档.md` 效果参数表）
- `val_hi/val_lo` 拼成 16 位后按该参数的定义域裁剪（各参数定义域见参数表）

### ⑦ 周期类模块的**时序契约**（新增，`硬件实现.md` §8.5）

调度层的声部时序器/取数器与音频层的对接规范，定稿如下：

**声部时序器 → 通道处理层**：`slot`(2)、`slot_vld`(1，**单拍脉冲**)、`frame_stb`(输入)。
**硬性契约**：每采样**恰好发 G 个**脉冲、位置**固定**、**每脉冲 1 拍宽**、`slot` 顺序 `0..G-1`、
第一个脉冲距 `frame_stb` **至少 1 拍**（不能同拍）。
> 模块三已有可对照实现：`rtl/voice_slot_seq.v`（调度层可直接用或按同契约自写）。

**声部取数器 → 单声部层**：`vld`、`phase_inc`(32)、`wave_sel`(2)、`timbre_slot`(**3**)、
`f_coeff`/`q_coeff`(16)、`attack/decay/sustain/release_step`(16)、`gate`/`sustain_pedal`(1)、
`velocity_gain`/`vca_gain`(16)——**全部 × P 并行**。
**时序**：必须在**时隙开始前**稳定；单声部层在时隙边界采样它们，**不需要握手**；
取数器**预取下一时隙**（读延迟藏在上一时隙的计算时间里）。

**单声部层 → 通道处理层**：`aud_in`(24 × P)、`ch_in`(4 × P，**0~15 = midi_channel−1**)、`vld`(1 × P)。

**状态写回**：`phase_acc`(32)、`env_value`(16，Q1.15 满量程 **32767**)、`env_state`(3)、
`filter_ic1/2`(32×2)；**采样边界统一写回**，需写回缓冲（32 × ~100 bit ≈ 3.2 Kbit，寄存器）。

**通道状态表的读取方案**：**双缓冲 + 寄存器多读口**。
- 表本体**双缓冲**，**采样帧边界**切换 bank（与效果/主输出参数表同一提交时刻）
- 读取侧用**寄存器实现**（16 项 × 约 200 bit = 3.2 Kbit），配 `P` 个并行读口
- **不能用单口 BSRAM**：通道层要在**一个时隙内**并发用 P 个声部的通道参数，单口每拍只读 1 次会停拍
- 帧内读到的永远是**同一版本**，不会"半新半旧"；因此效果参数**双缓冲足够，不需要三缓冲**

### ⑧ 通道号基准：**MIDI 通道 1~16 ↔ 内部 `ch_addr` 0~15**

- MIDI 消息里的通道号是 **1 基（1~16）**，内部 `ch_addr` 是 **0 基（0~15）**
- 换算：`ch_addr = midi_channel − 1`。**仅此一处换算**，其余全用 0 基
- 文档里"通道 1"指 MIDI 通道 1，对应 `ch_addr = 0`
