- Setup 违例 **0**，Hold 违例 **0**，TNS 全 0；音频域（49.152 MHz）Fmax **49.352 MHz**，最差 slack **+0.082 ns**

- P&R 耗时 22 min（22:44:57 → 23:06:59）

## 本版唯一改动：波表槽 0（钢琴）的 5 次分音 −11 dB

**背景（诊断结论）**：“和弦震荡感” = 等律大三度的 5:4 近似造成的 **10.3 Hz 拍频**，
来自 **C4 的 5 次分音(1308.17 Hz) × E4 的 4 次分音(1318.50 Hz)**，不是 RTL bug。

```
录音实测（record10）：1308.17 与 1318.50 Hz 两根独立谱线，相距 10.33 Hz
                     1290–1330 Hz 带内包络在 10.25 Hz 处有 43% 深度的调制
                     同段 520 Hz 带、1046 Hz 带无任何调制峰
用户听测：            C4+C5（八度，分音精确重合）无拍频  ⇒ 确认是拍频
```

**改法**：只改 `data/wave_table.hex` 槽 0 的 2048 行——

- 5 次分音 **−24.6 → −35.6 dB**（衰减 11 dB），其余分音（4/3/2/7…）**完全不动**
- 峰值归一化回 31831（响度不变），槽 0 RMS 18640 → 18373（−0.13 dB）
- 其余 7 个槽**逐行逐字节不变**；文件大小 98,304 B、换行符 CRLF 均保持

**为什么压 5F 而不是 4F**：包络纹波幅度 = `2·min(a₅F, a₄F)`，当前 `min` 就是 5F。
只压 4F 会让 `min` 不变而载波变轻，**相对**拍频反而从 30% 升到 76%。

**预期效果**：拍频纹波 0.1172 → 0.0330（**−11 dB**），相对 4F 载波 30% → 8%。

**已验证**：按位平面重建综合网表里的 pROM（16 块 × 64 个 `INIT_RAM_XX`，`bit i = 地址 i`）逐地址比对：
对当前新表 **0 / 16384 不一致**；对改前旧表 2047 / 16384 不一致（正好是改动的样点）。

> ⚠ 本目录**额外**收了 `wave_table.hex`（98,304 B，SHA256 前 16 位 `0EAC4AD4B2B6CABF`），
> 这是既有存档没有的文件——因为本版的全部意义就是波表数据变了，收了才能复现位流。
> 回退：`data/wave_table.hex.bak_20261102_2210`（同目录 `.bak_20261102_2210` 也在 `wave_table/out/`）。

## 时序：转正了，但**不是**改波表的功劳

- 资源与 baseline_J 完全相同 ⇒ 波表数据不参与布局布线。−0.082 → +0.082 ns 是这一轮 P&R 布局抽签更好。
- **音频域余量只有 0.4%**（0.082 / 20.345 ns），历史在 ±0.08 ns 之间摆动
  （baseline_H +0.025 → baseline_I/J −0.082 → 本版 +0.082）⇒ **别再往 49.152 MHz 域加逻辑**。
- 最差路径仍是老家族：`u_full_top/rst_sync_2_s0/Q → u_master/g_lim.u_lim/env_d1_*_s0/D`
  （数据延迟 20.204 ns 里几乎全是布线，skew 仅 0.007 ns）；第二名
  `u_fx/g_rev/u_rev/rmem_rmem_1_5_s/DO[0] → ret_l/r_*`（+0.137 ns）。
- baseline_H 加的“本地复位再同步”寄存器（`rst_n_l` / `rst_n_meta`）**仍在网表里**，
  但这条路径依旧排第一 —— 说明综合/布局把这级同步的作用吃掉了，以后可单独立项。

## 录音链警告（重要，别再被它带偏）

`develop/material/audio/*` 全部是**手机 .m4a（AAC）**：record10 只有 65 kbps，
频谱在 **15.5–16 kHz 有硬砖墙**、16 kHz 以上噪声底 −123 dB、整体频响被麦克风/扬声器向 1.3–2 kHz 抬了约 30 dB。

⇒ 里面的 **68.1 Hz 边带梳**（= f(E4)−f(C4)）、200–2000 Hz 带的 67.4 Hz 振幅调制，
**不能归罪于 FPGA**（多半是扬声器/手机过载）；“record10 峰值 0.205 FS”是**手机满刻度**，不是 FPGA 的 FS。
判数字域必须抓 **BCK/WS/DIN** 或 `dbg_sd`。
