## 五、烧录与测试注意

1. **Programmer 里必须重新 Add File**，并核对列表里显示的时间戳等于该存档的时间
   （`23:06` / `20:34` / `20:59` / `12:13` / `17:07` / `20:28` / `18:14`），否则可能烧的是旧内容。
2. 本项目一直用 **SRAM 烧录**（掉电即失）→ 每次上电都要重烧；**烧完别按复位**。
3. MIDI 输入当前接在 **C21（乐器口）**：
   - 音符 / 力度 / CC1(颤音) / CC11(音量) / CC71/73/74 都可用；
   - **CC7 / CC10 / CC91 / CC93 / CC94 只在 A17（混音口 port3）生效**，要测效果器得把线挪到 A17。
4. 每份存档里的 `full_system.cst/.sdc/.gprj` 是**当时的**约束与工程文件，
   若用其它版本的源码配这份位流做对照，注意约束可能已经变过。
5. **判断「数字域有没有问题」不要用手机录音**：`develop/material/audio/*` 全是 `.m4a`（AAC，
   record10 只有 65 kbps），频谱在 **15.5–16 kHz 有硬砖墙**、16 kHz 以上噪声底 −123 dB，
   整体频响被扬声器/麦克风向 1.3–2 kHz 抬了约 30 dB。
   要判数字域请抓 **BCK/WS/DIN**（逻辑分析仪，BCLK 1.5 MHz）或 `dbg_sd` 的 1-bit 流。

## 八、历史经验

**baseline_H 期间得出（仍然有效）**

```
· 全局 rst_n 是高扇出网络；PRIMARY/LW 用满（8/8）后只能走通用布线，
  单条复位路径可以慢到 21.9 ns ⇒ 任何大模块都可以用「本地 2 级复位同步 + 同步复位」化解
· 音频域 49 MHz 下**禁止**「寄存器数组 + 变量索引」（32 选 1 读写 = 27.5 ns，
  实测 588 个违例）；需要数组就放 BSRAM，或改成「单状态扫描」
· 频谱最终成功版用的是 rtl/vis/spec_band.v（534 行，单点扫描式）
```

**2026-11-02 追加（baseline_K 期间）**

```
· 波表数据改动**不会**让时序变好或变差：K 与 J 资源一个不差，slack 从 −0.082 到 +0.082
  只是布局抽签。音频域余量只有 0.4%（0.082 / 20.345 ns），
  **任何往 49.152 MHz 域加的逻辑都必须先看 .tr**
· 最差路径仍是 `rst_sync_*_s0 → u_master/g_lim.u_lim/env_d1_*`（G 之后一直没离开第一）：
  20.2 ns 数据延迟里几乎全是布线，skew 仅 0.007 ns。
  H 加的本地复位再同步寄存器（`rst_n_l` / `rst_n_meta`）在网表里还在，
  但没能把这条路径挤出第一 —— 想让音频域彻底脱离抽签，只剩这一处可动
· 「和弦震荡感」定性：等律大三度 5:4 ≈ 10.3 Hz 拍频（C4 5F × E4 4F），**不是 RTL bug**；
  用录音验证时注意 §五.5（手机录音不可用于数字域取证）
```

**2026-11-03 追加（baseline_L 期间 —— 上面那条"10.3 Hz 拍频"的定性被推翻了）**

```
· ❌ 上面 K 期间的结论是**错的**：5F 衰减 11 dB 上板后，C4+E4 的震荡**毫无变化**
  ⇒ 10.3 Hz 那对分音不是主因。错在拿手机录音（AAC）做数字域取证 ——
  当时总包络其实是平的，我却把"1.3 kHz 窄带里 43%"当成了主因。
· ✅ 真正有用的判据来自**用户的听测**：单音没有 / 几十 Hz 嗡嗡（不是慢拍频）/
  program 0-3 四个音色都有 / 力度 127→40 不变 / CC1=0。
  ⇒ 只有"互调（差频）"能同时满足，且与波表分音、颤音、电平触发都无关。
· ✅ C24（dbg_sd，1 位 ΣΔ）是**唯一能做数字域取证的手段**：
  按「均值 1.65 V = 0 FS、±1.65 V = ±1.0 FS」解码，
  单音 C4 = 0.565 FS、C4+C5 = 0.740 FS、C4+A4 = 0.763 FS
  ⇒ 双音峰值正好压在 soft_limiter 的 0.75 FS 阈值上、离 24 位硬饱和只差 2.4 dB，
    而单音完全在阈值下 —— "单音干净、双音嗡嗡"与电平台阶完全吻合。
  ⚠ 抓 C24 必须 ≥200 kSa/s × ≥1 s；20 kSa/s × 60 ms 那种会被 SD 残余纹波混叠污染。
· 增益 stage 才是本设计最脆的地方：主音量 ×8 让双音恰好落在软限幅拐点上。
  L 版把它改成 ×4（−6 dB）后嗡嗡明显减弱但没完全消失 ⇒ 剩余部分在模拟侧（DAC/功放/耳机）。
  再降一档就是 SHIFT=14（再 −6 dB）。
· 综合/网表级验证的小技巧（本次用过，很值）：
  - 波表：按**位平面**重建 pROM（16 块 × 64 个 INIT_RAM，`bit i = 地址 i`），逐地址比对 hex；
  - 移位参数：在 .vg 里找 `norm_sat` 特化模块的位切片（SHIFT=13 ⇒ `acc_r[36:13]`，SHIFT=12 ⇒ `[35:12]`）。
```
