## 一、通用问题（跨模块）

### 1.7 可综合性红线

- 不用 `initial` 赋初值（除 FPGA 支持的 BRAM 初值）
- 组合逻辑分支必须覆盖所有情况，否则产生 latch
- 不用 `#delay`（仅仿真）
- 时钟信号不要走普通逻辑；高云由工具自动把 PLL 输出接入全局时钟网络（GCLK）

## 二、调度层

### 2.1 MIDI 消息解析

**位定时**

**`f_clk` 已定为 `49.152 MHz`**（见 `documents/硬件实现.md` §2.2）：

| `f_clk` | 商（`f_clk / 31250`） | 处理方式 | 误差 |
|---|---|---|---|
| **49.152 MHz（已定）** | 1572.864 | 固定计数 **1573** | **0.0087%** |

**结论**：不是整除，用固定计数 **1573** 即可 —— 0.0087% 远小于 UART 容差（±2%），**不需要累加器**。

> （50 / 100 / 96 / 76.8 MHz 是此前的**备选时钟方案**，现已不采用。）

若需更高精度或 f_clk 不整除，可用**累加器**（相位累加方式）保证长期平均准确：

```
acc <= acc + 31250;                 // 或按位宽缩放的等价值
if (acc >= f_clk) begin
    acc <= acc - f_clk;
    // 一个 bit 的时间到
end
```

注意：**累加器保证的是平均频率，单 bit 会有 ±1 拍的抖动**。`49.152 MHz` 下固定计数 1573 的误差仅 0.0087%，**已足够，无需累加器**。

**接收流程**：
1. 空闲线上为 1，检测 **1→0 跳变**为起始位
2. 等 1.5 bit（采到起始位中心）后开始按位间隔采样 8 个数据位
3. 采停止位校验

**运行状态（Running Status）**
- 需要保存「当前状态字节」
- 清除条件：收到 `0xF0`–`0xF7`（System Common / SysEx）
- 保持条件：收到 `0xF8`–`0xFE`（Real-Time）
- **实时字节可插入任意位置** → 解析器要在每个字节位置先判断 `≥ 0xF8`，是则旁路处理，不计入数据字节计数

**SysEx 保护**【建议】
- 长度可变，若 `0xF7` 一直不来会卡死 → 需要**超时计数**或**长度上限**，超限则丢弃并复位解析状态

**多路输入**
- 乐器端口 ×3 + 混音器端口 → 4 路 UART
- 【待确认】4 路是各配一个解析器，还是共用一个（需要仲裁）？
- 若是共用 → 需要输入选择/仲裁逻辑，且要保证不丢失（FIFO 深度？）

**信号极性**【待确认】
- MIDI 输入经 6N138 光耦，输出通常**反相** → 接入 FPGA 后可能需取反
- 需按实际电路确认（属硬件侧）

**混音类 CC 丢弃**
- 乐器端口的 CC7 / CC10 / CC91 / CC93 / CC94 直接丢弃
- 【建议】在解析器出口加一个按端口号 + CC 号的过滤

### 2.2 通道状态表编辑器

**读写冲突**：见 `documents/硬件实现.md` §七「表读写」（待写缓冲 + 采样边界提交；效果 / 主输出表双缓冲）。

**参数派生**（7 bit → 16 bit 的转换）需要**查表**：

| 派生 | 方法 | 资源 |
|---|---|---|
| `pan` → `pan_gL` / `pan_gR` | 等功率表（正弦/余弦） | 128 项 × 2 × 16 bit ≈ 4 Kbit |
| `bend_value` → `bend_ratio` | 指数表或分段线性 | 需确认精度要求 |
| CC1 → `vibrato_depth` | 查表或线性缩放 | 小 |

**待用值缓存**
- `bank_msb` / `bank_lsb` 须缓存，收到 Program Change 时才一起生效（文档已述）

**输入范围检查**
- CC 值域 0–127，需确认是否需要限幅（异常数据保护）

### 2.3 音色映射 / 2.4 鼓组映射

- 规模小（`[bank][program]`），【建议】用**组合逻辑 ROM / LUT** 而非 BRAM
- 需确认是**组合输出**还是**打一拍**，这影响分配器的时序

### 2.5 声部分配 / 释放器

**寻找空闲声部**
- 扫描 N 个声部的 `state` → 优先级编码器
- N = 32 时是 32 输入的优先级编码，一拍可完成
- 【待确认】是否需要「同一 Note 重复按下」的特殊处理（文档提到「同音处理」但未定义规则）

**抢断（voice stealing）**
- 需要找 `age` 最大（最老）的声部
- 32 输入比较树，可流水
- 【待确认】抢断时是否需要**淡出**避免爆音？（直接切断会有 click）

**互斥组静音（镲互斥）**
- 需遍历比较 `excl_group` 与 `channel`
- 【建议】维护一个「组占用位图」比遍历 32 个声部更快
- 【待确认】`excl_group` 的比较范围是**同通道内**还是**全局**？

**鼓声部忽略 Note Off**
- 按声部表的 `drum_mode` 位判断（已在声部表）

**与周期类的交互**
- 只发「已分配 / 已释放」标记，不直接改写计算路径正在用的字段（文档已述）
- 【建议】用一个小 FIFO 传递分配事件，时序更干净

### 2.6 声部时序器

- 本质是**计数器 + 索引生成**，逻辑很浅
- 【建议】时隙边界与采样边界对齐（用 `f_s` 的节拍复位计数器）

### 2.7 声部取数器【重点】

**多路并发读**：见 `documents/硬件实现.md` §7.5（声部表按泳道分 bank；音色表 / 通道表参数预取）。

**预取流水线**
- 需要 P 组寄存器缓存（每组的字段位宽之和约 200~300 bit）
- 【建议】`P = 8`（已定）时约 **1600~2400 FF**，很便宜

**写回**
- 运行状态字段（`phase_acc`、`env_value`、`filter_ic*`、`lfo_phase`）要写回声部表
- 【待确认】写回时机是「算完立即写」还是「采样边界统一写」？前者时序紧，后者需要额外缓冲

**参数分发**
- 把取到的参数按字段送到单声部处理层的各模块 —— 需要仔细规划布线
