## 二、🔴 完全未覆盖的硬性要求（**优先级最高**）

### 1. 多维交互控制（基础要求 1 —— **不做则基础项不达标**）

**现状**：系统只有 MIDI 串行输入，**没有任何传感器交互**。

**要做的事**：
- 选定 ≥2 个独立维度，例如：
  - **电容触摸**（音高选择 / 滑音条）
  - **光电 / 压力**（力度、触后）
  - **无接触手势**（如 IR 距离 → 表情）
- 传感器 → FPGA 的采集逻辑（ADC / 电容感应 / 定时器）
- 与现有 `midi_filter` 并列，**新增一条"自研交互 → 调度层事件"的通路**
- **建议复用调度层**：把传感器事件编码成与 `ev_note`/`ev_cc_*` 等价的内部事件，避免改动合成层

**关键**：赛题明确"**自主设计演奏交互形态**"，这是**设计题的核心得分点**，不只是加分项。

### 2. 可视化反馈（拓展 3b）

四选一即可（建议从易到难）：
- **LED 演奏指引**（最简单，只需 GPIO + 状态机）
- **实时频谱 / 波形显示**（需 FFT 或峰值检测 + 显示驱动）
- **李萨如图形**（X/Y 两路音频 → 示波器式显示）

**注意**：拓展 3 的"延迟 ≤5ms"和"可视化"是**同一条要求的两半**，只做一半可能拿不到该条分。

### 3. 脱机 LED 曲目指引 + 蓝牙/App（拓展 4）

- **脱机曲目指引**：Flash 存曲目 → LED 按节拍提示 → 可叠加"是否跟上"判定
- **蓝牙联动**：板上载 BLE 颗粒，可做手机 App 通信

## 三、⚠️ 部分覆盖 / 需补齐的

### 1. 演奏表情维度不足（拓展 2a 要求 ≥3 维）

| 维度 | 状态 |
|---|---|
| 力度（Velocity） | ✅ 已实现 |
| **滑音（Pitch Bend / Portamento）** | 🔴 **未实现**（`chan_table` 已有 `ct_bend_ratio`/`ct_bend_value`/`ct_bend_range`，**只是没通到声部层**） |
| **颤音（Vibrato / LFO）** | 🔴 **未实现**（声部表有 `V_LFO` 字段，**完全没人用**） |
| 音量 / 声像 / 表情 CC | ✅（算表情但不一定是"演奏维度"） |
| **延音踏板** | ✅（调度层负责） |

**Pitch Bend 的接法**（`voice_fetch.v` L254-257 已标明位置）：
```
声部表加 V_BEND 字段 → note2inc() 里乘 bend_ratio 再右移 15
⚠ 还需一条"更新已发声部"的路径（弯音不只影响新音）
```

**颤音**：正好可以把闲置的 `lfo_phase` 字段用起来。

### 2. 延迟指标（基础 ≤10ms / 拓展 ≤5ms）—— **必须实测**

**测量方法**：
- 输入一个 MIDI Note On，同时用示波器测 I2S 数据线的第一个非零样本
- 或用 `TEST_MODE` 让 FPGA 在收到事件的同一拍翻转一个 GPIO，测到音频输出的时间差

**理论值可先估算**（供对照）：
```
MIDI 串行接收：10 bit × 32 µs = 320 µs（最坏）
调度层分配：扫描 32 声部 + 提交 + 预取 ≈ 数个帧（帧 ≈ 20.8 µs）
音频链路流水线：若干采样
```

### 3. 复音数 32 —— **恰好达标，没有余量**

`P=8 泳道 × G=4 时隙 = 32`。评分现场若要求"可观测的 32 条独立谱峰"，需要：
- `TEST_MODE` 同时点亮 **32 个声部**且各发不同频率
- 资源上可行（当前 LUT 17%、DSP 42%、BSRAM 48%，有余量）
- ⚠️ 但 `soft_limiter` 有 566 个时序违例，32 路满负荷时风险更高——建议评审前解决

### 4. 现场验证工具链 —— **评分要用，必须准备**

赛题明确要求"**频谱可观测对应数量独立谱峰**"。需要：
- `TEST_MODE` 输出 N 路不同频率正弦（已有基础）
- **PC 端 FFT 分析脚本**（可录制 I2S 输出后分析）
- **或**直接给出音频文件 + 频谱图，供评委核对

### 5. 效果器参数表

`fx_delay` / `fx_chorus` / `fx_reverb` 的系数目前应该也是常量，与音色参数表同样需要"参数表 + 写口"。

## 四、技术性遗留（不影响赛题达成，但影响功能完整度）

### 1. 🔴 音色映射在 `vtab` 之后断掉（**当前未解决**）

**已实测确认调度层完全正常**：
```
midi_filter 发出 PC 事件 ✓ → chan_table 写入 program=5 ✓ → rd_program=5 ✓
→ timbre_map.tm_slot=5 ✓ → awr_timbre=5 ✓ → vtab[9][188:186]=5 ✓
```
**断点范围**：`vtab[V_TIMBRE]` → 预取 `pf_timbre` → `dds_voice.timbre_slot` → `{timbre_slot, idx}` → `wave_fetch` → `wave_table_rom.addr`

**已排除**：波表数据（8 槽确实不同）、字段地址、`aw_q` 打包、预取代码

**下一步**：修 `tb_timbre_e2e.v` 的打印位置（`$finish` 有多个），用 ROM 实际读地址高 3 位直方图对比 `+pc=0` / `+pc=5`

**⚡ 顺带先验一个假设**：`DEF_F_COEFF = 30000` 对应多少 Hz？
`fc = fs/π × asin(30000/32768)`，若偏低则**所有波形被固定低通滤平**，会独立造成"音色都一样"。

### 2. 音色参数表（功能完整度关键）

`voice_mono` 的滤波/包络参数全是 `full_system.v` 的 `DEF_*` 常量：
```
DEF_F_COEFF=30000  DEF_Q_COEFF=16384  DEF_FILTER_TYPE=0  DEF_WAVE_SEL=0
DEF_ADSR_CURVE=0  DEF_ATTACK_STEP=5  DEF_DECAY_STEP=20
DEF_SUSTAIN_LEVEL=20000  DEF_RELEASE_STEP=8
```
**8 个音色槽共用同一套滤波/包络**——换音色只换波形，不换"性格"。

**好消息**：`chan_table` 已输出 `ct_cutoff`/`ct_reson`/`ct_attack`/`ct_release`，只是没通到声部层；
`sched_subsystem.v` L25-27 注释已预告路径——"等音色表落地后，`pf_*` 再扩出这些字段即可，**端口不用改**"。

### 3. `soft_limiter` 时序违例（566 个）

```
Setup Violated: 566    TNS: -2851.8 ns    最差 slack: -25.907 ns
路径：master_volume 输出 → soft_limiter 内部寄存器（全程无流水）
```
方案已写好并验证（3 级流水，`tb_limiter` 5 项全过），代码存档 `scratch/agent/soft_limiter_流水线版备查.v`。**按决定暂不启用**——但**评审前建议解决**。

> ⚠️ **"P&R 没报错" ≠ "时序合格"**。Gowin 不会因违例中止，照常出 `.fs`。
> 每次 P&R 后必须主动看 `impl/pnr/full_system.tr` 的 `2.4` / `3.1.1` 节。

### 5. 音色映射真表 + 多库

当前恒等映射（**只取低 3 位**，`program 8` 回到槽 0，**每 8 个循环**）。
换真表只需改 `timbre_map.map_fn` 为 ROM 查表，**端口与握手不用改**。

### 6. 波表扩容

8 槽 × 2048 点 = 16384 点，用 16 块 BSRAM（`163/340`，**还剩 177 块**，可再放约 11 倍）。
若要放多周期长采样（钢琴/吉他真实采样），需外扩 SDRAM——板上有 DDR 颗粒。

## 6.2 音色映射：**已确认 RTL 正确，问题不在代码**

用端到端探针（`simulation/tb/tb_timbre_e2e.v`，支持 `+pc=N`）直接统计 `wave_table_rom` 实际读地址的高 3 位：

```
pc=0 → SLOT 0 : 5163350 hits        （槽 1~7 全 0）
pc=5 → SLOT 0 : 5153426 hits
       SLOT 5 :    9924 hits        ← 地址高 3 位确实变成了 5
```

**整条通路完全打通**：`PC → chan_table → timbre_map → awr_timbre → vtab[V_TIMBRE] → 预取 → dds_voice → wave_fetch → ROM 地址`。

**所以上板"音色切换无效"的原因只剩**：**板上跑的是改动前的比特流**（用户确认"还在用上次那个"）。
