## 一、🔴 音色参数表（**最大缺口**，优先级最高）

### 现状

`voice_mono` 需要的音色参数**全部是 `full_system.v` 里的常量**：

```verilog
parameter integer DEF_F_COEFF       = 30000,   // SVF 频率系数
parameter integer DEF_Q_COEFF       = 16384,   // SVF 阻尼
parameter integer DEF_FILTER_TYPE   = 0,       // 0=LP 1=BP 2=HP
parameter integer DEF_WAVE_SEL      = 0,
parameter integer DEF_ADSR_CURVE    = 0,
parameter integer DEF_ATTACK_STEP   = 5,
parameter integer DEF_DECAY_STEP    = 20,
parameter integer DEF_SUSTAIN_LEVEL = 20000,
parameter integer DEF_RELEASE_STEP  = 8,
```

**后果**：8 个音色槽**共用同一套滤波/包络参数**——换音色只换波形，不换音色"性格"。

### 好消息：通道表里**已经有**这些字段

`chan_table` 已输出（只是没通到声部层）：

```
ct_cutoff  ct_reson  ct_attack  ct_release
```

### 要做的事

1. 新建 `rtl/scheduler/timbre_param.v`（音色参数表）
   - 输入 `timbre_slot[2:0]`，输出 `wave_sel / f_coeff / q_coeff / filter_type / adsr_curve / attack_step / decay_step / sustain_level / release_step`
   - 规模小，用组合 LUT 即可，不必 BSRAM
2. `voice_fetch` 的 `pf_*` 预取口**扩出这些字段**（`V_*` 地址续在 `224` 之后）
3. `voice_mono` / `dds_voice` / `svf_voice` / `adsr_vca` 增加对应输入，替换 `DEF_*`
4. `sched_subsystem` 的例化把常量换成查表输出

**接口红利**：`sched_subsystem.v` L25-27 的注释已经预告了这条路——"等音色表落地后，本模块的 `pf_*` 再扩出这些字段即可"，**端口不用改**。

## 二、🟡 Pitch Bend / 调制轮

### 现状

- `chan_table` 已输出 `ct_bend_ratio`、`ct_bend_value`、`ct_bend_range`
- **但 `voice_fetch.note2inc()` 里没有乘 `bend_ratio`**，声部表也没有 `bend_ratio` 字段

`voice_fetch.v` L254-257 的注释写明了位置：

```verilog
//  ⚠ 本函数不含 bend_ratio 调制：文档要求
//     phase_inc = (phase_inc_base × bend_ratio) >>> 15（Q1.15），
//     但声部表里目前没有 bend_ratio 字段（弯音轮未接）。
//     接弯音时在此乘一次即可，调用点不用改。
```

### 要做的事

1. 声部表加 `V_BEND` 字段（16 位 Q1.15）
2. `apply_alloc` 里写入；**弯音变化时**需要一条"更新已发声部"的路径（不只是分配时锁定）
3. `note2inc()` 里乘 `bend_ratio` 并右移 15

**调制轮（CC1）** 目前完全没处理，需要单独加一条事件路径。

## 五、🟢 音色映射真表 + 多库

- 当前 `timbre_map.map_fn` 是**恒等映射** `timbre_slot = program[2:0]`
- **只取低 3 位**，所以 `program 8` 会回到槽 0（**每 8 个循环一次**，调试界面别列 128 个）
- `bank_msb` / `bank_lsb` 已在 `chan_table` 里缓存，但**未参与映射**

### 要做的事

1. `map_fn` 换成 ROM 查表：`timbre_rom[{bank_msb[1:0], program}]`
2. **端口与握手都不需要改**（`timbre_map.v` 的设计如此）

### 音色槽数的上限

当前 3 位 = 8 槽。要扩到 16/32 槽需要：
- `timbre_slot` 加宽（影响声部表字段、波表地址位宽）
- 波表总深度翻倍（当前 16384 点 = 16 块 BSRAM，余量还有 340-163 = 177 块）

## 六、🟢 波表扩容 / 外扩存储

- 当前 8 槽 × 2048 点（每槽 1 个周期），**只有 16 块 BSRAM**
- BSRAM 总余量：`163 / 340`，**还剩 177 块**（可再放 ~11 倍）
- 若要放**多周期长采样**（钢琴/吉他真实采样），需要外扩 SDRAM/DRAM——板上有 DDR 颗粒

## 十、🔴 当前未解决的 bug：音色映射在 `vtab` 之后断掉

**这是明天要继续查的**。

### 已实测确认（调度层完全正常）

```
midi_filter 发出 PC 事件          ✓
chan_table 写入 program: ch=0 val=5 ✓
rd_program=5 → ch_prog_num=5      ✓
timbre_map.tm_slot=5              ✓
awr_timbre=5                      ✓
apply_alloc 写入 vtab[9][188:186]=5 ✓
```

### 现象

上板发 `pc 0`~`pc 7` 音色全一样；且**不发 PC**、弹 note 60~67 时**8 个音也全一样**
（说明跑的是**新比特流**，`timbre_slot` 恒 = program = 0，不再跟 note 走）。

### 断点范围

`vtab[V_TIMBRE]` → **预取 `pf_timbre`** → `full_system` → `voice_mono` → `dds_voice.timbre_slot` → `{timbre_slot, idx}` → `wave_fetch` → `wave_table_rom.addr`

### 已排除

- 波表数据：**8 个槽确实不同**（正弦/三角/方波/锯齿，频谱已确认）
- 字段地址：`V_TIMBRE=188:186` 无重叠；`aw_q` 打包位 `e[28:26]` 与 `apply_alloc` 一致
- 预取代码：`wire [224:0] it = vtab[vid]` 覆盖到 bit 188，`pf_timbre <= it[188:186]`

### 下一步

修 `tb_timbre_e2e.v` 的打印位置，用**实际 ROM 读地址高 3 位的直方图**对比 `+pc=0` 与 `+pc=5`：
- 分布变了 → 地址段正常 → 查滤波器是否抹平差异
- 分布不变 → 断点在 `wave_fetch` / `dds_voice` 的地址拼接

### 另一个待验证的假设

`DEF_F_COEFF = 30000`（`sin(πfc/fs)` 的 Q1.15 表示）→ 截止频率约 **`fs/2 × 30000/32768 ≈ 22 kHz`**？
如果换算下来截止频率偏低，**所有波形的谐波差异会被低通抹平**——这会独立导致"音色都一样"。
**值得先把这个系数换算成实际 Hz 确认一下。**
