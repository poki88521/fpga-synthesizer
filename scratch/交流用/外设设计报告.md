## 一、结论摘要

**任务**：赛题中有四处涉及"外设"，其中**两处是基础要求**（不做则不达标），两处是拓展加分。

**结论**：
1. 建议采用 **8 弦光电门阵列**作为核心演奏交互——**一个传感器同时提供三个演奏维度**（选音/触发/力度），全数字接口、µs 级延迟，直接命中基础要求 1 的"选音、触发、拨弦、力度感应"四个词。
2. 可视化建议用 **WS2812 灯带 + 片上 64 点 FFT**，可同时表达"频谱/波形/演奏指引"三项，开销小且与音频通路解耦。
3. **脱机 LED 曲目指引不需要任何新增硬件**，是性价比最高的一项拓展；但必须存 **MIDI 事件流**而非音频，否则触碰"严禁预录 PCM"红线。
4. 引脚不是瓶颈：板卡 202 个 IO，当前仅用 6 个。
5. 已核实三项与既有认知不同的事实（见 §六），其中一项**排除了一个此前认为可能的原因**。

## 三、交互传感设计（核心）

### 3.1 方案选型对比

| 方案 | 可得维度 | 接口 | 延迟 | 需要外购 | 结论 |
|---|---|---|---|---|---|
| **光电门阵列** | **3**（音高/触发/力度） | **纯数字 GPIO** | **µs 级** | 红外对管（便宜） | ✅ **推荐** |
| 电容触摸 | 2（有无/位置，**无力度**） | GPIO + RC 扫描 | µs 级 | 需自制电极板 | 备选 |
| 压力检测（FSR/压电） | 1~2（力度为主） | **需 ADC** | µs 级 | FSR 较贵 | 可作为力度补充 |
| 无接触手势 | 2~3 | ADC / 专用模块 | **ms 级** | 模块较贵 | ❌ **与 ≤5 ms 目标冲突** |
| 霍尔 + 磁铁 | 1（连续位置） | **需 ADC** | µs 级 | 便宜 | 作为滑音维度补充 |

**选型理由**：光电门阵列是唯一**同时满足**"≥2 维、µs 延迟、全数字接口、低成本、易调试"的方案。

### 3.2 工作原理

```
        槽 1          槽 2                    槽 8
   红外LED ─▶│   红外LED ─▶│   ...     红外LED ─▶│
            │            │                     │
   光敏管 ◀──┘   光敏管 ◀──┘            光敏管 ◀──┘
            ↑
        手指穿过此槽 = "拨这根弦"
```

**同一个传感器给出三个独立维度**：

| 演奏动作 | 传感器信号 | 映射到 | 对应赛题要求 |
|---|---|---|---|
| 手指进入**哪个槽** | 8 路中哪一路变化 | 音符号（槽位 → 音高） | **选音** |
| 光路**被打断的瞬间** | 电平跳变沿 | Note On 事件 | **触发 / 拨弦** |
| 光路被挡**持续的时长** | 上升沿到下降沿的时间差 | 力度值（速度越快力度越大） | **力度感应** |

### 3.3 力度的实现原理（关键设计）

**物理依据**：手指穿过光路的速度越快，遮挡持续时间越短。

```
快速拨弦   → 遮挡 ≈ 1~3 ms   → 力度大（相当于力度值 110~127）
正常拨弦   → 遮挡 ≈ 5~10 ms  → 力度中（70~100）
缓慢划过   → 遮挡 ≈ 15~30 ms → 力度小（30~60）
```

**换算公式**：
```
vel = VEL_MAX − (block_us − T_FAST) × K
      钳位到 [1, 127]

建议取值：T_FAST = 1000 µs，T_SLOW = 30000 µs，K = (VEL_MAX − VEL_MIN) / (T_SLOW − T_FAST)
```

**实现代价**：仅需一个**自由运行的时间戳计数器**（49.152 MHz 下分辨率 20.3 ns，远超需求）+
上升沿锁存 + 下降沿相减。**无额外器件**。

> 设计要点：把"遮挡时长"当力度是**演奏界公认做法**（电子鼓、光电子琴都用），
> 物理直觉与音乐直觉一致——拨得快本来就该响一点。

### 3.4 硬件设计

**电气连接（每一路）**：
```
3.3 V ──[150 Ω]── 红外发射管 ── GND

3.3 V ── 光敏三极管(集电极→发射极) ──┬── FPGA 输入引脚
                                     └──[10 kΩ]── GND
```
- 有光（未遮挡）→ 光敏管导通 → FPGA 读到**低电平**
- 挡光 → 光敏管截止 → FPGA 读到**高电平**
- 因此"手指进入"对应**上升沿**，与直觉一致

**BOM（8 弦）**：

| 器件 | 规格 | 数量 | 预估单价 | 备注 |
|---|---|---|---|---|
| 红外发射管 | 940 nm，5 mm | 8 | 低 | 限流电阻 150 Ω |
| 红外接收管 | 光敏三极管 | 8 | 低 | 配 10 kΩ 下拉 |
| 电阻 | 150 Ω / 10 kΩ | 各 8 | 极低 | |
| 支架 | 3D 打印或亚克力 | 1 套 | 低 | 8 槽，槽距约 15 mm |
| 杜邦线 / 洞洞板 | — | 若干 | 低 | |

**机械结构**：一块开有 8 个槽的挡板，每槽两侧相对安装发射管与接收管，
手指从槽中穿过即完成一次"拨弦"。槽距决定音程跨度（8 槽覆盖一个八度）。

### 3.5 维度扩展（补齐"≥3 维表情"）

基础要求只需 2 维，但拓展要求"≥3 维演奏表情（力度/滑音/颤音）"。当前系统只有力度。
建议增加：

| 维度 | 器件 | 接法 | 用途 |
|---|---|---|---|
| **滑音/弯音** | 线性霍尔 + 磁铁 | 板载 ADC（见 §五） | 左手连续改变音高 |
| **颤音** | 同上或独立电位器 | ADC | 周期性音高摆动（复用闲置的 LFO 字段） |

> 说明：这两项在**主系统侧已有预留**——`chan_table` 已经算出 `bend_ratio`，
> 声部表也有空置的 LFO 字段；**缺的只是"接到声部层"这一段连线**。

### 3.6 RTL 结构与延迟预算

**模块划分**：
```
peripheral_top            外设顶层
├── ts_counter            自由运行时间戳（32 位）
├── photo_gate_array      8 路采集 + 去抖 + 边沿检测 + 时长测量
├── event_encode          事件打包（→ MIDI 等价消息）
├── disp/                 显示子系统（见 §四）
└── song_player           脱机曲目（见 §五）
```

**延迟预算**：

| 环节 | 预算 | 说明 |
|---|---|---|
| 传感器电平采样 | ≤ 3 拍（≈ 60 ns） | 每拍同步采样 8 路 |
| 去抖窗口 | ≤ 200 µs | 消除机械/光抖动，可配 |
| 时长→力度换算 | ≤ 2 拍 | 组合计算 |
| 事件打包 + 跨时钟域 | ≤ 4 拍 | 异步 FIFO |
| 主系统（事件→出声） | ≈ 1.3 ms | 已实现链路 |
| **合计** | **≈ 1.6 ms** | **远优于 ≤5 ms 目标，留 3 倍余量** |

## 四、可视化反馈设计（拓展 3）

### 4.1 载体选择

| 载体 | 频谱 | 波形 | 演奏指引 | 李萨如 | 驱动难度 |
|---|---|---|---|---|---|
| 板载 LED ×3 | ✗ | ✗ | ✗ | ✗ | 极低 |
| **WS2812 灯带** | ✓ | ✓ | ✓ | ✗（需二维） | **低（单线协议）** |
| SPI OLED 128×64 | ✓ | ✓ | ✓ | ✓ | 中（需帧缓冲） |

**建议**：先做 **WS2812 灯带**（三项全能、驱动最简、布线最少）；
若周期允许，再追加 OLED 作为第二显示后端（**接口不变，只增后端**），以覆盖"李萨如图形"。

### 4.2 灯带分区布局（64 点）

```
[ 0 .. 31]  实时频谱条    32 段，对数频率轴
[32 .. 47]  波形/包络指示 16 段
[48 .. 63]  演奏指引      16 灯，对应曲目当前音符
```

### 4.3 频谱实现

| 方案 | 资源 | 输出 | 建议 |
|---|---|---|---|
| **64 点基-2 FFT** | 约 2~3 K LUT、少量 DSP | 32 个频点 | ✅ 推荐 |
| 8 通道 Goertzel | 每通道 1 乘法器 | 8 个频点 | 够用但粗糙 |
| 多相滤波器组 | 中 | 粗 | 不推荐 |

**关键设计约束**：**可视化必须与音频通路解耦**。
每 1024 采样（= 20.8 ms）计算一次，使用 **ping-pong 缓冲 + 独立时钟域**，
不得在音频数据通路上插入任何与显示相关的逻辑，否则会引入抖动、破坏"确定性延迟"指标。

## 五、脱机曲目指引（拓展 4）

### 5.1 曲目格式（合规要点）

```
曲目 = 事件序列 { tick, note, velocity, duration }
       tick 分辨率建议 1/96 拍（与 MIDI 惯例一致）
       存储：片上 BRAM（短曲目）或板载 Flash（长曲目）
```

**⚠️ 合规红线**：赛题明确"**严禁直接播放预录 PCM 音频、预置推流及整段录音触发**"。
本设计存储的是 **MIDI 事件**，回放时仍由 DDS 振荡器**实时合成**，**不触碰该红线**。

### 5.2 指引逻辑

```
节拍时钟（按 BPM 推进）→ 查当前时刻应演奏的音符
  → 点亮对应 LED（"该弹这里"）
  → 比对实际收到的 Note On
      匹配 → 亮绿；错过 → 亮红；提前 → 亮黄
```

**不需要任何新增硬件**——纯 RTL + 一份曲目数据。**这是性价比最高的拓展项。**

## 六、接口设计（外设 ↔ 主系统）

### 6.1 设计决策：复用 MIDI 消息语义

```
传感器 → photo_gate_array → event_encode → 仲裁 → sched_subsystem
                                             ↑
                                  串口 MIDI（端口 3）也接在这里
```

| 演奏动作 | 编码为 | 说明 |
|---|---|---|
| 拨某弦 | `90 <note> <vel>` | note 由槽位决定，vel 由遮挡时长决定 |
| 松弦 | `80 <note> 64` | |
| 滑音 | `E0 <lsb> <msb>` | 14 位，中心 8192 |
| 延音踏板 | `B0 40 <val>` | CC#64 |
| 调制/颤音 | `B0 01 <val>` | CC#1 |

**选择理由**：
1. **调度层零改动**——现有 `sched_subsystem` 已能接收 MIDI 字节流
2. **可观测、可复现**——事件可打印、可存文件、可用现有串口工具重放
3. **合规安全**——事件流不是音频

**注入点**：建议**不占用物理 `midi_rx` 引脚**，而在 `full_system` 内部
将传感器事件与端口 3 做优先级仲裁后送入调度层。这样**串口 MIDI 与传感器可同时工作**
（一个用于调试，一个用于演奏）。

### 6.2 引脚需求汇总

| 用途 | 数量 | 类型 | 备注 |
|---|---|---|---|
| 光电门 | 8 | 数字输入 | 8 弦 |
| 霍尔（滑音） | 1 | **模拟输入** | 走板载 ADC（见下） |
| WS2812 灯带 | 1 | 数字输出 | 单线协议 |
| OLED（可选） | 5 | 数字输出 | SPI：SCK/MOSI/CS/DC/RST |
| 蓝牙模块（可选） | 2 | 数字 | UART TX/RX |
| **合计** | **≤ 17** | | 板卡可用 IO 共 198 个 |

### 6.3 板载 ADC（重要发现）

Arora V 器件**内建 8 通道 10 位 ADC**，输入可映射到 **Bank 2/3/4/5/6/7 的 GPIO**。
因此接入霍尔、FSR、光敏等模拟传感器**无需外挂 ADC 芯片**，直接使用片上资源即可。

> 依据：`material/official_docs/UG299-...ADC User Guide`

## 七、既有系统核实结果（与本次任务相关项）

以下均**经实际检查代码/计算确认**，非推断：

| # | 事项 | 核实结果 | 影响 |
|---|---|---|---|
| 1 | 板载 ADC 可用性 | ✅ Arora V 内建 8 通道 10 位 ADC，走 Bank2~7 GPIO | 模拟传感器**无需外挂 ADC** |
| 2 | 引脚余量 | ✅ 官方 202 个 IO_LOC，当前仅用 6 个 | 引脚**非瓶颈** |
| 3 | `DEF_F_COEFF = 30000` 是否导致音色被固定低通滤平 | ❌ **不成立**。按 `fc = (fs/π)·asin(c)` 计算得 **fc ≈ 17.7 kHz**，基本透明 | 音色差异问题**另寻原因** |
| 4 | Pitch Bend（滑音）链路 | ❌ **确认断开**：`chan_table` 已输出 `rd_bend_ratio`，但 `voice_fetch` / `voice_mono` / `dds_voice` **均无 bend 端口** | 滑音维度需补这一段的连线 |
| 5 | 引用文件 `tb_timbre_e2e.v`、`soft_limiter_流水线版备查.v` | ❌ **仓库中不存在**（`team_scratch/agent/` 仅有 2 个 md 文件） | 若 saki 手上有该版本，需提供以核对 |

**附加分析**：`soft_limiter` 的关键路径为 `l_in × g_cur`（24×16 乘法）+ `sat24` 饱和，
**在同一时钟周期内组合完成**。该结构在 49.152 MHz（周期 20.345 ns）下存在时序风险，
与 saki 所述的 566 个违例、最差 slack −25.9 ns 在**量级上相符**。
修复方向（插入流水级）合理，但不影响外设任务，属评审前应处理项。
