## 一、核心问题：音色参数表根本不存在

### 现状

**所有声部参数都是常量**（`full_system.v` L47-55 的 `DEF_*`，L231-239 映射成 `def_*`，L251-266 接到 `voice_mono`）：

```
f_coeff      = DEF_F_COEFF      = 30000   （≈17.7 kHz，几乎等于不滤波）
q_coeff      = DEF_Q_COEFF      = 16384   （Q=0.5，无谐振）
filter_type  = DEF_FILTER_TYPE  = 0       （低通）
adsr_curve   = DEF_ADSR_CURVE   = 0       （线性）
attack_step  = DEF_ATTACK_STEP  = 5       （≈125 ms）
decay_step   = DEF_DECAY_STEP   = 20
sustain_level= DEF_SUSTAIN_LEVEL= 20000
release_step = DEF_RELEASE_STEP = 8
```

`rtl/scheduler/sched_subsystem.v` L26 的注释自己写着：

> *"它们来自音色参数表，**目前仓库里还没有这个模块**。"*

### 后果

**8 个音色只在「波形」上不同，ADSR 包络、滤波器、增益完全相同。**

- 所有音色的 attack 都是 125 ms 线性上升 → 钢琴/打击/铺底听起来一样"软"
- 所有音色的滤波器截止都是 ~17.7 kHz → 没有明暗变化
- `chan_table` 里算出来的 `attack` / `release` / `resonance` / `cutoff` 字段**全部没被使用**

### 目标状态

| 字段 | 位宽 | 说明 |
|---|---|---|
| `wave_main` | 8 | 波表索引（目前由 `timbre_slot` 决定，字段未用） |
| `adsr_attack` | 16 | Attack 步长 |
| `adsr_decay` | 16 | Decay 步长 |
| `adsr_sustain` | 16 | Sustain 电平（Q1.15） |
| `adsr_release` | 16 | Release 步长 |
| `adsr_curve` | 2 | 0=线性 1=指数 |
| `filter_type` | 2 | 0=LP 1=BP 2=HP |
| `filter_cutoff` | 16 | 基准截止（Q1.15，存 sin(πfc/fs)） |
| `filter_resonance` | 16 | 基准谐振（Q1.15） |
| `filter_env_depth` | 16 | 滤波器包络调制深度（未实现） |
| `vca_gain` | 16 | 音色总增益 |
| `vel_sensitivity` | 8 | 力度灵敏度（未实现） |

**这些字段的 Schema 在 `documents/技术文档.md` §四.3（L245-259）已经定好了，缺的是「每个槽的数值」和「读出来的通路」。**

## 二、编辑器体验问题：改一次音色要 35 分钟

**根本原因**：参数表若是**硬编码 ROM**（`$readmemh` 从 hex 加载），Gowin 会在**综合时把初值固化进 `.fs`**，所以改一个数值都要走完整流程：

```
改 hex → 综合（~5 分钟）→ 布局布线（~30 分钟）→ 烧录
```

**没有"只改存储器内容"的烧录方式。**

### 三条路（已评估）

| 方案 | 调一次音色耗时 | 工作量 | 评价 |
|---|---|---|---|
| **A. 硬编码 ROM** | **35 分钟** | 小 | ❌ 调参不可行 |
| **B. 接 CC71/72/73/74（实时 CC 调制）** | **0 秒** | 小 | ✅ **建议先做** |
| **C. 参数表做成可写 BSRAM + SysEx 编辑** | **0 秒** | 中 | ✅ 正规做法 |

### 方案 B：已经有现成的，只是没接

`chan_table` 已经解析并存了这四个 CC：

```
CC73 → attack_mod     （Attack 时间）
CC72 → release_mod    （Release 时间）
CC71 → resonance_mod  （滤波器谐振 Q）
CC74 → cutoff_mod     （滤波器截止频率）
```

**输出在 `sched_subsystem.v` L215-216**：

```verilog
.rd_attack_mod(ct_attack), .rd_release_mod(ct_release),
.rd_resonance_mod(ct_reson), .rd_cutoff_mod(ct_cutoff),
```

**但 `ct_attack` / `ct_release` / `ct_reson` / `ct_cutoff` 全部躺在 L404-407 的「未使用信号清单」里，声部层拿不到。**

**只要加一次接线，之后调音色就是秒级**：

```powershell
python midi\midi_serial.py -p COM7 cc 74 100    # 调截止频率
python midi\midi_serial.py -p COM7 cc 71 90     # 调谐振
python midi\midi_serial.py -p COM7 cc 73 2      # 调 attack
```

**注意**：这是「通道级实时调制」，语义上不等于「音色参数表」，但对现场调音色够用。

### 方案 C：真正可编辑的音色

- 参数表用**可写 BSRAM**（8 槽 × 13 字段 × 16 bit ≈ 1.7 Kbit，很小）
- 上电从内置默认值加载（不改也能用）
- 运行时通过 **SysEx** 写入 → 立即生效
- `midi_filter` 已有 SysEx 解析框架，可复用
- 顺带满足"音色可编辑"（演示时出彩）

## 三、音色定位未定义

**目前不知道 8 个槽「应该是什么音色」。** 文档只在一个 `.mi` 例子里提了一句「槽 0 钢琴 125 ms」。

**从波表文件分析出的实际波形**（`board/full_system/data/wave_table.hex`，8 槽 × 2048 点）：

| 槽 | 峰峰值 | 占满量程 | RMS/峰值 | 形状 | 首尾差 |
|---|---|---|---|---|---|
| 0 | 60000 | 91.6% | 0.707 | **正弦** | 92 |
| 1 | 65535 | **100.0%** | 0.674 | 非标准 | 184 |
| 2 | 56428 | 86.1% | 0.792 | 非标准（像削顶正弦） | 183 |
| 3 | 60250 | 91.9% | 0.733 | 非标准 | 193 |
| 4 | 60000 | 91.6% | 0.577 | **三角** | 59（连续） |
| 5 | 48000 | **73.2%** | 1.000 | **方波** | 48000（跳变，正常） |
| 6 | 59971 | 91.5% | 0.577 | **锯齿** | 59971（跳变，正常） |
| 7 | 56066 | 85.5% | 0.502 | 非标准 | 55 |

**建议的定位思路**（配合现有波形，不照抄真实乐器的参数 —— 合成波形配真实乐器包络会很怪）：

| 槽 | 波形 | 定位 | 参数特征 |
|---|---|---|---|
| 0 | 正弦 | 柔和铺底 / 风琴 | 慢起慢落、低通全开、低谐振、高 sustain |
| 1 | 正弦变体 | 钟琴 / 电钢 | 快起、中速衰减、中等 sustain |
| 2 | 正弦变体 | 人声 / Pad | 很慢起、高 sustain、柔和低通 |
| 3 | 正弦变体 | 铜管 | 中速起、带通 + 中谐振 |
| 4 | 三角 | 长笛 / 木管 | 中速起、低通、低谐振 |
| 5 | 方波 | 电子主音 | 快起、带通/高通、中高谐振 |
| 6 | 锯齿 | 弦乐 / 贝斯 | 中速起、低通 + **高谐振**（经典锯齿扫频） |
| 7 | ? | 打击 / 拨弦 | 极快起、极快衰减、sustain = 0 |

**关键原则**：这类合成器靠**包络 + 滤波器**把同一个波形做出不同性格，而不是靠波形本身。

## 四、波表本身的问题（要报给 majiao）

**① 振幅不一致** —— 最响槽 1（100%，±32768）vs 最轻槽 5（73.2%，±24000），**差 2.7 dB**，**切换音色会有明显音量跳变**。建议各槽归一化到统一峰值（如 ±30000）。

**② 槽 1 用了满量程 ±32768** —— `-32768` 是 16 位有符号边界值，**取反会溢出**，后续任何增益都会削顶。建议留 5~10% 余量。

**③ 槽 1/2/3/7 的 RMS/峰值是 0.674 / 0.792 / 0.733 / 0.502** —— 都不是标准波形值（正弦 0.707、三角/锯齿 0.577、方波 1.0）。**如果这是刻意设计的"谐波含量不同的音色"，那正常；如果不是，可能是生成脚本参数有误。** 需要他确认设计意图。

**✅ 健康的部分**：8 槽 × 2048 点结构正确；**所有槽均值 ≈ 0，无直流偏置**；除方波/锯齿本身该有的跳变外无不连续。

> ⚠ **更正过一个错判**：曾误报"槽 5 是恒定 24000 的直流"，那是按 1024 点/槽分组导致的误判，**实际是 2048 点/槽，槽 5 是振幅 24000 的方波，正常**。

## 五、其它未接的字段

| 字段 | 现状 | 说明 |
|---|---|---|
| **`vca_gain`** | **写死 32768（1.0）**，不读音色表 | `voice_fetch` 的 `apply_alloc` 直接写 `V_VCAGAIN = 16'd32768`。原因：`adsr_vca` 里是 `g_vt = velocity_gain × vca_gain`，两者同源会变成**力度平方**（`vel=1` 完全无声）。若要启用音色表的 `vca_gain`，必须先重新划分它与 `velocity_gain` 的职责。 |
| **`vel_sensitivity`** | **未实现** | 力度灵敏度曲线（目前力度是线性 `vel << 7`）。 |
| **`filter_env_depth`** | **未实现** | 滤波器包络调制（当前滤波器截止是常量，不随音高/包络变化）。**这是音色单薄的重要原因之一** —— 真实乐器的音色明暗随时间和强度变化。 |
| **`filter_lfo_depth`** | **未实现**（LFO 暂缓） | 滤波器 LFO 调制。 |

## 六、建议的优先级

```
1. 接 CC71/72/73/74（方案 B）        ← 一次综合，之后调音色零等待；工作量最小
2. 定义 8 个音色的定位（第三节）      ← 决定参数怎么给
3. 实现音色参数表 timbre_param.v      ← 8 槽 × 13 字段，值按第 2 步的设计
4. 音色参数表改为可写 BSRAM + SysEx（方案 C）← 真正可编辑
5. filter_env_depth（滤波器包络调制）  ← 音色表现力，工作量中等
6. vel_sensitivity（力度曲线）
7. 波表问题修好（等 majiao）
```

**第 1 步的价值/工作量比最高**：只需要一次综合，之后所有音色调整都是实时的。
