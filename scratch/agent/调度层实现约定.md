## 2. 4 路 MIDI 解析器：FSM（建议）

**例化 4 份**（乐器 ×3 + 混音器 ×1），互不共用。位定时 `midi_tick ÷1573 = 31250 Hz`（误差 0.0086%）。

### 2.1 状态

| 状态 | 含义 | 出口条件 |
|---|---|---|
| `ST_IDLE` | 等状态字节 | 收满 1 字节 → 按字节分类 |
| `ST_D1` | 等第 1 个数据字节 | 收满 → 视消息长度转 `ST_D2` 或发射 |
| `ST_D2` | 等第 2 个数据字节 | 收满 → 发射 |
| `ST_SYSEX` | 收 SysEx 数据 | 收到 `F7` → 发射；超时 / 超长 → 转 `ST_SYSEX_SKIP` |
| `ST_SYSEX_SKIP` | 丢弃剩余的 SysEx | 收到 `F7` → 回 `ST_IDLE`；同时清运行状态 |

### 2.2 字节分类（每个收满的字节都先过这一层）

| 字节范围 | 处理 | 运行状态 |
|---|---|---|
| `0x80`–`0xEF` | 记为当前状态字节；按长度进 `ST_D1` / `ST_D2`（`0xCn`/`0xDn` 只 1 个数据字节） | **替换** |
| `0xF0` | 进 `ST_SYSEX`，清长度计数 | **清除** |
| `0xF1`/`0xF2`/`0xF3` | 按 System Common 收 1~2 字节后发射 | **清除** |
| `0xF4`/`0xF5`/`0xF6`/`0xF7` | 直接丢弃（`F7` 在 `ST_SYSEX` 内是终止符） | **清除** |
| `0xF8`–`0xFE` | **就地旁路**：不参与解析、不计入数据字节数、不改变运行状态、不打断当前消息 | **不影响** |

> `0xF8`–`0xFE` 可插在数据字节**之间**（例如 `0x90 0xF8 60 0xF8 100`），所以判断必须放在**每个字节入口**，而不是只在消息边界。

### 2.3 边界情况（照 `MIDI协议.md` 原文）

- 数据字节**多于**期望：多出来的那个按"下一条运行状态消息的第一个数据字节"处理。
- 数据字节**不足**：等下一个状态字节；未完成的消息被**重置**。
- 未定义状态字节（`0xF4`/`0xF5`/`0xF9`/`0xFD`）：**忽略**。

### 2.4 输入极性

**建议**：`midi_parse` 加一个 `parameter INV_INPUT`（或 1 bit 寄存器 `cfg_invert`），对 `rx` 取反。理由：6N138 光耦输出通常反相，文档把极性列为"暂缓（硬件侧）"，放一个可配置位就能先写完 RTL，上板一位切换。

## 3. SysEx 保护参数（建议值）

**问题**：`F7` 不来会卡死解析器；文档只说"需超时计数或长度上限"，没给数值。

**建议**（两个都做，互为兜底）：

| 保护 | 建议值 | 依据 |
|---|---|---|
| 长度上限 | **64 字节** | 本项目最长 SysEx = 效果参数 7 字节、主音量 8 字节，留 8 倍余量 |
| 字节间超时 | **10 ms**（31250 baud 下 = 312 个 `midi_tick`，9 位计数器） | 正常 SysEx 字节间隔 ≤ 1 字节时间（320 µs），10 ms 足够宽松、又不会真卡死 |

超限 / 超时后：**丢弃整条 SysEx**、回 `ST_IDLE`、清运行状态。建议同时拉一个 `sysex_error` 脉冲（便于 testbench 断言，也可选接到 LED）。

**建议**：`midi_parse` 只在 SysEx 通过校验后才把整条消息交给下游（即先缓存到 64 字节的小 RAM/寄存器组），避免"解析一半才发现超长"时下游已经看到半条消息。

| 100 / 101 + 6 | RPN 地址与数据 | — | 乐器（**只用 RPN 0,0**） |

### 4.2 过滤规则

- **乐器端口**：CC **7 / 10 / 91 / 93 / 94** → **丢弃**（混音调节只认混音器端口）。
- **混音器端口**：混音类 CC 正常写入；演奏类 CC 也照写（文档未禁止）。
- 其余 CC：按 `MIDI协议.md` 的"本项目"列，未列出的**忽略**（不写表、不报错）。

### 4.3 三个极易写反的字节顺序（务必逐处注明）

| 场景 | 顺序 |
|---|---|
| 14 位 CC 配对（CC0–31 为 MSB，CC32–63 为 LSB） | **先 MSB 后 LSB** |
| Pitch Bend | `En ll mm` —— **先 LSB 后 MSB** |
| RPN / NRPN 数据 | **先 MSB 后 LSB**（先 CC6，再 CC38） |

### 4.4 Bank Select 的"待用值"语义

- 顺序固定 `CC0 → CC32 → Program Change`，**中间不能插入其他消息**（尤其别的 PC）。
- 单独发 **不生效**：挂在待用值里，等下一个 PC 一起生效。
- **不改变正在发声的音符**（新音起效）。
- 实现建议：待用值缓存在**通道表编辑器内部**的 `pend_bank_msb/lsb`（7+7 位 × 16 通道），收到 PC 时把 `(pend_bank, program)` 一起交给 `timbre_map`。

### 4.5 CC120–127（**需要拍板**）

文档写"尚未确定"。**建议**：

| CC | 名称 | 建议 |
|---|---|---|
| 120 | All Sound Off | **实现**：该通道所有声部立即静音（不走 RELEASE） |
| 121 | Reset All Controllers | **实现**：复位控制器，但**不复位**文档列出的 7 项（PC、Bank Select、Volume、Pan、Portamento Time、Reverb Send、Chorus Send） |
| 122 | Local Control | 忽略 |
| 123 | All Notes Off | **实现**：该通道所有声部置 `gate=0`（走正常 RELEASE，与 120 区分） |
| 124–127 | Omni/Mono/Poly | 忽略 |

理由：120/121/123 是 GM1 必需控制器，且实现代价小；其余对本项目无意义。

## 5. 通道状态表：双缓冲 + 待写缓冲（实现约定）

照 `硬件实现.md` §三.1.2 / §三.2 与 §8.5.2：

| 项 | 约定 |
|---|---|
| 表本体 | **双缓冲**（两份参数寄存器区），16 项 × 约 200 bit = 3.2 Kbit |
| 读侧 | **寄存器实现 + P 个并行读口**（取数器每时隙一次读走该时隙所需全部通道参数，存入 P 组寄存器）。**不用单口 BSRAM**——一个时隙内要并发读 P 个声部的通道参数，单口会停拍 |
| 写侧 | 事件类写入先进**待写缓冲**：FIFO 深 **4**，条目 = `{ch[3:0], field[4:0], value[15:0]}` |
| 提交相位 | **`frame_stb`（采样帧边界）**——全系统唯一提交时刻，1 bit bank 选择位在提交时翻转 |
| 一致性 | 读方整帧只读当前 bank ⇒ 永远不会"半新半旧"；**双缓冲已足够，不需要三缓冲** |
| 复位 | 运行参数归零或默认；配置项（`max_voices`、`default_timbre`）载入默认值 |

**派生字段**（由编辑器算好再提交，供通道层直接取用）：

| 字段 | 算法 | 备注 |
|---|---|---|
| `pan_gL` / `pan_gR` | 等功率律 `cos/sin`，中心 0.7071（−3 dB） | 建议 128 项 × 2 × 16 bit 表（≈4 Kbit） |
| `bend_ratio` | `bend_value`(14 位，中心 8192) 取**高 7 位查表 + 低 7 位线性插值** | 128 项指数表（2 Kbit），精度 ±1 LSB |
| `note_count` | 分配器维护 | 分配 +1、释放 −1 |

## 6. 声部分配 / 释放器（建议算法）

### 6.1 分配优先级

1. **同通道、同 `note` 且仍活跃** → **重新触发该声部**（复用，力度按新 Note On 重采包络）；
2. 否则找**空闲声部**（`gate=0` 且处于 IDLE）→ 优先级编码器，`N=32` 一拍完成，取最低编号；
3. 否则**抢断**：在该通道内选 `age` **最大**（最老）的声部；若该通道未达 `max_voices`，也可先看全局最老声部；
4. 抢断时**必须走约 1 ms 快速释放斜坡**（直接切断会有 click）——复用 `RELEASE` 状态 + 临时改 `release_step`，**不新增状态**。

### 6.2 字段写入（Note On 时）

一次性写：`note`(7) / `velocity`(7) / `channel`(4) / `timbre_slot`(3，查映射表得) / `gate`(1) / `velocity_gain`(16，由力度 + 音色表 `vel_sensitivity` 派生) / `age`(16，分配时记时间戳)。

**注意**：分配器**不直接改写**计算路径正在使用的字段，而是通过「已分配 / 已释放」标记通知时序器；声部编号 → `(组, 泳道)` 的映射**固定不变**。

### 6.3 Note Off

**只写 `gate = 0`**。踏板保持与否由 ADSR 自己读通道表的 `sustain_pedal` 判定（声部表里**没有** `pending_release`、也没有 `sustain_pedal`）。

### 6.4 与周期类的交互

建议用**小 FIFO** 传递「已分配 / 已释放」事件（深度 4，条目 = `{voice_id[4:0], op[0]}`），时序器在帧边界消费。

## 7. 周期类时序契约（**接口冻结，照抄 `硬件实现.md` §8.5**）

参数：`P = 8`、`G = 4`、`N = 32`、`NCH = 16`、`N_cyc = 1024`、`f_s = 48 kHz`。

### 7.1 声部时序器 → 通道处理层

| 信号 | 位宽 | 方向 | 定义 |
|---|---|---|---|
| `slot` | 2 | 输出 | 当前时隙号 `0 ~ G-1` |
| `slot_vld` | 1 | 输出 | **单拍脉冲**，时隙开始时拉高 1 拍 |
| `frame_stb` | 1 | 输入 | 采样帧起始（来自 `pt8211_tx.sample_stb`），复位内部拍计数 |

**四条硬性契约**（违反则通道层行为未定义）：

1. 每采样周期**恰好发 `G` 个** `slot_vld`，**位置固定**；
2. 每个脉冲**恰好 1 拍宽**；
3. `slot` 在 `slot_vld` 那一拍有效，取 `0,1,…,G-1` **顺序递增**；
4. 第一个脉冲距 `frame_stb` **至少 1 拍**（不能同拍）。

> 参考实现：`rtl/voice_slot_seq.v`，默认 `STRIDE = 8` 拍间距、占 32 拍。

### 7.2 声部取数器 → 单声部层（全部 × P 并行）

`vld`(1×P)、`phase_inc`(32×P，已含 `bend_ratio`)、`wave_sel`(2×P)、`timbre_slot`(**3×P**)、`f_coeff`/`q_coeff`(16×P)、`attack_step`/`decay_step`/`sustain_level`/`release_step`(16×P)、`gate`/`sustain_pedal`(1×P)、`velocity_gain`/`vca_gain`(16×P)。

**时序**：必须在**时隙开始前**稳定并被单声部层寄存；单声部层在时隙边界采样，**不需要握手**。做法 = 取数器**预取下一时隙**（读延迟藏在上一时隙的计算时间里）。

### 7.3 单声部层 → 通道处理层

`aud_in`(**24×P**，Q1.23 单声道，与 `slot` 同拍有效)、`ch_in`(**4×P**，**0~15** = `midi_channel − 1`)、`vld`(1×P)。

### 7.4 状态写回（单声部层 → 取数器）

`phase_acc`(32，**不清零**)、`env_value`(16，Q1.15 满量程 **32767**)、`env_state`(3)、`filter_ic1`/`filter_ic2`(32×2)。

**采样边界统一写回**（不是算完立即写）；写回缓冲 `N=32` × 约 100 bit ≈ 3.2 Kbit（寄存器实现）。⚠ **缓冲位宽要预留 `lfo_phase`**（LFO 暂缓，但恢复时不改结构）。
