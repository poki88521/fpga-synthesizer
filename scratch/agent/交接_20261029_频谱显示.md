## 2. 三轮失败的根因（不要再重复）

| 版本 | 做法 | 结果 | 根因 |
|---|---|---|---|
| v1 | 32 个并行 Goertzel，`reg [31:0] y1[0:31]` + 变量索引读写 | **588 个 Setup 违例**，最差 −7.16 ns，音频 Fmax 49→36.4 MHz | 变量索引的寄存器数组 = 32 选 1 读 + 32 选 1 写译码，单拍 27.5 ns |
| v2 | y1/y2/bars 改三块 RAM，读写分相位 | 编译通过但**功能错**：1 kHz 输入时 32 个频带全亮 | 实现细节 bug（相位/地址/系数错配），且状态机复杂难调 |
| v3 | **单点扫描**：只有一份 Goertzel 状态，每 256 采样算一个频带，32 轮换 | 频率选择性仍错：1 kHz 输入时 band 0~5 饱和 100、band16 只有 75 | ① 一开始 `ph` 每拍翻转 ⇒ 每 2 拍更新一次（已修）② 修后低频端仍饱和 → 疑 **2cos(ω)→2 时定点量化的稳定性/缩放/归一化**问题 |

**结论：这个算法必须先有浮点参考实现再写 RTL**，否则只能盲试。

## 3. 推荐的正确流程（下一轮照这个做）

```
第 1 步（纯 PC，不碰 RTL）：Python 浮点参考实现
  · 32 个对数频带 f_i = 60 × (16000/60)^(i/31)，i=0..31
  · Goertzel：y[n] = x[n] + 2cos(ω)y[n-1] − y[n-2]，窗口 N=256/512/1024 都试
  · 幅度 = sqrt(y1² + y2² − 2cos·y1·y2)  ← **不是 |y1|**（这可能是 v3 出错的直接原因）
  · dB = 20log10(mag/N)，再映射到 0..100 px
  · 用几组合成信号验证：1 kHz 单音 / 261 Hz(C4) / 白噪 / 扫频
  · 输出「每个频带在给定输入下的期望柱高」→ 作为 RTL 的黄金参考
第 2 步：把浮点算法按定点重写并**在 Python 里做定点仿真**（Q14 系数、32 位状态），
         确认定点版与浮点版柱高误差 < 5 px
第 3 步：定点数学完全确定后，才写 RTL（此时几乎没有算法不确定性，只剩接线）
第 4 步：写 tb_spec_band（已有：simulation/tb/tb_spec_band.v，喂 1 kHz 正弦）
         判据：band 14~18 最高、且 band 0~5 不应饱和
第 5 步：集成（见第 4 节）→ 全系统编译 → 交用户综合
```

## 5. 硬件与时序约束（务必遵守）

```
· 音频域 49.152 MHz：**禁止**用变量索引的寄存器数组（32 选 1 就会 27 ns）
  → 需要数组就放 BSRAM（地址直接进端口），或者改成"单状态扫描"
· 时钟资源墙：PRIMARY 8/8、LW 8/8 已满
  → **不要新增时钟域**；计算放 clk_sys，渲染复用现有 vis（像素域）
· 当前余量：音频域约 +0.04 ns（极薄）→ 任何新增逻辑都要先想"会不会加深组合路径"
· 像素域 35 MHz（28.6 ns 周期）→ 32 选 1 的 8 位 mux 可以放这里
```
