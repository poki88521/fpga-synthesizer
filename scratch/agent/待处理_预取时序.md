# 待处理：预取路径的两级乘法（时序最差路径）

> 2026-10-20 晚
> 这是目前唯一已知的时序瓶颈，也是**唯一还没修过的**最差路径。
> 状态：**只出方案，尚未动手**。

---

## 一、问题

**连续三轮 P&R，最差路径都是同一条：**

| 轮次 | 最差 slack | From | To |
|---|---|---|---|
| 10-19（place_option 3，0 违例那轮） | +0.022 | `u_sched/u_sq/slot_1_s0` | `u_sched/u_vf/pf_phase_inc_171_s0` |
| 10-20（place_option 1） | −6.767 | `u_sched/u_sq/slot_1_s0` | `u_sched/u_vf/pf_phase_inc_230_s0` |

**起点是 `slot` 计数器，终点是 `pf_phase_inc`（相位增量寄存器）。**

## 二、原因：一拍里串了**两次乘法**

`voice_fetch.v` 里（大约 L407-419）：

```verilog
end else if (slot_vld) begin
    pf_phase_inc[gl*32 +: 32] <= apply_ratio(it[V_PHINC:V_PHINC_L],
                                             vib_bend_ratio(pf_ch, ...));
```

**两层嵌套：**

```
① vib_bend_ratio(bend, vib)   = (bend_ratio × vib_ratio) >>> 14    ← 16×16 乘法
② apply_ratio(base, ratio)    = (base × ratio) >>> 16              ← 32×16 乘法
```

**再加上 `slot` → `vtab[vid]` 的内存读取，全部压在一拍里。**

**16 个泳道副本各来一遍，这是整片设计里最深的组合链之一。**

## 三、修法：拆成两拍

### 3.1 结构

```
第 1 拍（slot_vld 当拍）：
    ratio_r[gl] <= vib_bend_ratio(bend_ratio, vib_ratio)     // 只做 ①

第 2 拍（slot_vld 之后一拍）：
    pf_phase_inc[gl] <= apply_ratio(base_r[gl], ratio_r[gl])  // 只做 ②
```

### 3.2 为什么安全

```
· 时隙周期 STRIDE = 32 拍，第 2 拍就出结果 → **余量 30 拍**
· pf_* 原先是"在 slot_vld 那一拍更新"，现在晚一拍
· voice_mono 在**下一个 slot_vld** 才采样 pf_*，所以仍然拿到稳定值
  → "预取提前一个时隙"这个语义**不变**
```

### 3.3 需要一起搬的信号

**第 1 拍要把第 2 拍要用到的东西一起锁存：**

```
ratio_r[gl]     32 位   ← ① 的结果
base_r[gl]      32 位   ← it[V_PHINC]（表里的基准相位增量）
```

**其余 `pf_*`（`pf_gate`/`pf_ch`/`pf_timbre`/`pf_vel_gain`/…）本来就不在关键路径上，**
**但为了保持"同一时隙的数据同拍有效"，建议**一起延迟一拍**，避免出现
"相位增量是新的、门控是旧的"这种半新半旧状态。**

### 3.4 实现要点

**需要一个 `slot_vld_d`（延迟一拍）来驱动第 2 拍：**

```verilog
reg slot_vld_d;
always @(posedge clk or negedge rst_n_sync)
    if (!rst_n_sync) slot_vld_d <= 1'b0;
    else             slot_vld_d <= slot_vld;

always @(posedge clk or negedge rst_n_sync) begin
    if (!rst_n_sync) begin
        ...全部清零...
    end else if (slot_vld) begin
        // 第 1 拍：只算 ratio + 锁存其余
        ratio_r[gl*32 +: 32] <= vib_bend_ratio(pf_ch[gl*4+:4], bend_flat, vib_flat);
        base_r [gl*32 +: 32] <= it[V_PHINC:V_PHINC_L];
        pf_gate   [gl]       <= it[V_GATE];
        pf_ch     [gl*4 +: 4]<= it[V_CH];
        ... 其余 pf_* 原样 ...
    end else if (slot_vld_d) begin
        // 第 2 拍：只做一次乘法
        pf_phase_inc[gl*32 +: 32] <= apply_ratio(base_r[gl*32 +: 32], ratio_r[gl*32 +: 32]);
    end
end
```

**⚠ 注意：`pf_gate` 等改为在 `slot_vld` 拍更新、`pf_phase_inc` 在 `slot_vld_d` 拍更新
→ 两者**差一拍**。如果真的介意，可以把所有 `pf_*` 都挪到第 2 拍统一更新，
但那样 `pf_gate` 的生效时间也晚一拍（下游 `voice_mono` 仍在下一个 `slot_vld` 采样，
所以仍然安全）。**

**建议：全部挪到第 2 拍统一更新，保持"同一时隙的数据同拍"。**

## 五、为什么这个必须做

**现在的两难：**

```
place_option 3（时序优先）→ 0 违例，但 LW 100% 撞墙，**出不了位流**
place_option 1（可布通优先）→ 能出位流，但 **−6.767 ns / 540 违例**
```

**实板验证（2026-10-20）：**

```
✓ 测试模式（不经过声部层）**干净**
✗ 正常模式**炸**，且 **C6 以下坏、C6 以上正常**
✓ 音色/包络/note-off/panic 都正常
```

**"仿真对、实板错" + "测试模式正常" → 违例集中在**声部层/预取**这一侧。**

**而最差路径的终点 `pf_phase_inc` 正是**决定音高的那个值** ——
低音的相位增量小，高位出错时相对误差最大，**能解释"低音坏、高音好"**。
