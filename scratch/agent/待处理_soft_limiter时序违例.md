```
3.1.1 Setup Paths Table（最差路径，共 566 个端点由它派生）
  slack -25.907   时钟周期 20.345 ns   Data Delay 46.208 ns
  From: u_full_top/u_master/u_vol/g_5_s0/Q          （master_volume 侧寄存器）
  To:   u_full_top/u_master/g_lim.u_lim/g_1_s0/D    （soft_limiter 侧寄存器）
```

**要点**：

- `clk_sys` 被 STA 正确识别为 **20.345 ns（49.152 MHz）** —— **时钟约束没问题**，不是 SDC 写错。
- 问题是一条**纯组合路径要 46.2 ns**，超出一个周期 25.9 ns。
- 保持时间（hold）**零违例**。
- **调度层、单声部层、波表、通道层都没有进最差 25 条** —— 只有这一个模块有问题。

## 二、根因

`soft_limiter.v` 把 **15 步组合逻辑**塞进了同一个时钟周期（`l_in` 到输出寄存器之间）：

```
abs24 → env=max(al,ar) → msb_pos(env)          ← 24 级优先编码器
      → nrem = env - (1<<nk)                    ← 桶形移位
      → nmant = nrem >> (nk-7)                  ← 桶形移位
      → mant
      → recip_lut(li) + recip_lut(li+1)         ← 两次 LUT 查表（32 项）
      → lprod = ldiff × mant[1:0]               ← 乘法
      → rsum → recip_mant
      → gprod = recip_mant × THRESH             ← 16×24 乘法
      → recip_raw = gprod >> nk                 ← 48 位桶形移位
      → recip_final
      → g_diff → g_rel → g_nxt → g_cur
      → lp = l_in × g_cur                       ← 24×16 乘法
      → sat24(lp >>> 15) → 输出寄存器
```

统计：**3 个乘法 + 4 个移位器 + 1 个 24 级优先编码器 + 2 次查表 + 多级比较**。

`soft_limiter.v` 的 L58-71 注释显示作者**已经意识到**组合除法会超时（原实现是 `div_num / env`），
并已改成 32 段线性插值查表。但**整条链仍在单周期内**，组合深度依然过大。

## 三、为什么不能简单插流水线

`soft_limiter.v` L154-156 写明了设计意图：

```verilog
//  ⚠⚠ 用**组合**的本拍增益 `g_cur` 去算本拍输出，而不是用它打一拍后的寄存器 `g`：
//     否则过载出现的那一拍用旧增益（1.0），输出会**瞬间超过阈值**（实测 6312337 > 6291456）。
//     这就是"Attack ≈ 0"的落法：G_target 当拍就生效，输出永不过冲。
```

**作者刻意让增益当拍生效来防过冲**，因此整条链被有意设计成单周期。
插流水必然让增益晚 1~2 拍，过冲会回来 —— 这是必须权衡的点，不能无脑加寄存器。

## 四、三条候选方案

### A. 折中流水（推荐，改动小）

把 `msb_pos → mant → recip_lut → gprod` 这段**打 1~2 拍**。这段只依赖输入 `env`，
与 `g` **无关**，所以可以安全流水；让 `g_cur` 使用**上一拍算出的 `recip`**。

- **代价**：过载头 1~2 个采样用过时增益 → 瞬时过冲
- **兜底**：已有的 `sat24()` 会把它削到满量程（**不是溢出**），听感是一个极短的削波
- **收益**：组合链砍掉一大半，大概率能收敛

### B. 彻底重构：逐位恢复（bit-serial）算倒数

摊到 8~16 拍完成。一个采样有 **1024 拍预算**，绰绰有余，组合延迟极低。
改动大，但一劳永逸，且不牺牲精度。

### C. 先旁路，验证其它部分（**建议先做这个**）

把软限幅器**旁路**（`g_cur` 恒 1.0，或直接接 `sat24`），先确认
调度层 / 单声部层 / 波表 / 效果器 / I2S 在真板上都正常，再单独攻这个模块。

风险最低，不会因为一个模块卡住整条链路的验证。

## 8.1 改法

把原单周期组合链拆成 3 级流水：

| 级 | 内容 |
|---|---|
| 0 | `abs24 → max → env`（组合，输入侧） |
| 1 | `env → msb_pos(24级优先编码器) → nrem/nmant 桶形移位 → mant` |
| 2 | `mant/nk → recip_lut ×2 + 线性插值 + ×THRESH + 2^(−k) 缩放 → recip_final` |
| 3 | `recip_final → g_tgt → g_diff/g_rel/g_nxt/g_cur`，施加增益 + `sat24` 输出 |

## 8.2 两个关键设计点（改的时候务必保留）

**① 音频必须跟着打同样的拍数。**
`l_in/r_in` 与包络/倒数链**同步**延迟 3 拍（`l_d1/d2/d3`、`r_d1/d2/d3`）。
这样 `g_cur` 与 `l_d3` 始终对应**同一个采样**，作者原本
「G_target 当拍生效、输出永不过冲」的语义（L154-156）**完全保留**。
如果只延迟增益而不延迟音频，就会变成"新音频配旧增益"，过冲会回来。

整体代价只是晚 3 个采样 = **62.5 µs @48 kHz**，听感无影响。

**② 所有流水寄存器必须用 `en` 使能。**
`en` 是采样节拍（约 1/1024 拍）。若写成每拍推进，流水会以**错误的速率**前进，
结果全错（而且波形看起来"像是动了"，很难查）。

## 8.3 算法一字未改

`recip_lut` 表（33 项）、`msb_pos`、`sat24`、「先乘后移」的顺序、
`g −= (g>>7)` 的 0.39% 余量 —— **全部照原样保留**，只调整了它们的时序位置。

## 8.5 TB 的一处适配（原因已写在 TB 内注释里）

`tb_limiter.v` 第 1 项原先在施加输入后**立刻**检查输出，而 `step()` 任务
每次只产生 1 个 `en` 脉冲（= 1 个采样），流水线需要 3 个采样才把数据推到输出。
故改为先把流水线灌满（连调 4 次 `step`）再检查。

**这不是放松判据** —— 第 4 项「300 拍后输出 1000000」依然在独立验证输出正确性。
**若将来把流水级数改回 0，这一项要跟着改回去。**
